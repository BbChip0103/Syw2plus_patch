## 4. 건물도 `used`에 들어가며, 건물 수는 고정 typemax로 막히지 않는다

- `used(+0x200C) = Σ cost[kind]`는 로스터 **전체**(건물 포함) 합이다(`supply_200c_accumulation_rule_0726.md`;
  초기 20 = HQ49 10 + 일꾼7 10). 조선 건물 cost 10~20(평균 13.57).
- `FUN_0043DB00`(후보별 가능성): override 0 · `ai==1`이면 **`+0x200E(건물 수) >= +0x2010/5`에서 전 건물 거부**,
  그 외는 선행 건물(`+0x2FB8`)·선행 연구(`+0x315C`)만 본다. **typemax 비교 없음.**
- `FUN_0043DBB0` 종별 한도(`0x43DF3E`~`0x43DF8E`): 로스터에서 `+0x1D8&2` 개체와 `+0x290==0xC` 개체
  (`+0x324` 종으로 계수)를 세어 N을 만들고 **한도 = typemax×N/6 (+typemax, N%12≠0이면)** — N과 함께 자란다
  (typemax 1: N=1→1, 6→2, 12→2, 13→3, 60→10). `+0x1D8&2`=건물, `+0x290==0xC`=건설 중이라는 해석은 **추정**이다.
- 부수: `+0x4C` dword의 bit `0x2`는 AI 건설 가능 플래그(`0x43DF0E test byte [..+0x9B5274],2`)이며 생산 건물 27종 전부 1.
  이것은 N147의 `0x9B5274` 리터럴이 G-7 밀집이 아니라 **이 건설 경로에서도** 쓰인다는 뜻이다(H-CROWD 해독은 별도, UNKNOWN 유지).
  매 호출 LCG로 2/3 확률 41·56·68 후보를 끈다(`0x43DEB1`).

**산술:** W29 fixture(`+0x2010`=1,200 ⇒ 건물 상한 240)에서 조선 AI가 5,000에 닿으려면 건물 보급
≥ 5,000−2,835 = **2,165**, 평균 cost로 **≈160채**가 필요하다(느슨한 상한 240×20=4,800이라 산술상 불가 아님).
관측은 W29 종단 7~11채(생산 건물), lap513(stock `+0x2010`=250, 건물 상한 50) 종단 11~20채이며
**마지막 증가 tick 17,988~23,885 — 건설이 멈춘 것이 아니라 24k tick에 ~15채 속도로 느리다.**
