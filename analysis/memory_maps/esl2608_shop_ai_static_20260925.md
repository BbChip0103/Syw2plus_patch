# ESL 2608 상점개설/AI 읽기 전용 확인 (2026-09-25)

범위: `260921_temp/[ESL]Syw2plus 2608/` 배포 파일을 **실행하거나 수정하지 않고** 2606과 정적 비교. 2608의 실제 AI 연구·아이템 구매 실패는 아직 재현하지 않았다.

2608 EXE는 PE32 6섹션으로, 기존 4섹션에 `.psncode`/`.psndata`가 추가됐다. 2606과 공통 파일 범위의 변경 바이트는 1,245개, 파일 꼬리는 32,768B 늘었다. 배포 폴더의 파일 459개는 기존 `[ESL]Syw2plus/` 전체 게임 파일 7,113개의 대체품이 아니며, 상대 경로 기준 439개 동일·10개 변경·10개 신규다. 격리된 전체 복사본 없이는 실행 근거로 삼지 않는다.

## 상점개설 제보의 정적 근거

- 패치노트 `ESL 2608` 시트 13행은 **상점개설 연구 복원, 가격 3000/3000**을 명시한다. 이것은 배포 문서의 주장이지 실제 AI 동작 증거는 아니다.
- EXE의 AI 연구 디스패치/후보 선택 범위 `VA 0x406770–0x407000`, 후보표 `VA 0x4EC514`부터 144×18B(143행+종료행)는 2606과 **바이트 동일**하다. 후보표에는 연구 78행, 생산 65행이 있다. 디스패치·표 구조는 `ai_production_decision_path_00406770_20260923.md`의 원본 바이트 분석과 대조했다.
- 기존 시장 계열 후보 행은 `0x4EC54A: 건물48(조선 방앗간)→연구27`, `0x4EC730: 건물57(일본 시장)→연구27`, `0x4EC83E: 건물73(명 시장)→연구27` 세 개뿐이고 2608에서도 동일하다. 사용자가 제공한 `컴퓨터 연구,생산.xlsx`(SHA-256 `ca845854924e2b6ea479fd78886641020329c55a2fe2d403ea345e34d81071ea`, 시트 `컴퓨터 연구생산` 7/34/49행)는 이 세 행을 **자원가치향상 연구**로 표기한다. 원본 연구 메타데이터도 **연구27=자원 가치 향상, 연구20=당시 빈 슬롯**이라고 확인한다.
- 2608의 상점/아이템 소비자에서 기존 연구 완료 플래그 주소 `0x00959902`(연구27) 일부를 `0x009598F4`(연구20)로 바꿨다. 후자는 원본 완료표 base `0x009598CC + 20×2`이다. 변경 지점은 `0x4851B0`, `0x488B50`, `0x488FA0`, `0x4A8480`이며 각각 old/new 절대주소 바이트를 2606과 대조했다. 이것은 **2608의 상점개설 게이트가 연구20으로 분리됐다는 강한 정적 근거**다. 단, 2608의 연구20 런타임 메타데이터와 사람이 실제로 완료할 수 있는지는 별도 검증 대상이다.
- 2608이 기존 AI 후보표에 **새 행을 추가하지 않았고 연구20 행도 없다.** 신규 `.psncode`의 정적 훅 스캔에서도 위 연구 선택기·후보표를 직접 참조하는 새 경로는 발견하지 못했다. 따라서 **정상 AI 후보 선택 경로에서 연구20을 고를 수 없는 누락은 확인**했다. 다만 실제 AI 미구매 증상과 이 누락의 단독 인과관계는 `UNCONFIRMED`다. 실제 연구 가용·발주·완료·아이템 구매 게이트를 런타임에서 분리 관측해야 한다.

## 현재 프로젝트와의 경계

G5 선택 추가·회전·부대지정·명령 패킷 범위(`VA 0x412D00–0x412F20`, `0x41EC20–0x41EF00`, `0x445D00–0x445E30`, `0x4AE500–0x4AE680`)는 2606과 바이트 동일하다. 따라서 2608이 20→50 선택을 해결했다는 근거는 없다. 현재 원본 SHA 핀 패처를 2608에 그대로 적용하지 않는다. 새 섹션/주소·old bytes·비중첩·원복을 별도 검증해야 한다.

## 2608 전용 정적 수정 후보

`patches/ai/shop_open_research_2608.py`는 입력 EXE SHA `bf39cb73f395d677a1c27fda01698f849b23973a39fd9be8b22af0010cb60f27`와 기존 표 SHA `86e6fd94f604b0045005734ba3ef1c5b3343dc7914d5e3bf33e003f6140ae85c`를 고정한다. 기존 143행(연구27 세 행 포함)을 그대로 보존하고 건물 48/57/73에 `(타입15, 연구20)` 세 행을 추가한 표를 읽기 전용 `.shopai` 섹션에 둔다. 새 표 VA `0x0112D000`(raw `0x00104000`, 146×18B+`0xFFFE`), 기존 선택기 내 절대주소 피연산자 10곳의 raw offset `0x6C84, 0x6C96, 0x6D3B, 0x6D42, 0x6D50, 0x6DBA, 0x6DEA, 0x6E1A, 0x6E65, 0x6E79`를 새 표의 동일 필드로 재지정한다. PE `SizeOfInitializedData`도 새 섹션 raw 크기 `0x1000`만큼 갱신한다. 최종 후보 SHA는 `0f3334668f5ed37d130726725f421515f031be2856efdde04a9c19ea572627f5`이며, 출력은 공유 `temp/Syw2plus_patch/esl2608_shop/2608_shop_open.v2.candidate.exe`에만 생성했다. 이전 초안 `2608_shop_open.candidate.exe`(SHA `d7c8b213…`)는 PE initialized-data 합계 갱신 전 결과이므로 **사용 금지**다. 원본 EXE 해시는 생성 후에도 불변이다.

사용자 지정 2606 base SHA `716dde6a1cd837c74c83c426fba634491143d624c0c284aad4dc4d5d5ea2417f`와 장수7/전비 변형 SHA `4a03895d8e6690080714fab7e851c3a0e9d44b7cac47fed78fc21a2f5210c6f8`, 시작자리고정 포함 변형 SHA `daf0b6a07f01d04397018924f9dd0c6ff414148c0547adc2d5c9e0b403a58523`을 바이트 비교했다. 세 파일 크기는 1,032,192B이며 첫 변형은 7바이트/6연속 구간, 두 번째는 11바이트/8연속 구간만 base와 다르다.

2608 원본은 8곳 전부의 old bytes와 주변 ±256B가 2606 base와 동일하며, 상점개설 후보의 59개 기존바이트 변경·4096B 새 꼬리와 이 11개 바이트는 겹치지 않는다. 따라서 **정확한 2608 SHA/old bytes/주변 코드·비중첩 확인을 전제로 한 정적 이식만 가능**하다고 판단한다. 장수 상한 5→7, `1500+200×7=2900`이 아니라 파일명 표기의 `1600+200×7=3000`과 맞도록 immediate `0x05DC→0x0640` 변경을 보존한다. 이 표는 원본 파일을 수정하거나 실제 플레이·시작자리·AI 동작을 입증하지 않는다.
