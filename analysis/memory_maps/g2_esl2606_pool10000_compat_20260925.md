# ESL 2606 두 버전 × G2 10,000 사용 슬롯 결합 근거 (2026-09-25)

원본·참고 파일은 읽기 전용이다. 생성기는 `patches/population/g2_esl2606_pool10000_owner1200.py`.
이는 **실험 후보**이며 실게임 안정성·저장/LAN·G2 마일스톤 합격 근거가 아니다.

| 입력 | SHA-256 |
|---|---|
| 핀된 stock `Syw2plus/syw2plus_original.exe` | `b56986e018b43293be8d9945521d145bba8dbe4e49fe70c6b6488b8c9c08a8ac` |
| 2606 장수7/전비1600-200-3000 | `4a03895d8e6690080714fab7e851c3a0e9d44b7cac47fed78fc21a2f5210c6f8` |
| 위의 시작자리고정 | `daf0b6a07f01d04397018924f9dd0c6ff414148c0547adc2d5c9e0b403a58523` |

둘 다 stock과 길이 1,032,192B 동일. stock 대비 변경 바이트 3,498/3,502개;
두 참고본 사이 차이는 file offset `0x1F2B0`, `0x2FBB1..0x2FBB3`의 네 바이트뿐이다.
핀된 stock용 G2 N=10001/개인1200/저장 호환 후보와 겹치는 변경 바이트는 **정확히 10개**다.
그 외 충돌은 생성기가 거부한다. stock과 2606의 6개 풀/목록 참조 site를 같은 Capstone scanner로
대조하면 unit_pool 한 곳(`0x47BA0F`)이 2606에서 제거된 것 이외에는 site 집합이 동일했다.

충돌의 명시 처리:

1. 전비 계산 `VA 0x43FFD4`, stock `05 dc 05 00 00`(1500 더하기), 2606
   `05 40 06 00 00`(1600 더하기). 기존 G2 결합기에서 들어오는 `b8 88 13 00 00`
   (고정5000)은 **전부 버리고** 2606의 원래 5바이트로 복원한다. 초기 전비
   `VA 0x41B576`도 stock `66 c7 00 dc 05`로 복원한다. 장수당 +200과 장수7
   상한은 참고본 바이트 그대로다. F4 32-bit used 장부는 이 후보에 넣지 않는다.
2. `VA 0x47BA0F`, stock `f6 86 68 b9 66 00 02 75 0c`는 stock 패처가
   UnitStruct 절대주소를 재배치한다. 2606은 이 9바이트를 전부 NOP한다.
   후보는 2606의 NOP를 유지하여 더 이상 이 주소를 참조하지 않는다.
3. `VA 0x47E51A`, stock `c7 04 cd 90 b9 66 00 64 00 00 00`, 2606
   `3e c7 04 cd 90 b9 66 00 20 03 00 00`은 segment prefix 추가와 즉치값
   변경으로 UnitStruct 절대주소의 바이트 위치가 +1 이동한다. 후보는 2606
   명령 전체를 보존하고 `VA 0x47E51E`의 주소 `0x0066B990`만
   `0x0108C200`으로 바꾼다: N=10001 재배치 pool 시작 `0x0108C000` + 기존
   pool 내부 변위 `0x200`. 즉치 `0x320`은 보존한다.

용량 N=10001은 0번 예약을 제외해 사용 가능한 10,000칸이다. 개인 개체 수 1,200;
전비 규칙은 **1600+살아 있는 장수×200(최대7명=3000)**. 이 둘은 독립 수치이며
전비 5000/10000 설정을 하지 않았다. N=10001은 기존 N=4001 실제 검증을
자동 승계하지 않는다. 기존 풀/목록/저장 wrapper의 정적 계약은 재사용하지만,
2606 자체의 게임 실행/장시간/저장·로드/멀티 및 10,000칸 근접 부하는 미검증이다.
