- 대상: 보호 원본 `[ESL]Syw2plus/[HQ]Syw2plus 2002.exe`, SHA256
  `b56986e018b43293be8d9945521d145bba8dbe4e49fe70c6b6488b8c9c08a8ac`, image base `0x00400000`. 읽기만 했다.
- Method: `i686-w64-mingw32-objdump -d -Mintel` 전체 출력(공유 temp `20261004_lap914_strategy_review/exe_disasm.txt`)에서
  `0x104f814` 참조 16곳·`call 0x4663e0` 7곳·`0xe5d42c` 참조 6곳을 전수 grep, 해당 함수 구간 디스어셈블.
  `.data` 문자열은 파일에서 직접 읽었다. 런타임 대조는 lap912 census raw·trace·PNG(§5).
- 다른 버전 EXE(ESL 2606/2608 등)에는 적용하지 않는다. 주소는 이 SHA에서만 유효하다.

## 2. 패널을 잠그는 지점 (전수 6곳)

`0x464EC0(surface)`=Lock(렌더러 `0xE5BF18`의 버퍼 `+0x1514`·pitch `+0x10`·높이 `+0x08`을 그 표면으로 바꿈), `0x465080(surface)`=Unlock.
인자로 표면을 넘기므로 `[0x104F814]` 참조 16곳이 전부다(생성 1·해제 2·전사 1·아래 12).

| lock | 안에서 하는 일 | 쓰기 |
|---|---|---|
| `0x417DF6` | `0x4658C0`(픽셀 읽기) → `!= 0xFE` 판정(패널 hit-test) | 없음 |
| `0x41B75E` | `0x419B50` 뒤 `0x41B787 call 0x4663e0(x,y,[0xB92CE4],[0xB92CE8],[0xB938D4])`(x=y=`ebp`) | 바닥 그림 |
| `0x41C50D` | `0x41C524 call 0x451560(this=0x639350, word[0x892FE6])`, `0x41C52E call 0x451810` | 미니맵 지형·점 |

## 3. writer

### 3.1 `0x004663E0` — 키 채움 RLE (census 9 pin에 없던 프리미티브)

- thiscall(ecx=`0xE5BF18`), 5인자 `(x, y, w, h, src)`, `ret 0x14`. 첫 바이트 `51 53 8b 5c 24 10 | 0f af 59 10`
  (`push ecx; push ebx; mov ebx,[esp+0x10]` = 6바이트, 상대 피연산자 없음).
- 동작: `dst = buffer + y*pitch + x`. 행마다 `w` 칸을 채운다. src 바이트가 `0xFE`면 다음 바이트 n만큼 **목적지에 `0xFE`를 쓰고**
  n칸 전진, 아니면 그 바이트를 1칸 쓴다. 클립 없음, 목적지 읽기 없음. rect의 모든 칸을 쓴다.
- 호출 7곳: 패널 4(`0x41B787` `0x41C5A0` `0x424965` `0x441533`), 그 밖 3 — `0x45ED3C`(표면 `[0x104F824]`),
  `0x4925C3`(표면 `[0x104F81C]`), `0x492263`(`0x464E00`으로 잡은 64×48 대상). `jmp`·주소 push 참조 없음.
- 형제: `0x00466480`(5인자, `0xFE`만 건너뛰는 raw 복사)은 호출 1곳 `0x4C876E`뿐이고 패널과 무관하다(미조사).

### 3.2 `0x00451560` — 미니맵 지형 (프리미티브 밖 직접 쓰기)

- thiscall(ecx=`0x639350`), 1인자, `ret 4`. 점 수 `word[this+8]`, 점 i의 좌표는 `byte[this+i*4+0x4061]+[this]`(x),
  `byte[this+i*4+0x4062] + (word[this+4] − [0xE5BF20] + [0xB92CE8] + 1)`(y, 패널 좌표).
- 쓰기: `mov eax,ds:0xE5D42C`(= 렌더러 버퍼) → `mov [eax + y*[0xE5BF28] + x], dl`. 인자 1이면 LUT `0xEE8D10` 색, 아니면 0.
- 호출 1곳 `0x41C524`. 렌더러 프리미티브를 거치지 않으므로 writer hook으로는 보이지 않는다.

### 3.3 `0x00451730` — 미니맵 점

- `0x4658E0`(set_pixel) 4회. set_pixel의 `call` 참조는 이 함수 안 4곳이 전부다. 호출 1곳 `0x451871`(`0x451810` 안).

### 3.4 미조사 (목록만)

- `ds:0xE5D42C`를 절대 주소로 읽는 곳: `0x406077` `0x451637` `0x451676` `0x493374` `0x49339A` `0x4B5485`.
  `0x451637`·`0x451676`은 3.2다. 나머지 넷의 대상 표면은 보지 않았다.

## 4. 프레임당 흐름 (`0x41C490`, 호출 `0x41C294`)

1. gate `0x41C450()`이 0이면 5로.
2. `[0x975980]==0`이면 `0x4AC3E0(0x4A,0,0)` 뒤 갱신, 아니면 `|[0x8924B8] − [0x975984]| ≥ 30`일 때만 갱신. `[0x975980]=1`.
3. 갱신이거나 `word[0x892FE4]==1`이면 패널 lock → 3.2 → 3.3 → unlock.
4. (gate 재검사) 0이 아니면 반환.
5. gate가 0이고 `[0x975980]==1`이면 `0x4AC3E0(0x4B,0,0)`, `[0x975980]=0`, 패널 lock → 3.1로 바닥 그림 다시 → unlock.
- 그 뒤 `0x41C299 call 0x41c5c0`이 §1의 전사를 한다.

## 5. 런타임 대조 (lap912 census-only 원본 lane, save006)

- 전사 표본 19개 전부 `x=0, y=457, rect [0,0,800,143], flags 17, source 800×203, hresult 0`.
  143은 `fnt/pannelj.spr` header의 높이와 같다.
- `fnt/pannel{k,j,c}.spr`: header u32 `(9, 831, h, 1)`, h = 163 / 143 / 160, 데이터 offset 3060(=`0xBF4`).
  3.1의 알고리즘으로 831×h를 풀면 파일 끝과 정확히 맞는다(세 파일 모두).
- 폭 831은 패널 pitch 800보다 크다. 행 r의 800..830열은 다음 행의 0..30열 자리에 쓰였다가 다음 행이 덮는다.
  호출 뒤 버퍼의 행 0..h−1은 그림의 앞 800열과 같다(오프라인 143/143행). 마지막 행의 넘침은 행 h의 0..30열에 남는다(전사 rect 밖).
- census map 64장: 범주 10(`dd_surface_blt`) 4,449,556픽셀이 **전부** pannelj 불투명 칸 위다(무관한 그림이면 0.823). y<457에는 0.
- PNG 4장: pannelj 불투명 칸의 "인덱스별 최빈 RGB 일치율" 0.735~0.796. pannelk 0.256~0.267, pannelc 0.266~0.281, 어긋난 pannelj 0.307~0.353.
- 수치·입력 SHA는 `20261004_lap914_strategy_review/recalculation.json`.

## 6. 한계

- 3.1이 실제로 패널에 쓴 순간(인자·버퍼)은 hook으로 관측한 적이 없다. §5는 결과 픽셀의 대조다.
- save006은 일본(pannelj)이다. 조선·명 패널은 높이가 163·160이라 전사 rect와 y가 다르다(파일 header 기준, 미실행).
- gate `0x41C450`이 save006에서 열려 있는지는 set_pixel 호출(전부 3.3 경유)로 추정한 것이다.
