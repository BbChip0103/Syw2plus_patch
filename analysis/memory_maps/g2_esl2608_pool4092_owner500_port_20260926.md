## PE / 주소 근거

2608의 `.psncode`, `.psndata`, `.shopai`는 2606의 G2 BSS/`.rsrc` 코드 동굴 위치를 점유한다. 따라서 2606의 절대주소를 그대로 쓰지 않고 기존 7개 섹션을 보존한 채 3개 섹션을 추가했다. 원본 section-table 빈 120바이트, ImageBase `0x400000`, section/file alignment `0x1000`, 원본 `SizeOfImage=0xD2E000`을 확인한다.

| section | RVA | VA | virtual/raw size | 역할 |
| --- | ---: | ---: | ---: | --- |
| `.g2bss` | `0xD2E000` | `0x112E000` | `0x765000` / 0 | 확장된 공유 유닛 풀 및 목록 |
| `.g2code` | `0x1493000` | `0x1893000` | `0x3000` / `0x3000` | 저장·로드 래퍼 |
| `.g2psn` | `0x1496000` | `0x1896000` | `0x10000` / 0 | 4093×16바이트 portrait cache |

새 `SizeOfImage=0x14A6000`. 2606 G2 `.text` 변경 청크 1338개(4바이트 1315, 3바이트 16, 2바이트 7)를 정확한 old bytes와 종류별 범위로 분류·검사하고 주소를 `+0xA2000` 옮겼다. `.psncode`의 실제 풀 참조 8개를 재배치했다. 해당 섹션의 상한은 1200→4093, post-load 1199→4092, cache VA `0x110C000→0x1896000`이다. `.psndata`·`.shopai`의 유사 DWORD는 기계 코드 참조로 확인되지 않아 변경하지 않는다. 원래 2608 비-`.text` 섹션 payload는 바이트 동일 검증한다.

기존 2606 저장 마커 `N4K1`을 `N4K8`로 분리하고 portrait cache를 여섯 번째 sidecar로 저장/로드한다. 기존 세이브 fallback에서 새 cache를 지운다. 첫 이식(v1)은 여섯 번째 sidecar 때문에 load-wrapper의 `JNE rel8` 범위를 넘겨 `save006.dat` 로드 중 `EIP 0x018952AF` 예외가 났다. 배포하지 않았다. 현재 v2는 `JNE rel32`와 분기 목적지 회귀 테스트를 쓴다. `N4K8` 세이브를 과거 실험 EXE와 섞지 않는다.

`create_copy`는 새 파일만 생성하고 `restore_copy`는 정확한 후보 바이트가 일치할 때만 원본 사본으로 되돌린다. 입력 EXE는 쓰지 않는다. section 비중첩, 주소/old-byte, PE 파서 경고 없음, 래퍼 콜 목적지, 버전 거부를 테스트한다.

## 검증 범위

세 후보는 각각 전용 게임 복사본·prefix·Xvfb에서 실제 화면 입력으로 HQ/생산 예약/중간 저장/300 tick 이상 경과/로드/생산 완료를 확인했다. JSON은 `local/runtime/g2_esl2608_{shop_v2,seven_v2_roundtrip,fixed_v2}/.../output/g2_ingame_probe.json`이며 모두 `PENDING_PRODUCTION_ROUNDTRIP_PASS`이다. 7명판은 원본 `save006.dat` 로드 후 합성 high-slot(4092) 생산자 초상화 클릭으로 카메라 `[49,159]→[158,95]`을 확인했다 (`local/runtime/g2_esl2608_portrait_v2/.../output/portrait_probe.json`). 이 합성 fixture는 자연 등용 전체를 증명하지 않는다.

남은 위험: 8인 동시 활성·각 전비5000·멀티/LAN 및 장기 세이브는 미검증. 시작자리고정판 nation1 장수 초상화 생산 완료는 90초 내 관측되지 않았고 원본 대조도 없어 **미결**이다. 따라서 이는 사용자 시험용 4092/500 빌드이지 G2 마일스톤 승인 근거가 아니다.
