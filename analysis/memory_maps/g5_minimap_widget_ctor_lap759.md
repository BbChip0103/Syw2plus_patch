# 미니맵 위젯 위치 초기화 함수 (lap759, 정적 + 실측 확인)

원본 `[HQ]Syw2plus 2002.exe`(SHA `b56986e018b43293be8d9945521d145bba8dbe4e49fe70c6b6488b8c9c08a8ac`)
기준. 참고 저장소 `Syw2plus_re`(read-only)의 `analysis/memory_maps/cafe_community_offsets.md`
§13(`0x451C12`=미니맵 X좌표, `0x451C19`=미니맵 Y좌표)을 출발점으로 삼아 objdump 정적 분석 +
gdb 실시간 breakpoint trace로 재확인/확장했다.

## 정적 확인 (objdump -d, 0x400000~0x800000 전수 xref)

```
451c10: c7 01 00 00 00 00     mov DWORD PTR [ecx],0x0        ; this+0x0 = 0   (X)
451c16: c7 41 04 fd 01 00 00  mov DWORD PTR [ecx+0x4],0x1fd   ; this+0x4 = 509 (Y)
451c1d: c3                    ret
```

`0x451C12`/`0x451C19`(카페 커뮤니티 주소)는 이 두 `mov [ecx±],imm32` 명령의 **imm32 피연산자
내부 바이트**다 — 즉 `.text`에 박힌 상수(항상 0x00000000/0x000001fd)이며, 이 함수가 실행되든
안 하든 값이 절대 바뀌지 않는다. **이 주소를 실행 중 실시간으로 읽어도 "서브시스템이 살아있는지"에
대해 아무 정보도 주지 않는다** — lap758이 다음 lap 후보로 제안한 "이 주소를 실시간으로 읽어라"는
전제가 이 정적 확인으로 반증됐다.

전수 xref 스캔 결과 `0x451C10`의 직접 호출자는 **`0x451138` 단 한 곳뿐**이며, 이는
`0x451130`에서 시작하는 큰(약 0x1c000바이트) 구조체 초기화 함수 내부다. 호출 직전
(`0x41b595: mov ecx,0x639350` → `0x41b59a: call 0x451130`)에서 `ecx`(this)가 **고정
정적 주소 `0x639350`**임을 확인했다(힙 포인터 아님).

## 실시간 확인 (gdb 전수 진입 카운트 trace, lap759)

`tools/g5_minimap_init_breakpoint_probe.py` + `tools/g5_minimap_init_entry_trace.py`로,
Wine 프로세스 spawn 직후부터(메인 메뉴 도달 전) 격리 실행 전체(메뉴→솔로 로비→인게임→미니맵
좌클릭/우클릭/m·Shift+M·Tab 키)에 걸쳐 non-invasive breakpoint(`stop()`이 항상 `False`를
반환해 실제로 멈추지 않음)로 `0x451130`/`0x451C10` 진입을 셌다.

**결과: 두 주소 모두 정확히 1회씩 호출됨**(`widget_ctor_FUN_00451130`=1,
`xy_writer_FUN_00451C10`=1). 호출 시점의 `ecx`=`esi`=`0x639350`(정적 분석과 일치),
`widget_ctor_FUN_00451130`의 복귀주소는 `0x41b59f`. 이 복귀주소 주변(`0x41b590`~)은
`ecx=0x892410`으로 `0x4a4090`을 호출하고 `0x975914`/`0x975b20`대 플래그를 만지는 코드로,
**기존 G5 새게임초기화(H-NEWGAME-INIT, `0x892410`/`0x4a3060`, lap752~754) 조사와 같은 코드
영역**이다 — 즉 미니맵 위젯 X/Y 초기화는 "새 게임 시작"(솔로 로비→인게임 전환) 경로의 일부로
1회 실행되며, 프로세스 시작 시점이나 맵/미니맵 토글마다 반복 실행되는 것이 아니다.

## 결론 / 다음 단계용 주소

- **미니맵 위젯이 이 격리 환경에서 완전 비활성은 아니다** — 위젯 구조체(정적 주소 `0x639350`)의
  X/Y 필드가 새 게임 시작 시 실제로 (0, 509)로 초기화되는 것을 실행 증거로 확인했다. lap758의
  독립 negative 증거(참고 저장소도 렌더 함수를 못 찾음)와 모순되지 않는다 — "위젯 존재/초기화"와
  "렌더 진입점 발견"은 별개 질문이다.
- **다음 실측에 쓸 수 있는 새 주소(미실행, 다음 lap 후보):** `0x639350`(X, dword)/`0x639354`
  (Y, dword)는 정적 상수가 아니라 **위젯의 실제 런타임 상태**이므로, 게임 진행 중 다른 시점(예:
  카메라 이동, 미니맵 클릭 시도 전후)에 이 두 주소를 읽어 값이 (0,509)에서 변하는지 확인하면
  "초기화만 되고 그 뒤로 죽었는지" 대 "실제로 갱신되는데 렌더만 실패하는지"를 가를 수 있다.
- 이 파일은 원본 읽기 전용 정적/실행 증거만 담는다. 제품 코드 변경 없음. 전문(gdb 이벤트 로그,
  probe-result.json, 캡처)은 `docs/history/laps/20260929_lap759_work_g5_minimap_widget_ctor_live_trace.md`
  참고.
