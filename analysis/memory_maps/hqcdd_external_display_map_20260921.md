# 외부 저장소 HQCDD의 표시/전장 주소 지도 — 2026-09-21 흡수

출처: `https://github.com/Jeongyong-park/syw2-ddraw` (HQCDD, MIT, v0.7.1, 2026-09-12 마지막 푸시).
SYW2Plus 전용 DirectDraw→D3D11 래퍼이며 실험적 16:9 전장(1068×600, HUD X=134)을 포함한다.

**신뢰 등급 규칙:** 이 문서의 주소는 **외부 주장**이다. 아래 "독립 확인" 절의 항목만
우리 핀된 원본에 대해 이번 세션이 직접 대조했다. 나머지는 HQCDD 문서의 서술이며
우리가 재현하지 않았다. AGENTS.md "다른 버전 오프셋을 추측 적용하지 않는다"에 따라
확인되지 않은 항목을 패치 근거로 쓰지 않는다.

## 독립 확인 — 함수 진입점 26곳 (이번 세션)

핀된 원본 `b56986e0…`과 `조선의반격 ESL 2601 (멀티용).exe`(`02b65090…`)의 각 주소
16바이트 창을 비교했다. **26/26 전부 바이트 동일**이며, 디스어셈블 결과도 함수 진입
형태(프롤로그 또는 전역 로드)로 일관됐다. 즉 HQCDD가 2606에서 얻은 주소는 최소한
함수 경계 수준에서 우리 원본과 같은 자리에 있다.

의미(이름)는 별개이며, 우리가 각 참조의 역할을 확인한 것은 아니다.

### 산술 교차검증 (통과)

- 전장 캐시 `0xBA3D30` → 다음 객체 `0xC0BD30` 간격 = **425,984B**, 그리고 832×512 = **425,984** — 일치.
- 전장 사각형 right/bottom이 inclusive 831/511이면 **832×512** — 캐시 크기와 일치.
- 8인 시야 259,200B = 8 × 32,400 = 8 × 180×180 — 정수로 떨어짐.

## HQCDD 주장 (우리 미검증)

- 모드 3 = 800×600×8, 모드 4 = 원래 1024×768×8. SYW2X도 `0046452C`/`00464533`을 바꾼다.
- 16:9는 표시 1068×600, HUD 오프셋 134, 내부 캐시 1088×608, 변경 표 17×16, 600행 복사.
- 복사 함수 실측: 1067픽셀은 6바이트 불일치, **1068·1088은 전 픽셀 일치** (Unicorn 실행).
- `009E2B74`는 그리기(`0049ACC0`)와 판정(`00498C20`)이 **공유**하므로 X 원점 하나만 옮기면 둘이 함께 이동.
  → 우리 스캔의 절대참조 2건은 `0x497C8F`/`0x499D98`이며, 이 두 위치가 HQCDD가 지목한
  두 함수 내부인지는 **함수 경계 미확인**이다. 로더가 값을 쓰는 경로도 절대참조로는 잡히지 않았다.
- 하단 배경은 `0041C5C0`에서 `0104F814` surface를 `BltFast(x=0, y=화면높이-HUD높이)`.
- 피격 경고는 `00451890`이 미니맵 좌표를 `object+0x2BAB2`에 저장하고 `00451920`이 읽어 `00451A09`에서 `00419DE0` 호출.
- DirectPlay 전송: `00439FA0 → 00439E80 → 0046B300 → IDirectPlay4A::SendEx`, GUID
  `0AB1C531-4745-11D1-A7A1-0000F803ABFC`, vtable 오프셋 `0xC4`.
- 시야 비교: 6개 카메라/플레이어 조합 × 모드당 228회 실행에서 `0089D58E` 259,200B가 일치.
  중앙 카메라 갱신 타일이 1,024 → 4,096으로 증가(작업량 관측이며 FPS/틱 지연 측정 아님).
- 영상 초기화 `0x4697A0`이 AMStream(CLSID `49c47ce5-9ba4-11d0-8212-00c04fc32c45`)을 쓰므로
  영상 파일을 지워도 `DDRAW.dll!DirectDrawCreate` 의존이 남는다.

## 우리 G1에 대한 함의

G1(원본 구성 1600×1200)이 "월드 시야 확대 vs 스프라이트/HUD 원본 픽셀 크기"에서 막혀 있는데,
HQCDD는 **1068×600 + HUD 중앙정렬**이라는 더 좁은 범위로 실제 플레이까지 도달했다.
위 주소들은 우리가 미결로 둔 전장 캐시·HUD 좌표 공유·하단 배경 합성의 **후보 진입점**이다.

**단, 이것은 G1 합격 근거가 아니다.** HQCDD의 표시 크기는 1068×600이고 우리 목표는
1600×1200이다. 배율·캐시 크기·변경 표 형태가 모두 다르므로 수치를 그대로 옮길 수 없다.

## 한계

- 우리는 HQCDD 기준본 2606을 보유하지 않았고, HQCDD의 Unicorn 실험을 재현하지 않았다.
- 확인한 것은 **주소의 위치 일치와 참조 존재**이며, 각 함수의 의미는 HQCDD 서술을 옮긴 것이다.
- HQCDD v0.7.1은 `.text`/`.rdata`/초기 `.data`의 SHA-256을 검증하므로 **`.text`를 바꾼 EXE에서는
  16:9가 거부된다**. 우리 장수/전비 패치와 HQCDD 16:9는 현재 방식으로는 공존 불가다
  ([[hero-limit-supply-patch-sites-20260921]] 참고).
- 외부 저장소는 읽기 전용으로만 다뤘고 클론은 세션 임시 경로에만 두었다.
