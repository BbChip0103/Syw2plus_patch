## 집결지 필드 writer

생산 건물/유닛 구조체의 `+0x654`/`+0x656`는 다음 세 계열로 분리된다.

| VA | 명령 | 의미 | 판정 |
|---|---|---|---|
| `0x411B85` / `0x411B8C` | `mov [ebp+0x654/656], si` | 구조체 생성 시 `0,0` 초기화 | 초기화, UI 입력 아님 |
| `0x412589` / `0x412590` | `mov [ecx+0x654/656], ax` | command `0x15`에서 `-1,-1` 제거 | 입력 계약의 reset writer |
| `0x4125A5` / `0x4125AF` | `mov [ecx+0x654/656], ax` | command `0x15`의 packed 좌표 저장 | **실제 rally writer** |
| `0x48B12F` / `0x48B136` | `mov [esi+0x654/656], ax/cx` | 특정 unit flag `0x40000000`에서 자기 위치+3 | 자동/생성 경로, UI 입력 아님 |

`0x412540`은 다섯 인자를 받는 command 적용 함수다. 첫 인자가 `0x15`이면 packed
좌표를 분해해 `+0x654/+0x656`에 저장하고 `0x4A9A40`으로 후속 이벤트를 발행한다.
`0x40FF90`은 이 command를 UI/공용 forwarder에서 호출하는 wrapper이며, 따라서
좌표 클릭을 `+0x654/+0x656` 변화로 판정해야 한다. `0x412589`/`0x4125A5`는 직접
호출 xref가 아니라 `0x412540` 내부 분기다.

## 장수 카운터와 활성 경로

PlayerStruct[0]의 장수 카운터는 `0x956770 + 0x980 = 0x9570F0`이다. 실제 UI
player가 nation `n`이면 구조체 배열 stride `0x3ABC`를 적용한
`0x956770 + n*0x3ABC + 0x980`을 읽어야 한다.
`0x43E7F0`은 장수 템플릿 flag bit3를 확인한 뒤 `[ecx+0x980] < 7`이면 1,
그렇지 않으면 0을 반환하는 공용 eligibility helper다.

- `0x43FDE7`: 전비 계산 중 `+0x980 = 0` 초기화
- `0x43FE60`: 장수 조건 일치 시 `++[+0x980]`
- `0x43FEA9`: 장수 조건 처리 후 카운터 재기록
- `0x406B68 -> 0x43E7F0`: 생산/패널 동작의 장수 활성 판정 호출
- `0x48D1B7 -> 0x43E7F0`: 장수 관련 유닛 동작의 동일 판정 호출
- 상한 소비 지점: `0x40D8D3`, `0x4121A8`, `0x4124D2`, `0x49A5C3`에서
  `0x9570F0` 또는 `+0x980`을 읽어 `7`과 비교

이 정적 결과는 장수 버튼이 실제로 클릭 가능한 fixture라는 것을 증명하지 않는다.
그것은 다음 fresh baseline 실행에서 `hero_count_raw` 변화와 생산 결과로 판정한다.

## lap795 중간 tier 독립 정정 — 집결지 UI 입력 계약

lap794의 writer 식별은 맞지만, 그 사실만으로 **지도 우클릭이 command `0x15`를 만든다**고
볼 수는 없다. baseline SHA를 다시 확인하고 `objdump -d -M intel`로 발행 경로를 역추적한
결과, 실제 UI 계약은 다음과 같다.

1. 명령 설명자 table entry `0x11`은 초기화 `0x496556..0x49656D`에서 action `0x15`,
   보조값 `0x0B`, 단축키 `T/t`로 등록된다. 선택 패널의 live 12-slot 배열은
   `0x8930A6 + 2*slot`이고 `0x4A3A40`이 이 값을 읽는다.
2. 패널 클릭 경로 `0x49958D..0x499811`은 그 slot의 설명자를 `0x496360`으로 action에
   매핑해 `0x892FFE`에 쓴다. 따라서 집결 모드 진입의 직접 기계 지표는
   `slot descriptor == 0x11` 및 클릭 직후 `0x892FFE == 0x15`다.
3. 활성 action이 `0x15`인 상태에서 지도 **좌클릭**이 `0x41EBF6..0x41F0A4`를 지나
   `0x4AE550`에 `action=0x15`와 packed world 좌표를 넘긴다. 이후 command queue가
   `0x4AEC60 -> 0x40FF90 -> 0x412540`으로 적용되고 `ecx`는 선택한 HQ 구조체여야 한다.
4. 빈 지면 좌표면 `0x41259F` 분기로 가 `+0x654/+0x656`에 좌표를 쓴다. 기존 rally와
   동일한 좌표를 다시 누르면 `0x412569..0x412597`이 `-1,-1`로 reset하므로, fresh probe는
   현재 값과 다른 유효 지면을 골라야 한다.

기존 UI 증거도 이 정정을 지지한다. lap794 r2는 `(704,503)`의 `R` 셀 뒤 지도 좌클릭에서
선택만 `1→0`, rally는 불변이어서 그 셀이 집결지 모드가 아님을 이미 반증했다. 같은 baseline의
2026-09-26 HQ 캡처와 lap794 r4 캡처는 첫 행 네 번째 `(776,503)`에 붉은 깃발 버튼을 보인다.
다만 unit type/nation별 command list는 runtime `Data`에서 채워지므로, **좌표만 믿지 말고**
다음 work가 HQ 선택 직후 12-slot을 읽어 descriptor `0x11`의 실제 slot을 확인한 뒤 그 셀을
좌클릭해야 한다. 정적 계약상 `T` 단축키도 같은 action 후보지만, fresh 1회는 패널 클릭을
우선해 사용자 조작과 동일한 경로를 검증한다.

lap794 r3의 `R 셀 + 지도 우클릭`과 r4의 `지도 우클릭만`은 어느 쪽도 위 계약을 충족하지
않는다. 따라서 세 raw의 rally 불변은 제품 결함 증거가 아니라 하네스 입력 불일치다.
