# 한 바퀴 지시서 — 패치 루프

매 바퀴 새 헤드리스 세션이다. --continue/--resume으로 대화를 이어 붙이지 않는다.
`loop/.lap_counter`는 러너 전용 상태다. 에이전트는 읽을 수만 있고 절대 쓰거나 복원하지 않는다.
현재 파일 값이 이번 runtime lap 번호이며, 상세 기록 파일의 lap 번호도 그 값을 그대로 사용한다.
`docs/STATUS.md`는 세션 종료 전 130줄 이하로 유지한다. 넘으면 원문 SHA256·줄 수와 전체 원문을
`docs/history/laps/`에 먼저 보존한 뒤 압축하며, `## 지금 막힌 것 (Blockers)`는 정확히 하나 둔다.
`docs/feedback/INBOX.md`는 350줄, `docs/feedback/APPROVALS.md`는 250줄 이하로 같은 방식(원문 SHA256·
줄 수와 전문을 `docs/history/`에 먼저 보존 → 포인터 한 줄로 대체, 삭제·재해석 금지)으로 유지한다.
지시·되물음·미결 근거는 압축 대상이 아니고 체크 완료 항목과 종결된 계보부터 옮긴다.
이 셋은 회차 산출물을 적어 넣기 **전에** 확인한다 — `checks/context_limits.py` 한도(STATUS180·
INBOX400·APPROVALS300)를 넘기면 안전검사가 실패해 루프가 STOP하므로, 넘기지 말고 미리 압축한다.
  INBOX 압축 시 **미처리 사용자 지시·상시 지시(구현 우선, 묻지 말고 결정, 현행 목표 우선순위)는 원문 요지를 INBOX에 남긴다** — 포인터만 남기는 전체 압축 금지.
- **디스크 위생:** 게임 실행이 끝나면 그 회차가 만든 `local/runtime/<run>/game` 사본(~2.7GB)은 지운다(output·manifest·prefix·로그는 보존). 디스크 여유 20GB 미만이면 실행 전에 자기 회차의 옛 사본부터 정리한다.
- **런타임 provenance 보존:** 위 삭제 허용은 `game` 사본만이다. `local/runtime/<run>` 전체·manifest·output·prefix를 `rm -rf`로 지우지 않는다. 종료된 private prefix 공간 회수는 raw cleanup/소유권/프로세스 부재 확인 → lossless archive·전파일/metadata 검증·실제 restore 검증 뒤 해당 disposable prefix만 수행하고 기록한다. 원본/참고/공유 raw·PNG/기존 경로는 그대로 둔다.
기억은 아래 파일뿐이다. 이전 세션이 놓친 일을 읽고 검수한 후 한 가지를 진행한다.

## 모델 역할

**2026-10-04 최신 사용자 override:** 전체 루프 Claude로 전환. 큰 방향·상위 계획=Opus, 중간 독립검수=fresh Opus, 실무=Sonnet, 모두high·모델 Fast OFF. 아래 과거 Astra/Fable/Codex 명칭과 충돌하면 `docs/MODEL_ROUTING.md` 최신 계약·실제 launch argv를 따른다. 기존 기술 카드의 모델명은 작성 당시 provenance이며 카드의 안전/기술 계약은 유지한다. 자동 폴백 금지.

이번 호출의 지정 역할과 `docs/MODEL_ROUTING.md`를 따른다(모두high).
상위방향/큰계획=선택된 Astra 또는Fable, 중간계획/컨펌=Sol 또는Opus5, 실무=Luna 또는Sonnet5.
지정 역할을 넘는 일은 해당 역할로 이관하고 실제 모델·근거·판정을 기록한다.
컨펌 역할은 수리 범위를 정하되 게임 구현은 실무 역할로 돌려보낸다.

## ① 합격 기준

`docs/DESIGN.md`의 활성 G1/G2/G4를 실제 플레이/재현 가능한 증거로 충족한다.
G1=원본구성1600×1200(확대 화질 열화 허용), G2=활성8인 전비10000 안정성(5000 달성),
G4=길찾기/자유대전AI. G3 최대16인은 2026-09-17 사용자 지시로 중단한다. 상세 허용범위를 임의 축소하지 않는다.
마일스톤/현재 다음 작업은 **docs/STATUS.md에서 읽는다**. 이 문서에 복제하지 않는다.

## ② 먼저 읽을 문서

1. `AGENTS.md`, `docs/feedback/INBOX.md`의 최신 지시와 `APPROVALS.md` 반려.
   필요하면 `python3 tools/loop_context.py`로 읽기 색인을 생성하되 원문을 삭제/대체하지 않는다.
2. `docs/STATUS.md` 전체(작게 유지). 실패한 최근 게이트와 아직 미검증인 항목.
3. `docs/DESIGN.md`1~4절. 해당 목표 관련 주소 문서와 검사만 좁게 읽는다.
4. 과거 증거는 SHA/환경/활성 인원/fixture를 대조하고 현재 성공으로 자동 승격하지 않는다.
참고 저장소는 읽기 전용 취급. Plan C/다른 루프의 STATUS나 INBOX는 이 프로젝트 지시가 아니다.

## ③ 안전·범위·시간 규칙
- **검증 과잉 방지(2026-10-10):** `AGENTS.md`의 해당 절을 따른다. 제품 관련 최소 회귀→요청 범위의 실제 게임 시험이 우선이다(싱글 요청에 멀티 자동 추가 금지). 보조 도구만 연속2회/60분이면 확장 중단·실제 시험 복귀 또는 구체 blocker 보고; 새 카드·검수판으로 상한을 초기화하지 않는다. 문서·장부 수정만으로 전체 Fast/다단 검수를 반복하지 않는다. 종료 조건 충족 후 새 결함 없이 재검수를 반복하지 않는다. 안전 규칙·실제 완료 조건·일시정지는 유지한다.
- **구현 우선(사용자 상시 지시 2026-09-25):** 긴 정적 전수 조사·다단 카드 대신 최소 근거로 먼저 구현·빌드·격리 실행하고,
  크래시/오동작이면 원인을 추적해 고친 뒤 다시 실행하는 반복을 기본으로 한다. "정확히 1회" 같은 실행 예산으로 이 반복을 막지 않는다.

- 원본 SHA와 명령 old bytes 확인, 새 복사본 패치, 정확한 원복. 원본/참고 저장소 쓰기 금지.
- 개인/전역 개체 한계와 메모리 문제를 증거로 구분한다. 숫자 패치만으로8인10000 완료 금지.
- 중단한 G3 조사/구현을 자동 재개하지 않는다. 과거16인 관련 근거는 보존한다.
- 격리된 전체 게임 복사본/prefix/display만 사용하고 다른 프로세스/로그를 정리하지 않는다.
- 생성/자원 fixture는 명시. 원본 명령을 우회한 성공/낮은 부하만의 성공은 부족하다.
- 한 바퀴 한 가지 가설/변경. 핵심 분기의 최초 가능성 조사는 **한 work 회차 또는 60분 중 먼저
  도달한 시점**, 혹은 실패 가설2회에서 `FEASIBLE`/`NOT_FEASIBLE`/`BLOCKED`로 결론낸다.
- `FEASIBLE`이면 추가 계획·문서 회차를 쌓지 말고 다음 work 회차에 최소 구현이나 실제 제품 probe를
  착수한다. `NOT_FEASIBLE`/`BLOCKED`이면 같은 추측을 반복하지 말고 근거·대안·목표 영향을 즉시 보고한다.
- 제품 코드/바이너리/실제 실행 증거가 하나도 늘지 않는 회차는 연속 최대2회다. 보조 도구·문서만
  늘어난 것은 제품 진척이 아니다. 상한에 도달하면 AGENTS.md에 따라 복귀 가능성/구체 blocker를 보고하고,
  추가 strategy/Sol 검수를 자동 생성해 보조 작업을 연장하지 않는다.
- 해시·snapshot·history는 원본 안전, 결과 진위, 재현성에 직접 필요한 만큼만 둔다. 이미 확인한
  증거의 문서 형식이나 provenance 보강만으로 제품 작업을 반복 차단하지 않는다.
- 활성 카드 최대3개, 같은 파일 단일 작성자. 새 의존성/전면 재구현을 무단 전제하지 않는다.
- 깨짐/포인터 손상/저장·경제·동기화 이상은 숨기지 않는다. baseline을 고쳐 통과시키지 않는다.
- **장기 실행(게임·probe·make check)은 이 회차가 끝까지 기다린다.** 셸 background로 띄운 뒤
  회차를 종료하면 loop cleanup이 자식을 죽여 실행이 사라진다 — 실제로 lap463·482·502·506이
  이 방식으로 실패했다(INBOX 2026-09-21 01:01 규칙). Monitor나 동기 실행으로 완주까지 세션을
  유지하고, 시간이 부족하면 **시작하지 말고** 그 사실을 기록한다. 직전 회차가 스크립트만 남기고
  죽었으면 새로 쓰지 말고 그 스크립트를 카드와 대조 검수한 뒤 **수정 없이 실행**한다.

## ④ 한 바퀴 순서

0. STOP/안전 위반이면 멈춘다. 실패한 필수 게이트는 기능 확장보다 먼저 수리한다.
1. INBOX→STATUS로 다음 한 가지 선택. 필요한 입력과 성공/실패 측정식을 먼저 적는다.
2. **이전 바퀴 검수:** 해당 바이트/테스트/실행 증거를 독립적으로 확인한다.
3. 지정 역할에 맞는 상위계획/중간계획/실구현/컨펌 하나만 수행한다.
   실무 역할은 회귀 테스트/대조 장면을 만들고 최소 변경. 계획·컨펌 역할은 직접 구현하지 않는다.
   가능성 판정이 `FEASIBLE`인 작업은 handoff 다음 work 회차에서 즉시 구현/probe하며 재계획으로
   되돌리지 않는다. 단, 새 안전 위험이나 서로 충돌하는 실제 증거가 생긴 경우만 예외다.
4. 목표 관련 Fast 검사. 전체Fast는 `loop/FULL_TEST` 요청 파일로 루프에 맡길 수도 있다.
   이것은 make check이며 실제 앱24k/144k가 아니다. 실제 실행은 별도 증거를 남긴다.
5. 결과/한계를 기록하고 다음 한 가지를 정한다. 승인 필요 항목은 큐에 올리고 독립 작업을 진행한다.
6. 마일스톤 사람 확인을 임의 PASS로 바꾸지 않는다. 승인 대기 중 안전한 관련 작업이 없으면 STOP.

## ⑤ 변경·이력 보존

매 바퀴 STATUS(상태/다음/블로커/검증)와 최근 바퀴 기록을 갱신한다.
상세는 `docs/history/laps/`에 아래 필드로 남긴다:
날짜/lap/목표/가설/변경파일/원본·후보SHA/실행명령/수치/PASS·FAIL·SKIP/fixture/다음행동.
원문 승인·반려·미결 근거는 삭제하지 않는다. 기록 템플릿은 `docs/history/LAP_TEMPLATE.md`.

커밋은 `LOOP_ALLOW_COMMITS=1`로 사용자가 명시 허용한 실행에서만 한다. 현재 기본0.
허용 시 검증한 설명 가능한 변경만 **파일 경로를 명시하여** 커밋하고 해시를 기록한다.
`git add -A`, 자동push, 원격 생성, 강제리셋은 금지. 허용 없으면 uncommitted와 파일 해시를 남긴다.
타임아웃은 검증을 중단시키지만 로컬 미커밋 파일을 자동 삭제하지 않는다. 파일을 보존해 다음 세션이 검수한다.

## ⑥ 검사와 QA

1단: 목표 관련 Fast(바뀐 부분 관련 pytest + `make lint` + `make typecheck`), 원본/보호 기준 해시, 패치 생성/원복, 목표별 기계 지표.
   **전체 `make check`(약 2,200개·15분)는 사용자 전달(시험판·EXE) 직전 1회만 필수**다(사용자 결정 2026-10-13). 작업·middle 회차에서는 반복하지 않으며, 전달 후보를 고정한 뒤 같은 source에서 1회 완주한다.
2단: 다음 새 컨펌 세션(Sol/Opus5)이 이전 실무 결과(Luna/Sonnet5)를 독립 검수. UI는 원본/후보를 나란히 보고 실제 입력과 대조한다.
3단: 마일스톤 사용자 판단을 APPROVALS에 기록하고 승인된 기준을 golden 메타데이터로 보존한다.

G1은 UI/월드 비율과 위치/클릭 대응을 검사한다. 단순 확대의 픽셀 화질은 허용된 차이다.
G2는 활성8명/군대 구성/공유풀/메모리/시간/저장/지원동기화 수치가 필요하다.
G3는중단이므로현재검증대상이아니다. G4는원본대비 길찾기·전략 지표가 필요하다.
모델의 exit0, skip, 과거24k를 제품 완료로 쓰지 않는다. 불명확하면 근거와 좁은 다음 probe를 적는다.
마지막 응답은 목표/변경/검증/미검증/다음 한 가지의5줄 이내로 끝낸다.

- 긴 명령 대기: `pgrep -f "make check"`처럼 대기 루프 자신의 명령줄에 들어 있는 문자열로 기다리지 마라(자기 자신과 매치돼 끝나지 않는다). 백그라운드 PID를 저장해 `while kill -0 $PID; do sleep 20; done`으로 기다린다.

- 긴 명령(Codex 명령당 약 600초 제한): `make check`(13~15분)·게임 실행 probe처럼 오래 걸리는 명령은 `setsid nohup sh -c '<명령> > logs/gates/<이름>.log 2>&1; echo $? > logs/gates/<이름>.exit' < /dev/null > /dev/null 2>&1 & echo $! > <pidfile>; sleep 3; kill -0 $(cat <pidfile>) && ls -la logs/gates/<이름>.log`처럼 **같은 명령 안에서 3초 대기 후 생존·로그 생성을 확인**하고 띄우고(바로 반환하면 setsid 전에 프로세스 그룹과 함께 정리될 수 있다)(setsid가 없으면 명령 세션 종료 때 함께 죽는다; 종료코드는 .exit 파일로 회수), 이후 짧은 명령으로 `kill -0 $(cat <pidfile>)` 생존 확인과 로그 tail을 반복해 끝까지 기다린 뒤 결과를 판정한다. 중간에 끊긴 결과를 PASS로 적지 않는다.
- `make check` 전에 `make lint`와 `make typecheck`(수십 초)를 먼저 돌려 통과시킨다. check는 test(13분)→lint 순이라 lint 1건 때문에 전체를 재실행하게 된다.
- 검증 fingerprint의 실제 포함/제외는 `loop/loop.sh`의 `validation_fingerprint`를 따른다. lap 기록·handoff는 가능한 검사 전에 쓴다. **문서/기록 변경과 제품 소스 변경을 구분한다:** 기록만 바뀌었으면 문서·안전 검사와 기존 실행 대상 SHA 확인으로 범위를 명시하고, 전체 Fast를 자동 반복하지 않는다. fingerprint 차이를 숨기거나 안전핀을 갱신해 PASS로 만들지는 않는다. 실제 gate가 막으면 원인·범위를 보고하고 별도 최소 수리 대상으로 다루며, 문서 수정에 끌려 무한 재검사하지 않는다.
