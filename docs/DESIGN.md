# DESIGN — 원본 확장 패치의 네 목표

사용자 확정(2026-09-10). 새 지시가 없는 한 루프가 목표/허용 오차를 바꾸지 않는다.
구조 출처는 `Syw2plus_re_loop`; **제품은 재현 엔진이 아니라 원본 기반 버전/패치**다.

## 1. 한 줄 합격 기준

원본의 화면 구성과 조작을 유지하면서 차후 고해상도 이미지의 디테일을 살릴 수 있는1600×1200 화면, 8인 전비10000 안정성(5000 단계 달성),
개선된 길찾기/자유대전AI를 실제 플레이와 재현 가능한 근거로 검증한다.
2026-09-17 사용자 지시로 G3 최대16인은 중단한다. 활성 목표 G1/G2/G4; 기존 번호·과거 근거는 보존한다.
2026-09-25 사용자 지시로 **G5(드래그 선택 상한 20→50)를 추가하고 최우선**으로 둔다. G1/G2/G4 진행분은 보존하되 후순위.
각 목표는 독립 검증하되 마지막에는 함께 적용한 동일 후보를 검증한다.

## 2. 목표와 완료 조건

### G1 — 원본 구성 그대로1600×1200

- 기준800×600/4:3 → 출력1600×1200/4:3, UI/월드/스프라이트 상대 크기와 구도 유지.
- 시야만 넓히는 작업이 아니다. **800×600 최종 화면의 정수2배 출력만으로는 G1 완료가 아니다.**
  그 방식은 배치·입력 확인용 프리뷰일 뿐이며, 차후 2배 해상도 스프라이트의 추가 디테일을
  최종1600×1200 픽셀까지 보존할 수 있는 렌더/합성 경로가 필요하다.
- **스프라이트 단순 리사이징의 화질 저하는 현재 허용**한다. 사용자가 차후 별도 이미지를
  제작해 교체한다. 그림 재제작 자체를 지금 완료 조건/블로커로 두지 않되, **교체한 그림이
  800×600 최종 버퍼로 축소됐다 다시 확대되는 구조는 G1 합격 경로로 보지 않는다.**
- 허용하지 않는 것: HUD 조각 분리, 잘림/비율 왜곡, 클릭 좌표 불일치, 시야 확대 대체.
- 같은 상태의 원본/후보 캡처와 실제 입력(선택/드래그/미니맵/메뉴/생산)으로 판정.
- 1080p 물리 모니터보다 목표의 높이1200이 크므로 창/전체화면 표시 정책을 기록한다.

### G2 — 8인 각각 전비 상한10000으로 안정 플레이

- 2026-09-26 사용자 판단: **전비5000 단계는 달성으로 본다.** 새 목표는 **활성8인 각각 전비10000**이다.
  아래 조건의 "5000"은 이제 "10000"으로 읽는다(과거 5000 근거·기록은 보존). 5000 단계 후보·증거를 10000
  완료 증거로 승격하지 않는다. 개인 개체 상한1200·전역 풀10,000이 전비10000에서 병목이 되는지는 측정으로
  판정하고, 상한 변경이 필요하면 근거와 함께 기록한다.

- **8명의 활성 플레이어**가 각각 전비5000에 접근/도달하고 전투·생산·사망·재생산한다.
  빈 슬롯8개에 cap=5000만 적힌 관측이나 1명 시험은 합격 아님.
- 사용자 제기 위험: 원본 최대 개체/공유 슬롯 구조 때문에 한계/메모리 문제가 날 수 있다.
  **메모리 초과가 이미 재현됐다고 기록하지 않는다.** 먼저 고장 형태를 측정한다.
- 조사/변경 범위: 개인 개체 상한, 전역 풀/예약 슬롯, 유닛ID/인덱스 폭, 소유자 목록,
  공간 인덱스/경로 탐색 큐, 투사체/효과/건물, 저장 크기와 네트워크 직렬화.
- 계측: 실제 소유 개체 수·전비 비용 합계·풀 사용/고수위·할당 실패·메모리 사용/주소 공간·
  tick시간/정체·크래시·잘못된 ID/생산 누락. OOM/범위 초과/생성 거부/CPU정체를 구분한다.
- 대표적인 저전비 다수/고전비 군대/건물/효과 혼합으로 시험한다. 전비는 개체 수가 아니다.
  전비0 객체까지 고려하며 단순히 총전비40000을 유닛40000개로 바꾸지 않는다.
- 테스트 준비용 생성/자원 지급은 명시하고, 정상 생산·전투·저장로드를 후속 검증한다.
- 같은 후보의 관련 실제24k 및 장기144k, 저장/로드, 지원 멀티 동기화가 필요하다.
  성능 목표는 시험 하드웨어/지도/군대 구성을 고정한 뒤 사전에 정한다.
- 2026-09-23 18:43 사용자 Q8=(ㄱ): cap5000 접근/도달은 AI 자연 도달 대신 **명시된 gate-legal 시딩**으로 만들어도 된다.
  위의 전투·생산·사망·재생산, 저장/로드, 24k/144k, 멀티 조건은 그대로다. 해석과 순서는
  `docs/work/active/G2_STRATEGY_Q8A_SEEDED_ACCEPTANCE_LAP522.md`(strategy, 사용자 번복 가능)에 있다.
- 2026-09-25 사용자 추가 목표: **실사용 가능한 전역 공유 유닛 풀 상한을 10,000개**로 늘린다
  (0번 비사용 슬롯은 실사용 개수에 포함하지 않는다). 인당 전비 상한5000과 개인 개체 상한1200은
  이 지시로 바뀌지 않는다(인당 전비 목표는 2026-09-26에 10000으로 상향됨, 위 참조). 8명×1200개는 최대9600개이므로, 풀의 10,000개 동시 점유를
  합격 기준으로 삼으려면 나머지400개를 채울 합법적인 개체/소유자 fixture를 먼저 명시한다.
  기존 4001슬롯 후보의 24k·144k 증거를 이 추가 목표의 완료 증거로 승격하지 않는다.

### G3 — 최대16인 플레이 (중단: 2026-09-17 사용자 지시)

아래는 과거 계약 보존이며 현재 구현/조사/완료 대상이 아니다. 불가능성을 새로 증명한 판정이 아니다.

- 12인이 아니라 **16인**. 로비 슬롯 숫자만 늘리는 것이 아니라 활성16명 게임이 목표.
- 테이블/루프 경계/동맹·적대·시야 비트/색상/소유자ID/지도 시작점/AI/승패/저장/통신을 추적.
- 9~16번 플레이어의 생성/명령/시야/동맹/승패/저장 복원이 모두 실제로 동작해야 한다.
- 16인 인간 멀티를 지원한다고 표시하려면 실제 지원 전송 방식의 동기화 시험이 필요하다.
  16개 로컬AI만으로 인간16인 네트워크 완료를 주장하지 않는다.
- 16인×전비5000 조합은 별도 추가 부하 조건이다. G2의8인5000 증거를 확장 재사용하지 않는다.
  조합을 제공할지와 최대 지원 부하는 측정 후 명시하며 임의로 지원한다고 광고하지 않는다.

### G4 — 길찾기 및 자유대전 컴퓨터 AI 개선

- 길찾기: 장애물/좁은 길/대규모 군집/재탐색/도달 불가/건설로 변하는 통로를 시험한다.
  도착률, 정체 시간, 경로 비용, 처리 시간/메모리를 원본과 비교한다.
- 난이도: 생산/경제/정찰/공격/방어 등 전략 행동을 측정하고 난이도별 차이를 검증한다.
  자원 치트만 추가하고 알고리즘 개선이라 하지 않는다. 의도적 보정이 있으면 공개한다.
- 원본 동작과 개선 동작을 비교/원복할 수 있게 구분한다. 허용하지 않은 규칙 변경은 금지.
- 저장·리플레이·멀티를 지원하는 경로에서는 결정론/동기화 회귀를 검사한다.
- 알고리즘/SDK를 지금 임의 확정하지 않는다. 원본 병목과 반복 가능한 비교 장면부터 만든다.

## 3. 마일스톤 순서 / 병렬 경계

2026-09-17 최신 사용자 지시: **G2 활성8인 각각 전비5000 안정 플레이가 최우선**.
M0 구조·기억·검증 배관 → M2 G2 → M1 G1 → M4 G4 → M5 통합 후보. M3 G3는중단한다.
G2 구조 조사와 G4 비교 장면 준비는 독립 파일로 병행 가능하다. 활성 작업 최대3개.
실제 다음 행동은 `STATUS.md`의 "다음 한 가지"만 진실로 삼는다.

## 4. 근거와 검증 등급

- 주소/명령: `analysis/memory_maps/`, 정확한 원본 SHA와 새 후보 해시.
- 기준: `docs/baseline/` 색인(새 캡처/이미지 중간결과는 공유 `temp/Syw2plus_patch/` 아래, 메인 레포에 PNG 보관 안 함), 승인분은 `golden/` 메타데이터로 승격.
- 과거 증거: `patches/population/verification_0910/`. 기존QHD는 G1 요구 미충족 참고 실험.
- Fast: 자동 테스트/린트/타입/패치안전. Integration: 실제 원본 앱 및 관련24k.
- Long/Release: 관련144k, 해당 목표의 저장/경제/지원 멀티/시각·입력 검증.
- 모든 수치에 후보SHA·지도·활성 인원·군대·시간·프로세스/입력·fixture 여부를 붙인다.
- 1단 기계 → 2단 다음 새 세션의 독립 검수 → 3단 마일스톤 사용자 판단.
  승인된 기준을 기계 회귀로 남긴다. 과거/skip/모델exit0을 현재 합격으로 승격하지 않는다.

## 5. 안전 / 범위

원본 및 참고 저장소는 읽기 전용 취급. 새 복사본과 명시적 원복, SHA/범위 검증 필수.
계측 코드가 원본 게임 로직 대신 동작하는지 구분한다. 저장·경제·메모리 손상을 숨기지 않는다.
전체 디컴파일/엔진 재현은 전제 아님. 필요한 바이너리 패치/래퍼/모듈 교체를 근거로 선택한다.
새 라이선스를 가정하거나 게임 데이터/EXE/DLL을 커밋/배포하지 않는다.
유료 세션·자동서비스·커밋/푸시는 설정만으로 시작하지 않는다.

### G5 — 드래그 선택 상한 20 → 50 (2026-09-25 18:16 사용자 지시, 최우선)

- 한 번의 드래그(마우스 사각형 선택)로 선택되는 유닛 상한을 원본 20에서 **50**으로 올리는 패치를 추가한다.
- 원본 기반 바이트 패치로 만들며, 선택 배열·부대지정(Ctrl+숫자)·선택 UI(초상화/정보창)·명령 전달 루프 등
  20을 전제로 한 모든 고정 크기/반복 상한을 전수 조사해 넘침 없이 확장한다(배열 재배치 필요 여부 포함).
- 합격: 실제 게임에서 드래그 1회로 50기 선택·이동/공격 명령이 50기 모두에 전달되고, 51기째는 선택되지 않으며,
  UI 표시·부대지정 저장/호출·저장/로드에서 크래시·메모리 오염이 없음을 원본 대비 근거로 보인다. 멀티 동기화 영향은 별도 표시.
