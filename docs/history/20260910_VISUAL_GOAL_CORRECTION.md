# 화면 목표 정정 — 2026-09-10 사용자 피드백

## 실제 요구

“해상도가 올라가면서 UI, 스프라이트 크기 이런 것들 다 원본 화면과 똑같이 구성”되어야 한다.
원본의 화면 구도, UI 배치, 스프라이트 상대 크기/비율과 클릭 대응을 유지하는 것이 기준이다.
**시야만 넓어지고 UI가 흩어진 현재 QHD 실험은 요구사항 미충족이다.**

## 이전 해석 철회

에이전트가 추가한 “넓은 게임 시야가 필수, 단순 스케일링은 완료가 아님” 조건은
사용자의 요구가 아니었다. 이 조건을 폐기한다. 현재 QHD 런타임 기록은
32비트 원본의 뷰포트를 확장할 수 있다는 기술 증거일 뿐, 원하는 화면의 성공 증거가 아니다.
전비5000의 생산/저장로드 증거는 별개로 유효하다. 24k 통합 실행도 화면 품질을 증명하지 않는다.

## 새 완료 기준

1. 원본 무패치 화면을 같은 상태에서 먼저 캡처하여 비교 기준으로 보존한다.
2. UI 전체와 스프라이트가 일관된 좌표/배율로 표시된다. 독립된 HUD 조각이나 비율 왜곡 금지.
3. 유닛/건물의 상대 크기와 화면 구도를 원본과 대조한다. 단순 출력 해상도 숫자는 합격 기준 아님.
4. 입력 좌표가 최종 표시와 대응한다. 선택/드래그/미니맵/생산 버튼을 실제 입력으로 검증한다.
5. 원본 렌더링을 보존한 출력 확대/래퍼 경로도 후보로 인정한다. 현재 뷰포트 패치를
   강제로 다듬는 것이 기본 방향은 아니다. 스프라이트 원화 디테일 증가를 자동으로 약속하지 않는다.

## 후속 사용자 확정 — 1600×1200

이후 사용자는 QHD가 아니라1600×1200을 목표로 지정했다.
원본800×600과 같은4:3이며 각 축2배다. `PRODUCT_GOAL.md`에 현재 목표를 반영했다.

## 최초 정정 당시 미결 항목 (현재 목표는 위 갱신을 따름)

4:3 원본 구도를16:9 모니터에 표시할 때 좌우 여백/배경 처리, 필터 선택 등은
아직 확정하지 않았다. 화면을 가로로 늘이거나 시야를 넓히는 선택을 묵시적으로 하지 않는다.
구현 전 기준 캡처와 짧은 시각 비교로 확정한다.

## 보존 정책

기존QHD 코드·증거는 삭제하지 않고 **요구에 맞지 않은 참고 실험**으로 보존한다.
기존 보고서의 ‘성공’은 뷰포트 기술 실험 문맥으로만 읽는다. 새 작업 큐는 이 문서를 우선한다.
