## 2. P-E 교차검증 — **다른 디스어셈블러로 독립 재계산**

lap421은 capstone5 resync sweep을 썼다(자기 도구 재실행은 독립 검수가 아니다). 이번에는 PE `.text`
(932,581B)를 추출해 **objdump(binutils)** 로 선형 디스어셈블(311,563줄)한 뒤 변위 `0x692` 접근을
전수 대조했다.

- disp `0x692` 참조 **21건**(lap421과 동일), 그중 write **5건**.
- write 5건 = `0x40bc97`/`0x40bca0`/`0x40bcab`/`0x40bcfe`(esi 누산기 블록) + `0x40c1c2`
  (`movw $0x0,0x692(%ebx)`, 상수0). → **기록자 2 site, lap421과 정확히 일치.**
- 원본 vs 후보 hit 목록 `diff` → **IDENTICAL**(패치가 이 영역을 건드리지 않음, lap421 주장 확인).

**판정: P-E ACCEPT(불일치 0).** 서로 다른 디코더가 같은 집합을 냈으므로 sweep desync 의심은 해소된다.

## 3. 폐쇄형 산술 — lap421보다 **강화**해서 확정

lap421은 전이 **3건**(0→19579, 19579→−26278, −26278→−6599)을 맞췄고, 4-tick 주기의 나머지 한 걸음
**−6599→0은 "반복"으로만 적고 유도하지 않았다**. 단순 가산으로는 −6599+19679=13080이라 0이 나오지
않는다. 또 첫 걸음의 `−100`과 `bp` 임계값을 유보했다. 이 구멍을 바이트로 닫았다.

`0x40bc86` 블록 실제 바이트(objdump):

```
40bc86  mov 0x692(%esi),%ax        ; move
40bc8d  cmp %bp,%ax  / 40bc90 jge 40bca9
40bc92  add %edi,%eax / 40bc94 cmp %bp,%ax / 40bc97 mov %ax,0x692(%esi)
40bc9e  jle 40bcb2   / 40bca0 mov %bp,0x692(%esi)      <-- clamp store
40bca9  add %edi,%eax / 40bcab mov %ax,0x692(%esi)
40bcb2  mov 0x692(%esi),%ax / 40bcb9 cmp $0x32,%ax / 40bcbd jl 40bd64
40bcf4  add $0xffffff9c,%eax / 40bcfe mov %ax,0x692(%esi)   ; -100
```

- **가산 레지스터는 `%edi`이고, `%edi`는 `+0x688`에서 온다** — `0x40bc00`/`0x40bc19`/`0x40bc30`의
  `mov 0x688(%esi),%di` 3곳(§5에서 전수 확인). lap421의 "`+0x688`을 매 tick 더한다"는 모델은
  **바이트로 확인됨**.
- lap421이 유보한 `−100`은 `cmp $0x32`(50) / `add $0xffffff9c`(−100)로 **확정**.
- `sim422.py`로 이 블록을 명령 단위로 그대로 시뮬레이션하고 `bp`와 가산값을 signed16 전 범위
  브루트포스했다:
  - 관측 시퀀스 `[0,19579,−26278,−6599,0,19579,−26278,−6599,0]`를 재현하는 **`bp`는 0 단 하나**
    (65,536개 중 유일).
  - `bp=0` 고정 시 재현하는 **가산값도 19,679 단 하나**(65,536개 중 유일) — 관측된 `+0x688`과 일치.
  - 미해결이던 **−6599→0은 `0x40bca0`의 clamp store(`mov %bp,…`, `bp=0`)** 로 설명된다.

**⇒ 전이 4/4가 폐쇄형으로 설명되고 파라미터는 가정이 아니라 유일해로 결정된다.** 결정적으로,
이 경로는 **누산기 site 하나만으로 완결**되며 `0x40c1c2` 리셋은 **필요하지 않다** — lap421의
"값을 만들 수 있는 site는 사실상 1곳뿐"은 맞다.

- **H6(외부 wild write) 기각: ACCEPT(강화).** 외부 기록자를 가정할 여지가 산술적으로 남지 않는다.
- **H5(활성화 경로 자체 결함, 실체는 `+0x688` 선오염) 확정: ACCEPT.**
- **(a) 저슬롯 대조군 대체 승인: ACCEPT.** 저슬롯 대조군은 "H6이 고슬롯에만 작용하는가"를 간접
  반증했을 뿐이지만, 유일해 폐쇄형 재현은 외부 기록자 자체를 불필요하게 만들므로 **더 강한 증거**다.
  lap421이 이 fixture로 저슬롯 활성화가 0건(N28 재확인)임을 실측한 것도 재확인했다.

## 5. W13 선행 처리 — `+0x688` 기록자 정적 전수 (P-G를 middle이 미리 닫음)

W13 카드 §2 P-G(정적, 게임 미실행)는 middle 범위 안이라 이번 회차에 **완료**했다. 같은 objdump
대조로 변위 `0x688` 접근 **7건**, 원본 vs 후보 `diff` **IDENTICAL**:

| VA | 형태 | 성격 |
|---|---|---|
| `0x40bc00`,`0x40bc19`,`0x40bc30` | `mov 0x688(%esi),%di` | **read** — 누산기 가산값 로드(§3) |
| `0x40c0b2` | `add 0x688(%ebx),%di` | read |
| `0x411ec0` | `mov %dx,0x688(%ebp)` | **write** — 직전 `mov 0x9b5258(%eax),%dx`, 즉 **유닛타입 스탯표 복사**(같은 블록이 `0x9b5268`/`0x9b526a`/`0x9b526c`/`0x9b5270`/`0x9b5272`도 연속 복사). 스탯표 계열 `0x9B5238`은 F4 blocker의 비용표와 같은 family |
| `0x48cba9` | `mov %dx,0x688(%esi)` | **write** — 수명 중간 write, 직후 `cmp $0x46,0x8d(%esi)` 타입 분기 |
| `0x4c582c` | `movl $0xb02c,0x688(%ebx)` | write, **32bit 상수** — 다른 구조체 family로 보이며 16bit 필드를 만들지 않음 |

**즉 16bit 기록자는 2곳(`0x411ec0`, `0x48cba9`)뿐이다.** 관측이 "alive(tick10,231)에 `+0x688=10`
정상 → tick10,432 이전에 19,679"이므로 **생성 시 초기화(`0x411ec0`)만으로는 설명되지 않고**,
수명 중간 write(`0x48cba9`) 또는 변위-리터럴 스캔이 볼 수 없는 경로가 표적이다.

## 6. 신규 음성 결과 (W13의 오답 하나를 미리 제거)

"후보의 재배치 영역이 스탯표 `0x9B5238/0x9B5258`를 덮어써서 `+0x688`이 쓰레기가 됐다"는 자연스러운
가설을 **바이트로 배제**했다. `tail_relocation_storage_layout_v1.layout(4001)` 실측:

- `unit_pool` new `[0x108C000, 0x17B8658)`, `unit_existence`/`unit_age`는 그 위에 연접.
- 스탯표 `0x9B5238`(=10,179,640)은 재배치 new_start(17,350,656)보다 **아래**이고, 구 영역들의
  끝(`active_slot_list` 0x975D68 등)보다 **위**다 ⇒ **어느 재배치 영역과도 겹치지 않는다.**

⇒ W13은 이 경로를 다시 파지 않는다.

## 7. 살아있는 한계 (W13이 반드시 다뤄야 함)

- **변위-리터럴 스캔의 사각:** lap421의 P-E와 이번 §5의 P-G 둘 다 "`disp==0x688/0x692`인 명령"만
  본다. **다른 base 오프셋으로 같은 주소에 쓰는 경우**(예: base=unit+0x680, disp 0x8)나
  `memcpy`/`rep stos`류의 구조체 통째 복사는 **원리적으로 보이지 않는다**. `+0x692`는 §3의 유일해
  폐쇄형 재현이 있어 이 사각이 무의미하지만, **`+0x688`에는 그런 상쇄 증거가 아직 없다** —
  따라서 W13은 "기록자는 정확히 2곳"을 **단정하면 안 된다**.
- `+0x688=19,679`가 "오염"인지 "그 타입의 정상 스탯인데 소비 측이 못 견디는 것"인지는 **미결**.
  `0x411ec0`이 스탯표에서 그대로 복사하는 필드라는 §5 사실은 후자의 가능성을 **열어 둔다**
  (W13 판정식의 H3 분기). lap421/W13이 쓰는 "오염" 표현을 결론으로 굳히지 않는다.
- 이번 회차는 **게임 미실행**이므로 W13의 P-H(전이구간 dense 재실행)는 그대로 남아 있다.
