# 2026-09-15 G1 판정 정정 — 2× 출력은 고해상도 그림 경로가 아님

사용자는 차후 직접 제작한 고해상도 스프라이트를 교체하여 추가 디테일이 실제 1600×1200 화면에 남기를 기대한다. 기존 800×600 DxWrapper 정수2배 후보는 원본 구도·입력 확인에는 유효하지만 **G1 완성 경로로 승격하지 않는다.** 과거 이미지·입력 PASS 사실은 그대로 보존하고 합격 의미만 좁힌다.

- 동일 원본/후보 PS35 메뉴 캡처 비교: 원본 800×600 nearest2× 대 후보 1600×1200은 1,920,000/1,920,000 픽셀 exact/MAE0. Bilinear2×는 1,632,059/1,920,000 exact/MAE1.355. 후보 PS35와 PS3 각 프레임의 2×2 픽셀 480,000/480,000 블록이 모두 동일하다. 이는 **관측된 출력**이 픽셀 복제라는 증거이며, 게임의 모든 내부 렌더 표면 형상이나 모든 이미지 교체 규칙을 직접 측정한 것은 아니다.
- 2배 크기 원본 SPR를 넣으면 게임이 자동으로 축소한다는 단정은 아직 불가: 디코더·블릿·축척 규칙에 따라 화면에서 단순히 더 크게 보이거나 포맷 거부/클리핑될 수도 있다. 하지만 원래와 같은 상대 크기로 최종800×600 구도에 맞추면 그 단계에서 추가 픽셀 정보는 보존될 수 없고, 최종2× 확대가 이를 되살리지 못한다.
- 실제 G1 완료는 원본 구성/입력 그대로 **추가 디테일을 보존하는1600×1200 렌더 또는 후단 고해상도 합성**이 필요하다. 새 이미지 재제작은 사용자 후속 작업이므로 현재 블로커가 아니지만, 그 이미지를 온전히 표시할 렌더 경로는 현재 제품 요구다.
- 다음 좁은 조사: 원본이 실제 요청·잠금·블릿하는 DirectDraw 표면 크기 및 좌표 단위를 private read-only로 확인. 800×600 surface만 있으면 상위 해상도 표면 전환/후단 합성 경로를 각각 비용·호환성으로 빠르게 판정하고, 안전한 훅 근거 없이 숫자만1600으로 바꾸지 않는다.
