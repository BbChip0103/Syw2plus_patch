# 환경 하네스 범위와 제품 검증 경계

## 이번 환경 세팅의 완료 조건

1. 전체 게임 데이터의 전용 복사본과 파일 출처 기록. 원본/형제 저장소 무변경.
2. 전용 Wine prefix와 충돌 없는 Xvfb 화면. 다른 세션 재사용/전역 종료 없음.
3. 원본 EXE SHA 확인, 시작·화면 캡처·입력 전달·상태/메모리 관측의 짧은 스모크.
4. 실행 조건/후보 해시/지원 DLL/로그/스크린샷/종료 결과를 재현 가능한 경로로 기록.
5. 진단 DLL 빌드 도구와 read-only doctor, 증거 검사 CLI, 회귀 테스트.
6. 실제 개발 루프는 STOP/비활성 유지. 스모크 후 임시 실행 프로세스 정리.

전체 게임 복사본에 기존 wrapper/진단 DLL이 있다면 명시한다.
**원본 EXE가 그대로라는 것과 모든 로드 DLL까지 무수정이라는 것은 다르다.**
원본 실행 파일 검증과 화면의 제품 기준 승인도 별개다.

## 이후 기능 개발에서 채워야 하는 검증

| 목표 | 하네스가 제공할 기반 | 제품 완료에 추가로 필요한 것 |
|---|---|---|
| G1 | 화면/입력 캡처와 실행 해시 기록 | 같은 게임 상태의 800×600 대 1600×1200 화면 구성·좌표 비교, 사용자 확인 |
| G2 | 상태 trace 및 부하 증거의 기초 검사 | 실제 활성8명, 전비5000 생산/전투/재생산, 풀/시간/메모리, 저장/지원동기화, 연속24k/144k |
| G3 | 입력 증거의 관측 한계·누락 거부 | 16인 엔진/계측 확장 후 9~16 소유자·시야/저장/통신 실증 |
| G4 | 반복 실행·상태/화면 수집 기반 | 고정 지도/상황의 도착률·정체·경로비용 및 난이도 행동 비교 |

지금 16인 지원 코드나 AI 변경을 세팅으로 위장해 구현하지 않는다.
원본8개 플레이어 레코드/1200슬롯 계측으로 16인을 검증했다고 보고하지 않는다.
전비 cap=5000만으로 사용 전비5000이나 활성8인을 증명할 수 없다.
RSS 수치는 관측값이지 OOM 원인/무발생의 증명이 아니다.

## 증거 승격 금지

- mock → 실제 게임 검증으로 승격 금지.
- 메뉴 시작/입력 스모크 → 전투·멀티·장기 안정성으로 승격 금지.
- 기준 EXE 실행 → G1 후보1600×1200 승인으로 승격 금지.
- 포맷 검사 통과 → 의미적 제품 승인으로 승격 금지.
- 모델 CLI 존재/버전 확인 → 해당 계정의 모델 호출 성공으로 승격 금지.

새 스크린샷과 이미지 중간결과는 공유 `temp/Syw2plus_patch/` 아래에 두고 문서에는 경로/해시/측정 조건을 남긴다. 메인 레포는 PNG를 보관하지 않으며 과거 JSON 경로는 증거 보존을 위해 바꾸지 않는다.
`docs/baseline/golden/`은 사용자 승인 전 자동 갱신하지 않는다.
