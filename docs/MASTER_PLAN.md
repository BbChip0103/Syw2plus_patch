# 상위 계획 — G1~G4 원본 패치

2026-09-10 lap2, Codex gpt-6-astra / strategy. 역할 계약 effort=high.
상태: **Astra 상위 범위 확정, Sol 실행 카드화·사전 컨펌 대기**. 별도 컨펌 모델 호출 없음.
제품 계약은 DESIGN.md, 현재 실행 큐는 STATUS.md만 사용한다.
이 문서는 마일스톤 승인이나 구현 검증 결과가 아니다.

## 범위·우선순위

DESIGN의 M0→M1/G1→M2/G2→M3/G3→M4/G4→M5 순서를 유지한다.
M0 환경은 Sol/high 기술 검수 APPROVE 기록이 있고 G1 조사 착수에 필요한 격리 배관이 있다.
제품 마일스톤 사람 승인은 없지만, 이는 읽기·실행 기반 G1 조사 착수를 막지 않는다.
lap2의 유일 활성 목표는 G1이다. G2/G3/G4 병행 카드는 만들지 않는다.
Sol/high는 아래 확정 범위를 실행 카드로 구체화하고 사전 컨펌하며, Luna/high가 실행한다.
게임 코드 변경·새 의존성·엔진 재구현·자동 배포/서비스/커밋은 이번 계획 범위 밖이다.

## lap2 결정과 중단 조건

첫 실무 카드는 **G1-A 무패치 기준 장면·입력 효과·출력 경계 조사**로 고정한다.
원본SHA가 고정된 격리 복사본만 실행하며 EXE/DLL/게임 데이터는 변경하지 않는다.
관측 결과가 나오기 전에는 해상도 상수, QHD 후보, 래퍼 DLL 또는 입력 코드를 패치하지 않는다.

G1-A의 입력은 다음과 같다.

- 원본/격리 EXE SHA `b56986e018b43293be8d9945521d145bba8dbe4e49fe70c6b6488b8c9c08a8ac`.
- 격리 manifest `local/runtime/20260910_222434_2612938_0/manifest.json`을 복제해 만든 새 run.
- 전용32비트 Wine prefix, 충돌 없는 전용 Xvfb display, 화면은 최소1600×1200.
- 원본 메뉴 장면과 재현 가능한 실제 전투 장면 하나. 지도/세력/카메라/선택 대상/fixture를 기록한다.
- 입력은 메뉴, 유닛 선택, 드래그 선택, 미니맵 이동, 생산 각1회 이상이며 전후 효과를 기록한다.

G1-A PASS는 아래 산출물이 모두 있고 서로 같은 run/장면을 가리키는 경우다.

1. 원본800×600 content crop의 메뉴·전투 PNG와 SHA, 창/client 좌표 및 테두리 제외 규칙.
2. display surface의 width/height/pitch/bpp와 실제 로드된 EXE·DirectDraw 관련 모듈 SHA/경로.
3. 각 입력의 X11 좌표, 원본 content 좌표, 전후 상태값 또는 화면 효과와 기대 일치 판정.
4. `게임 렌더 surface → 표시/스케일 경계 → X11 content → 입력 역변환 → 게임 입력` 근거표.
5. 후속 최소 가역 probe 한 개의 변경 지점, old bytes/버전 거부/원복 방법 또는 불가능 근거.

다음 중 하나면 G1-A FAIL로 기록하고 패치 없이 Sol로 돌려보낸다: 전투 장면 재현 실패,
동일 장면/프레임 대조 불가, 실제 로드 모듈 불명, 입력 효과 미관측, 원본SHA 불일치,
원본/격리 경로 쓰기, 전용 prefix/display 미확보. 60~90분 또는 실패 가설2회에서 중단한다.

## G1 조사 방향과 선택 기준

가설: 원본800×600 렌더링을 보존하고 최종 출력과 입력을2배 대응시키는 경로가
원본 구도 유지 요구를 충족할 수 있다. 아직 구현 가능성이 확인된 사실은 아니다.
DESIGN의 정수2배 출력 허용과 QHD 반려 기록이 선택 근거다.

| 선택지 | 판단 / 재검토 조건 |
|---|---|
| 최종 출력2배와 입력 역변환 | 우선 조사. 실제 출력/입력 경계와 기존 DLL 경로 확인 후 채택 여부 결정 |
| 내부 렌더링1600×1200 및 UI 전체 수정 | 우선 경로의 불가능 근거가 있을 때 Astra 재계획. 고정 크기 버퍼 감사 필요 |
| 기존QHD 후보 재포장 | 원본 구도 요구 미충족으로 제외. 주소/실패 이력만 참고 |

analysis/memory_maps/original_qhd_probe_0910.md는 동일 원본SHA의 역사적 근거다.
행 테이블/렌더러 손상 이력이 있어 해상도 상수만 바꾸는 구현은 근거가 부족하다.
과거 스모크는 Wine builtin DirectDraw(ddraw=b),1024×768 가상 화면이었다.
창 크기 숫자만1600×1200으로 표시하는 것을 실제 출력 성공으로 세지 않는다.

## middle → work 인계 계약

Sol/high가 G1-A의 명령·산출 경로·좌표표 양식을 작업 카드로 구체화하고 사전 컨펌한다.
Luna/high는 승인 범위만 조사/구현하며 자기 결과를 최종 승인하지 않는다.

1. 과거 제목 화면2샘플과 QHD 캡처는 G1-A의 새 메뉴·전투 기준 장면을 대신하지 않는다.
2. Sol은 G1-A가 관측 전용임을 확인하고, fixture·입력 기대값·실패 시 정리/보존 경로를 고정한다.
3. G1-A 결과를 Sol이 독립 검토해 출력 경계를 하나 선택한 뒤에만 별도 G1-B 구현 카드를 만든다.
4. G1-B는 선택된 경로의 최소 가역 probe와 정상/버전거부/원복 검사를 포함한다.
   새 복사본만 패치하고 원본/후보/로드 모듈SHA, 범위·비중첩 검사를 기록한다.
5. 검토 입력: 변경 파일·명령·SHA·캡처·입력 trace·판정표·남은 위험.
   PNG는 지정 공유temp의 YYYYMMDD_HHMMSS_접두사 경로에 저장한다.

G1-B 합격식: content가 정확히1600×1200이고 기준800×600의 각 축 정수2배이며,
동일 camera/tile 범위·HUD/월드 상대 위치를 유지하고 잘림·왜곡·누락은0이다.
정적 기준점은 테두리를 제외한 기대 좌표 `candidate=2*original`에서 축별±1 candidate pixel 이내다.
선택/드래그/미니맵/메뉴/생산은 출력 content 좌표를 `floor(candidate/2)`로 역변환했을 때
G1-A의 같은 원본 입력과 동일한 상태 변화/화면 효과를 내야 한다. 동적 영역은 사전에 mask하고,
나머지 정적 영역은 선언한2배 scaler로 만든 기준과 비교한다. scaler·mask·허용 오차는 실행 전에
Sol이 고정하며 결과에 맞춰 완화하지 않는다.
1600×1200 이상 전용 가상 화면에서 전체 출력 캡처가 필요하다.
1080p 이하 물리 화면은 canonical 합격 환경이 아니다. 지원한다면 전체4:3 프레임의 compositor
축소 또는 명시적 실행 거부만 허용하며 crop/stretch를 허용하지 않는다. 이 정책은 별도 기록하고
가상 화면 성공을 물리1080p 사용성 성공으로 대신하지 않는다.

전비 합계는 객체 수가 아니다. G2 원인 분류 전에 풀 확대나 OOM 수리를 결정하지 않는다.
성능 예산과 G4 개선 최소 폭/반복수는 기준 측정 후 변경 시험 전에 Sol이 고정한다.
G3의16인×5000은 별도 부하 조건이며 자동 지원 선언하지 않는다.
생성/자원/상태 fixture와 치트 보정은 공개하고 정상 게임 경로의 후속 검증을 요구한다.

## 중단·승인

필수 게이트 예상 밖 실패, 구현 근거 충돌, 마일스톤 경계에서는 근거를 보존하고 승격한다.
실패 가설2회 또는 첫 조사60~90분이면 구체 blocker를 기록한다.
구현 무변경 streak≥2는 구현 진척이 아니다. 반복 계획 대신 첫 실무 산출물의
실제 기준 캡처/입력 효과/출력 경계 증거 유무로 진척을 판단한다.
Fast PASS는1단 일부다. 다음 새 Sol/Opus5 독립 검수와 APPROVALS의 사람 판단을
분리하며 skip/exit0/과거 결과를 승인으로 바꾸지 않는다.
