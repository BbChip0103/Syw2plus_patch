## 3. W44R B4 실패의 분류 (lap567 strategy)

1. **raw 재확인 결과는 lap566과 같다.** `save_load_result.json`(SHA `961e3e37…9fe`)에서 `pre_save.tick_fresh=16015`, `save_receipt.tick_before=16016`, `load_receipt 16017→16016`, `post_load.tick=16018`이다. lap564 C5 고정식 `post_load.tick < pre_save.tick_fresh`는 `16018 < 16015`이므로 거짓이다. 하네스 `w44_run.py:485-490`에는 이 비교가 없다. **B4 FAIL, lap565 자기 라벨 `STABLE_MIXED_24K`는 false positive다.** 기준을 사후에 완화하지 않는다.
2. **N208(신규, strategy 자기 정정):** lap564가 고정한 C5 식은 **구조적으로 참이 될 수 없다.** 저장은 `tick_fresh`를 읽은 뒤에 일어나므로 저장된 tick은 항상 `tick_fresh` 이상이다(16016 ≥ 16015). 로드 직후 tick은 저장된 tick 이상이다. 따라서 저장된 파일이 과거 상태를 복원해도 `post_load.tick < pre_save.tick_fresh`는 성립하지 않는다. 결함은 lap564 계약 식(strategy)과 하네스 누락(work) 두 곳에 있다. 제품 저장/로드 결함 증거는 없다.
3. **다만 lap561 원래 문구("로드 시 tick 역행 관측")로 읽어도 증거는 약하다.** 저장과 로드 사이가 1 tick(16016→16017)뿐이다. 그래서 풀·장부 일치는 "로드가 아무것도 안 했다"는 경우와 구별되지 않는다. 로드가 상태를 바꿨다는 직접 증거는 `load_receipt` 안의 1 tick 역행(16017→16016) 하나다. W21 Step2의 `1557→46`처럼 저장과 로드 사이에 긴 간격을 두어야 판별력이 생긴다.
