# W13 — `+0x688` 오염 write site 특정과 전이 tick 좁히기 (발행: lap421 work, 수행: 다음 work 회차)

- 발행자 / 역할: lap421 Claude Code `claude-sonnet-5` / high / work(실무, 자기 발행 — 카드 §3의
  "이 단계만으로 회차를 끝내지 않는다"에 따라 P-E+P-F를 이번 회차에 완주했고, 그 결과로 나온
  후속 표적을 이 카드로 넘긴다). 근거는 `docs/history/laps/20260921_lap421_work_g2_w12_pe_pf_move_input_root_cause.md`.
- 수행 역할: **work (Sonnet5/high)**. 정적 판별 1회 + dense 재실행 1회.
- 선행 상태: W12(H5 vs H6)는 **닫혔다** — H5 확정, H6 기각. `+0x692`의 폐쇄형 산술
  (`+0x688` 상수를 매 tick 더함, mod 65536, `>=50`이면 `-100`)이 관측된 이상값 전체
  {19579,−26278,−6599,0} 반복을 정확히 설명한다. 남은 질문은 "`+0x688` 자체가 왜 19679가
  됐는가"다.
- 목표 연결: G2 P2(원본 생산·AI 경로 안정성). `+0x688` write가 slot id(고 슬롯)에 의존하는
  계산이면 P2 회귀의 진짜 조건이 확정된다.

## 1. lap421이 확정한 것 (재조사 금지)

- 슬롯3565는 tick **10,231**에 alive 전이하며 `+0x688=10`(정상 소값)이었다.
- tick **10,432** 샘플(1초 간격 샘플, 정확한 전이 tick 아님)에서 `+0x688=19679`로 이미 바뀌어
  있었다. 이 구간 내내 `move(+0x692)=0`이었다 — 즉 이 write는 P-E가 찾은 `+0x692`의 두 site
  (`0x0040bc86~0x40bcfe` 누산기, `0x0040c1c2` 리셋) **어느 쪽도 아니다**(둘 다 `+0x692`만
  건드리고 `+0x688`은 건드리지 않음, `scan421_sites.json` 확인).
- tick11,915에 이 유닛이 실제로 움직이기 시작하면서 이미 나쁜 `+0x688`이 누산기에 소비돼
  `+0x692`가 첫 tick부터 범위 밖으로 나갔다. `+0x688` 오염이 먼저이고 `+0x692` 이상은 그
  **결과**다.

## 2. 수행 순서와 측정식

### P-G. 정적 판별 — `+0x688` 기록자 전수 (시간상자 30분, 게임 실행 없음)

`scan421_pe.py`를 재사용(`DISP=0x692`→`0x688`로 변경, 나머지 로직 동일)해 후보 `.text`에서
변위 `0x688`을 쓰는 store를 전수 열거한다. 원본과 후보 둘 다 스캔해 패치 유무와 무관한
사이트인지 확인한다(lap421의 `+0x692` 스캔은 원본·후보 동일이었다 — 이 필드도 그럴 가능성이
높지만 가정하지 않고 확인한다).

- 기록자를 전부 나열하고 각각의 호출자/문맥(진입 조건, 어떤 값을 쓰는지)을 `scan421_callers.py`
  방식으로 확인한다.
- 특히 값 `19679`(`0x4CDF`)나 그와 연산으로 이어지는 즉치/테이블을 우선 본다.

### P-H. 실행 probe — 전이 구간 dense 재실행 (이 회차의 실행 증거)

lap421 `movement_state_probe_pf.py`를 복사해 `DENSE_LO=10190`, `DENSE_HI=10450`(전이가
이 창 안에 있음, 여유 40 유지)로 바꾸고 **그 구간에서만** dense 샘플링한다(11,860~11,928
쪽은 이번 카드의 표적이 아니므로 normal cadence로 낮춰 비용을 줄인다). 슬롯3565의 전체
9필드 + `+0x688`을 매 tick 2회 이상 해상도로 기록해 정확한 전이 tick을 좁히고, 그 tick에
P-G가 찾은 site 중 어느 것이 실행되는지 대조한다(가능하면 워치포인트, 아니면 같은 tick에
호출되는 다른 관측 가능 신호와 교차 확인).

fixture는 lap421과 **동일**: op7 resource-only, 8 owner, N=4001, seed42, marked compat
`4331d9cd…`. 새 prefix/display.

### 판정식 (실행 전 고정)

- P-G가 기록자를 **정확히 1곳** 찾으면 그 site가 P-H의 전이 tick에 실행되는지만 확인한다.
- **2곳 이상이면** 어느 것이 실행되는지 좁히는 최소 수단(워치포인트/호출자 대조)을 같은
  회차에 붙인다(W12와 동일한 원칙).
- site가 **slot id를 입력으로 쓰는 계산**(예: `0x4B0`/`1200` 관련 상수, 또는 재배치 이후
  주소가 안 맞는 오래된 테이블 인덱싱)이면 P2 회귀의 구조적 원인으로 승격하고 다음 카드는
  그 계산을 바이트로 확정한다. slot id와 무관하고 원본에도 동일하게 존재하면 **원본 고유
  엣지 케이스(H3)** 로 분류하고 그 경로(어떤 명령/상황이 `+0x688=19679`를 정상적으로
  만드는지, 예: 아주 먼 목적지좌표 차이의 결과일 수도 있음)를 바이트로 확인한다.
- **정정 의무:** "high slot 전용"이라고 근거 없이 단정하지 않는다 — P-G/P-H가 slot 의존성을
  직접 보여주지 않으면 UNKNOWN으로 남긴다.

### 9.1 선행 상태 승인 (§7이 "닫혔다"고 적은 것의 독립 확인)

lap421 W12를 원시 산출물 + **독립 디스어셈블러(objdump)** 로 재계산해 **ACCEPT(불일치 0)** 했다.
추가로 lap421이 유보했던 부분을 닫았다 — `0x40bc86` 블록을 명령 단위로 시뮬레이션하고 signed16
전 범위를 브루트포스한 결과, 관측 시퀀스를 재현하는 `bp`는 **0 하나뿐**이고 가산값은 **19,679
하나뿐**이며, lap421이 유도하지 못한 네 번째 걸음 **−6599→0은 `0x40bca0`의 clamp store**로
설명된다. 전이 **4/4**가 유일해로 닫혔다. ⇒ H5 확정·H6 기각은 **강화된 상태로 유효**하고,
§4가 요청한 "저슬롯 대조군 대체"도 **승인(ACCEPT)** 한다.

### 9.2 **P-G(§2 정적 판별)는 lap422가 이미 완료했다 — work는 재실행하지 말 것**

변위 `0x688` 접근 **7건**, 원본 vs 후보 **IDENTICAL**:

- read 4곳: `0x40bc00`/`0x40bc19`/`0x40bc30`(`mov 0x688(%esi),%di` = 누산기 가산값 로드), `0x40c0b2`.
- write 3곳 중 **16bit 기록자는 2곳뿐**:
  - `0x411ec0` `mov %dx,0x688(%ebp)` — 직전이 `mov 0x9b5258(%eax),%dx`인 **유닛타입 스탯표 복사**
    (생성/초기화 성격).
  - `0x48cba9` `mov %dx,0x688(%esi)` — **수명 중간 write**, 직후 `cmp $0x46,0x8d(%esi)` 타입 분기.
  - `0x4c582c` `movl $0xb02c,0x688(%ebx)`는 32bit 상수라 16bit 관측값을 만들지 않는다.

관측은 "alive(tick10,231)에 `+0x688=10` 정상 → tick10,432 이전에 19,679"이므로 **생성 시 초기화만으로는
설명되지 않는다**. 따라서 **이 카드의 실질 표적은 `0x48cba9`(및 §9.4의 사각)** 이다.

### 9.3 배제된 가설 (다시 파지 말 것)

"재배치 영역이 스탯표 `0x9B5238/0x9B5258`를 덮어썼다" → **바이트로 배제**.
`layout(4001)` 실측상 `unit_pool` new `[0x108C000,0x17B8658)`이고 스탯표 `0x9B5238`은 그 아래·구
영역들 끝 위라 **어느 재배치 영역과도 겹치지 않는다**.

### 9.4 §2 판정식 정정 (work는 이 정정을 따른다)

§2 판정식은 "P-G가 1곳/2곳 이상"으로 갈리지만, **"둘 다 아님"을 반드시 살아있는 선택지로 둔다.**
변위-리터럴 스캔은 **다른 base 오프셋으로 같은 주소에 쓰는 명령**(예: base=unit+0x680, disp 0x8)과
`memcpy`/`rep stos`류 **구조체 통째 복사**를 원리적으로 볼 수 없다. `+0x692`는 §9.1의 유일해
폐쇄형 재현이 그 사각을 상쇄하지만 **`+0x688`에는 아직 상쇄 증거가 없다**. 따라서:

- P-H에서 전이 tick이 좁혀졌는데 `0x48cba9`도 `0x411ec0`도 실행되지 않으면, 그것은 실패가 아니라
  **"변위-리터럴 밖 경로" 라는 결과**다. 그 경우 다음 표적은 슬롯3565 struct 주변의 쓰기
  (인접 필드 동시 변화 여부)로 전환하고, 추측 수리 없이 근거를 올린다.
- 또한 `+0x688=19,679`를 **"오염"으로 단정하지 않는다** — `0x411ec0`이 스탯표에서 그대로 복사하는
  필드이므로 "그 타입의 정상 스탯인데 소비 측(누산기)이 못 견딘다"(§2 판정식의 H3 분기)가
  여전히 열려 있다. slot 의존성이 직접 보이지 않으면 UNKNOWN으로 남긴다(§2 정정 의무와 동일).

### 9.5 이번 카드의 남은 범위

§5(검사)·§6(산출물)·§7(중단 조건)은 그대로 유효하다.
