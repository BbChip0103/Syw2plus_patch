# G2 strategy — S1 fixture 구성 판정: 허용목록에 bit 0x4 전투 타입 1종 추가 (lap526)

- 발행: lap526 strategy (Claude Code `claude-opus-5-5` / high, INBOX 2026-09-23 strategy 모델 교체 지시), 2026-09-23 KST.
- 입력: `loop/ESCALATE_SOL` §82(lap525 middle 회부), `analysis/memory_maps/g2_unit_attack_domain_flags_1d8_lap525.md`(N181~N183),
  `docs/work/active/G2_STRATEGY_Q8A_SEEDED_ACCEPTANCE_LAP522.md`(A1~A8·S0~S5), DESIGN §2 G2.
- 성격: 방향·기준 판정이다. 게임 실행 0, 제품 source·브리지·테스트 변경 0. 실행은 middle 카드 → work로 넘긴다.
  **G2 제품 합격도, 3단 마일스톤 승인도 아니다.** 사용자가 번복할 수 있다.
- 이 문서는 lap522 문서의 A8과 §5 "타입 허용목록 확장 금지" 한 항목만 개정한다. 나머지 A1~A7·S0~S5·J4(144k 사전 허가)는 그대로다.

## 0. 충돌 확인

- lap525가 원본 바이트로 보였다: 허용목록 {5,7,46}의 `+0x1D8`에는 bit 0x4가 없고, fixture의 모든 유닛은 `+0x1BC`==1이다.
  따라서 시딩 유닛은 op8로도, 자동공격으로도 아무것도 공격할 수 없다(N182).
- 이 사실은 lap522 §3 A2(owner마다 전투 사망 ≥20)와 A8·§5(허용목록 {5,7,46} 고정)를 동시에 지킬 수 없게 만든다.
  lap522 §2의 전제 "무교전 원인 = order 발부 공백"은 기하에 대해서는 맞지만 구성(타입 능력) 원인을 빠뜨렸다. **strategy 쪽 결함이다.**
- 참고 저장소 §20 원본 라이브 실측(28타입)으로 다시 확인했다: bit 0x10(`+0x1BC`=2) 보유 타입은 0종이다.
  그래서 type5의 bit 0x400(2군 공격)은 이 fixture에서 쓸 곳이 없다. 추가한 전투 타입이 모든 유닛을 때릴 수 있고, 같은 전투 타입끼리는 서로 때릴 수 있다.

## 1. 판정

### K1 — (나) 채택: bit 0x4 전투 타입 X 1종을 허용목록에 추가한다
- 이유:
  1. DESIGN G2는 "8명이 **전투**·생산·사망·재생산", "저전비 다수/**고전비 군대**/건물 혼합"을 요구한다. 현재 {5,7,46}에는 공격 가능한 군대가 없다.
  2. 확장은 기준 **강화**다. 허용목록에 X를 **추가**할 뿐 5·7·46은 그대로 남는다. 가드는 하나도 풀지 않는다.
  3. 선례가 있다. lap463이 같은 방식으로 {5,7}→{5,7,46}을 확장했다(lap461 카드 §6-1: Place→Gate→Spawn과 매 개체 장부 검증을 유지한 채 집합만 넓힘).
- (가) 기각: type110 편측 사냥은 결과가 미리 정해진다. owner당 2기(총 16기)가 공격하므로 "8명 전투"가 아니다. A2를 "피격 사망"으로 재정의하면 기준 완화다.
- (다) 기각: S0는 `FEASIBLE`이고 S1을 막는 기술 blocker가 없다. W26은 N141 정지 생존이다. 지금 제출하면 lap522 J1의 "움직이는 상태에서의 안정"이 비어 있다.

### K2 — 사용자 승인은 필요 없다 (통지만, 번복 가능)
- 허용목록은 사용자가 정한 것이 아니다. 모델이 정한 하네스 핀이다(lap461 middle 카드, lap463 확장, 테스트 `test_g2_runtime_bridge_fixture_type_allowlist_pin.py`).
- 사용자는 Q8=(ㄱ)에서 "자원/**유닛 주입**" 시딩을 허용했다. 어느 타입을 주입할지는 fixture 선택이다.
- INBOX 상시 규칙 "실제 구현 선택이 목표·안전·배포 범위를 바꿀 때만 새 질문을 추가한다"에 따라 판단했다. 이 변경은 셋 중 어느 것도 바꾸지 않으므로 새 질문을 만들지 않는다.
- AGENTS "안전 pin 변경은 원인과 승인 기록을 남긴다": **이 문서와 `ESCALATE_SOL` §83이 그 승인 기록이다.** 핀 테스트는 자동 갱신이 아니라 이 기록을 인용해 {5,7,46,X}로 바꾼다.

### K3 — X 선택 규칙 (지금 고정, middle은 강화만 가능)
- 후보: 원본 §20 실측으로 bit 0x4를 가진 **기동 유닛** {2,3,4,10,12,13}.
  - 제외 42·63: `+0x1D8` bit 0x2 계열(46·47과 같은 건물 계열)로 보인다. 고정 포대라서 "움직이는 상태" 증거를 약하게 만든다.
  - 제외 110·111: 시작 유닛이다(owner당 2기, 111은 특수 bit `0x20000000`). 사망이 owner 패배 같은 부수효과를 내는지 모른다. 110은 이미 비시딩으로 존재하므로 공격자로 남아도 된다.
- 적격 조건(전부 원본 타입 행을 읽기 전용으로 확인, fail-closed):
  1. 행 `+0x4C` bit 0x4 = 1(§20 값과 일치해야 한다).
  2. op5 가드 그대로 통과: 행 `+0x24`&14 == 0, 1 ≤ 폭·높이(`+0x16/+0x18`) ≤ 8.
  3. 비용(행 `+0x10`) ≥ 1. A1 [4900,5000] 조합이 산술적으로 가능해야 한다.
- 선택: 적격 후보 중 **비용이 가장 낮은 것**(같은 수의 전비로 더 많은 공격자·사망·슬롯 재사용), 동률이면 **타입 번호가 작은 것**.
- 적격 후보가 0이면 `ARM_FAIL`로 끝낸다. 가드를 풀거나 다른 후보군으로 넓히지 않고 strategy에 회부한다.
- 행 값은 middle이 참고 저장소 정적 자료로 먼저 답해도 된다. 확정할 수 없으면 S1 실행 첫 단계의 읽기 전용 preflight에서 같은 규칙으로 판정한다. 규칙은 바꾸지 않는다.

### K5 — A2 계측 보강 (강화)
- 전투 사망은 두 경로로 나눠 센다. **op8 스크립트 명령으로 생긴 사망**과 **명령 없이 생긴 사망(자연 자동공격)**이다. 둘 다 D_o에 넣되 비율을 보고한다.
  - 자연 자동공격이 X로 생기면 스크립트 입력 의존이 줄었다는 근거가 된다. 0이면 그대로 적는다.
- op8 대상 선정은 middle이 **고정된 결정적 규칙**으로 정한다(예: owner o → owner (o+1) mod 8의 가장 가까운 유닛). G4 AI 개선으로 포장하지 않는다.
- §82 middle 요구 두 가지를 기준으로 올린다: 표본마다 8 owner `(used, reserved, count)`와 `live`를 **원시로 저장**한다. A5에 **`used<0` 검사**를 넣는다(W35 F4 공백).

### K6 — 유지하는 금지 (변경 없음)
- AI/생산/건설 로직 패치 금지. op4 금지. `(flags&14)` 가드와 폭·높이 가드 완화 금지. Place→Gate→Spawn 순서와 매 개체 장부 검증 유지.
- 허용목록 확장은 **X 1종만** 허가한다. 두 번째 타입 추가는 다시 strategy 판정이 필요하다.

### K7 — streak 판정 (PROMPT ③)
- lap525(middle 문서)가 1회, 이 회차가 2회째 무증가다. S1 카드 발행이 필요하므로 세 번째 문서 회차가 생긴다.
- **strategy 판정: G2 트랙을 계속한다.** S0가 재배치 슬롯에서 원본 명령 경로의 수락·피해·사망을 실제로 보였고, 남은 장애는 fixture 구성 하나로 좁혀졌기 때문이다.
- 허가는 **middle S1 카드 발행 1회**뿐이다. X 선택을 정적 자료로 확정하는 일은 그 회차 안에서 끝낸다. 별도 회차로 만들지 않는다.
- 그다음 work 회차는 반드시 S1 게임 실행으로 끝나야 한다. 게임 실행 없이 끝나면 더 쌓지 말고 STOP하고 사용자에게 보고한다.

## 2. 순서 (갱신)

1. **middle(Opus5.5):** S1 카드(W36) 1장을 발행한다.
   - K3 규칙으로 X를 정한다. 확정하지 못하면 preflight 절차를 카드에 고정한다.
   - 브리지 허용목록 {5,7,46}→{5,7,46,X}(한 조건항)와 핀 테스트 개정을 지시한다. 둘 다 이 문서를 인용한다.

3. **middle:** 원시만으로 재계산해 독립 검수한다. `ACCEPT`이고 라벨이 `DRIVEN_CYCLE_STABLE`이면 lap522 J4대로 144k 카드 1장을 바로 발행한다.
