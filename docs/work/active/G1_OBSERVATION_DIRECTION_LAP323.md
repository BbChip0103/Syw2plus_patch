## 결정: §14.7 제출 형태의 실행 허가 REJECT

입력: G1_RUNTIME_CONTRACT_MIDDLE_LAP284.md §13~§14, lap322 기록·인계,
DESIGN §1~§4, APPROVALS 2026-09-12 01:03의 bounded repair→fresh validation 허가.
관측 대상 두 전역값을 구성 시점에 읽자는 목적은 유지한다. 그러나 runtime 예산만 바꾸면
나머지 금지를 모두 유지할 수 있다는 실행 주장은 입증되지 않았다.

1. §14.7은 runtime 예산 변경을 요청하면서 원본 재실행·하네스 수정·입력을 모두 금지한다.
   새 격리 전체 복사본/prefix/display에서 어떤 실행 파일을 어떤 진입점으로 시작해
   0x4D6312까지 도달하는지 명시하지 않았다. 기존 세션에 붙는 것은 안전 규칙 위반이다.
   이것은 실행 불가능성의 증명이 아니라 **허가 가능한 실행 경로의 근거 부재**다.
2. 입력 0으로 대화상자 구성에 도달한다는 증거가 없다. 타이틀 시점 전역값 또는 임의 polling을
   구성 시점 값으로 바꾸면 안 된다. 1회 관측은 해당 run·호출 문맥에만 유효하며 모든 로드
   경로의 결정성·클릭 hitbox·로드 성공을 증명하지 않는다.
3. §14.0/§14.7의 “runtime 예산 요청 없음”과 같은 절의 예산 변경 요청은 문서상 충돌한다.
   제품 쌍 예산과 별도 연구 관측 예산을 분리해서 다시 선언해야 한다.

따라서 이번 예산은 runtime/게임/Wine/Xvfb/Stage B/입력 모두 0으로 유지한다.
정적 CFG 반복 재개, 추측 클릭, 다른 세션 접속으로 우회하지 않는다. N4 수리·W3 재pin은 보류.
G1~G4·S1 기존 판정과 모든 미결을 보존한다. 마일스톤 종료/이동 없음.

## middle 인계: 실행 경로의 양립성 판정 한 건

새 middle이 다음 표를 문서로 채우고 ACCEPT-WITH-REVISION 또는 BLOCKED로 판정한다.
실무 구현·유료 후속 세션 자동 시작은 이 인계에 포함하지 않는다.

| 항목 | 필요한 근거와 수용 기준 |
|---|---|
| 격리 시작 | 입력 EXE SHA·복사 출처·새 run/prefix/display·시작 명령 후보·소유 PID 확인/종료 경계. 개인 원본 경로 실행 금지 |
| 도달과 계측 | 시작→0x4D6312 도달의 근거 파일/주소·필요 이벤트·해당 읽기 시점 증명 방법. polling만으로 exact-site 주장 금지. breakpoint 등 변경이 필요하면 원본 코드 수정 여부와 별도 승인을 명시 |
| 변경할 금지 | runtime·새 격리 복사본 실행·입력·연구 하네스 준비를 각각 유지/변경 필요로 선언. 기존 허가와의 관계 및 근거를 쓰고 “한 줄만 변경” 추정 금지 |
| 예산·보존 | 최대 1 fresh run, 총 90초 이내 준비/관측/수집/종료 예산을 미측정 가정으로 명시. 도달 실패/timeout/수집 실패에도 run ID·SHA·PID·시간·오류·원시 값/미관측 사유 보존. 자동 연장·재시도 금지 |
| 판정 | exact-site 800×600→해당 호출 A, 640×480→해당 호출 B, 다른 값→A/B 폐기, 미도달/시점 미증명→UNKNOWN. 제품 evidence·PASS 소비 경로와 파일 분리 |
| work 경계 | 수정할 연구용 파일·함수·검증 파일 후보와 합성 실패 검사 명시. 허가 미확정 상태에서는 구현/실행 카드 0 |

어떤 항목도 입증할 수 없으면 필요한 권한/실험과 구체 blocker를 반환한다. 구현 근거가 충돌하면
더 조사하거나 수리로 밀어붙이지 말고 증거를 보존한다. 새 봉투의 실제 실행은 middle 검토와
필요한 범위 결정 뒤 별도 Luna/Sonnet5/high work, 이어서 새 middle 독립 검수로 분리한다.
§14.1 fixture 반증은 보류 가능한 별도 연구안이며 이 바퀴의 두 번째 활성 카드로 열지 않는다.
동일 정적 수치 반복이나 문서 작성량을 구현 진전으로 집계하지 않는다.
