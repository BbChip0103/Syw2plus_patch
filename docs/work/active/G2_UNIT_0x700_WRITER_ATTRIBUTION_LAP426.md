# W15 — `unit+0x700` 오염 주체 귀속 (발행: lap426 middle, 수행: 다음 work 회차)

- 발행자 / 역할: lap426 Claude Code `claude-opus-5` / high / **middle(검수·중간계획)**.
  근거 `docs/history/laps/20260921_lap426_middle_g2_w14_pi_independent_review.md`.
- 수행 역할: **work (Sonnet5/high)**. 실행 probe 1회(읽기 2개 추가) + 정적 평가.
- 선행 상태: **W14는 CLOSED**. lap425 P-I 판정 **(B) `+0x700`(K) 자체가 표적**을 lap426이
  원시 457표본으로 독립 재계산해 **ACCEPT**했다. 이 카드는 그 한 단계 위, **누가 썼는가**다.
- 목표 연결: G2 P2(원본 생산·AI 경로 안정성). fault `0x00414133` 인과 사슬 최상류 확정.

## 1. lap426이 확정한 것 (재조사 금지)

- 전이는 슬롯3565 단일 변화점이다: `s363 tick10400 K=0` → `s364 tick10400 K=22432`,
  이후 tick10528까지 22432 고정. 같은 표본에서 `K`만 바뀌고, 다음 표본에서 `m`·`f688`만 바뀐다
  ⇒ 인과 방향 `K → m(+0x68c) → f688(+0x688)`은 관측으로 닫혔다.
- `base`는 슬롯3565 생존 152표본 전부 10, `(type,owner)=(76,4)` 불변 ⇒ **(A) 배제**.
- ref 슬롯3562(owner4) 148표본 전부 `K=0`/`base=9`/`f688=9` 불변, 저대역 anomaly 0
  ⇒ 슬롯3565 **국소** 현상.
- probe 읽기 주소는 명령 바이트와 일치한다(lap426 V7): `[0x669c7c+140*K]`,
  `[0x9b5258+916*type]`. **스탯표 필드는 `0x9b5258`이다** — `0x9b5228`은 같은 916B 레코드의
  선두 주소(`0x48cad8 lea`)이지 이 체인의 입력이 아니다.
- **`+0x700`의 정당 상한은 `< 3759`다(코드 유도, 추정 아님).** `0x40d79f`가 `[esi+0x388]`을
  `+0x700`에 복사하고, 같은 인덱스가 `0x959a8c + 2*(index + 3759*owner)`의 owner별 WORD 카운터를
  `inc`(`0x40d72b`)/`dec`(`0x40f038`)한다. owner당 3,759 엔트리이므로 그 이상은 이웃 owner 침범이다.
  `K=22432`는 상한의 **5.97배**.
- **표 밖 읽기 착지점 확정:** `0x669c7c+140*22432 = 0x9687FC`, 주기 필드 `0x968808`,
  카운터 write `0x96BF44` — 셋 다 핀된 bulk 라이브 상태 blob **`[0x892410, 0x975D8C)`** 내부
  (blob 오프셋 `0xD63EC`). 즉 살아있는 게임 상태를 보정표로 읽고 있다.
- **주기 게이트는 범인이 아니다.** `0x48c8b1`의 `ds:0x8924b8 % [0x669c88+140*K] == 0` →
  `0x48c8c2 call 0x413cb0(1)`에서 `0x413cb0`은 `[ecx+0xb4] += arg; clamp to [ecx+0x120]; ret 4`로
  `+0x700`을 쓰지 않는다. **이 경로를 다시 파지 않는다.**

## 2. 이 카드가 **전제하지 않는** 것 (중요)

lap425의 다음-단계 제안("`+0x700` 비상수 write **4곳 중** tick10400 실행분 특정")은
**전제를 좁혔다**. `scan424_700.py`는 `.text`에서 *변위 리터럴 0x700 + 베이스 레지스터* 형태만
매칭하므로 다음을 구조적으로 못 본다:

- (a) 다른 객체/배열이 넘쳐 `unit+0x700`에 **우연히 착지하는 OOB write**
- (b) 변위가 다른 인덱스형 write `[reg + reg*scale + other_disp]`
- (c) `rep stos` / `memcpy` 계열 블록 write

G2 회귀의 현행 유력 가설이 **잔존 1200-bound site의 풀 밖 write**(lap414 확인, 최소 3곳)인 이상
(a)는 배제 대상이 아니라 **1순위 용의자**다. 따라서 이 카드는 "4곳 중 하나"를 가정하지 않고
**먼저 정당/외부를 가른다**.

## 3. 수행 순서와 측정식

### P-J. 정당 write vs 외부 write 판별 (이 회차의 유일한 실행 증거)

lap425 `movement_state_probe_pi.py`를 복사해 **읽기 2개만 추가**한다. 새 창을 넓히지 않는다
(`DENSE_LO=10380`, `DENSE_HI=10420`, `STOP_TICK=10500` 그대로).

슬롯3565와 ref 슬롯 양쪽에 매 표본 추가 기록:

1. `src = DWORD [unit+0x388]` — `0x40d79f`가 `+0x700`에 복사하는 원본 값.
2. `sib = DWORD [unit+0x6fc]` — `+0x700` 바로 앞 DWORD. `0x413103`이 `+0x6fc`를, `0x413120`이
   `+0x700`을 같은 패턴으로 쓰므로 둘은 같은 배열의 이웃 슬롯이다. **블록/OOB write는 이웃을
   함께 더럽히고 단일 필드 store는 그러지 않는다** — 가설 (c)의 저비용 판별자다.

추가로 이번 run은 **재현 확인이 목적의 절반**이다. `K=22432`라는 **값 자체**는 아직 1회 관측이다.

### 판정식 (실행 전 고정)

- **(J1) 정당 site.** 전이 표본에서 `src == 22432`(또는 `src`가 같은 tick에 22432가 됐다)
  ⇒ `0x40d79f`/`0x40f040`가 **정상적으로** 동작했고 오염은 그 **입력 `[unit+0x388]`**에 있다.
  다음 표적은 `+0x388`의 write site 정적 인벤토리다. `+0x700` 4곳 추적은 중단한다.
- **(J2) 외부 write.** `src`가 정상(0 또는 `< 3759`)인데 `+0x700`만 22432
  ⇒ 그 4곳이 쓴 것이 **아니다**. §2 (a)/(b)/(c)가 살아난다. 다음 표적은 잔존 1200-bound site
  전수(lap414 최소 3곳)를 `unit+0x700` 착지 가능성으로 **정적** 평가하는 것이다.
  후보 풀 베이스 `0x0108C000` + `3565*0x758`이 어떤 stock 경계 산술의 사거리에 드는지 계산한다.
- **(J3) 블록 오염.** `sib(+0x6fc)`도 같은 표본에 함께 비정상 ⇒ 단일 store가 아니라 블록
  write/구조체 복사. (J2)의 (c)로 좁힌다.
- **(J4) 값 비재현.** 이번 run에서 `K`가 22432가 **아닌** 다른 값으로 튀거나 전혀 안 튄다
  ⇒ 값은 비결정적이고 **주소만 결정적**이라는 뜻이다. 이는 (J2)를 강하게 지지한다(정당 site는
  게임 상태에서 온 값을 쓰므로 같은 fixture에서 같은 값이 나올 개연성이 높다). 판정을 그대로
  기록하고 "값 비결정" 사실을 새 근거로 올린다. **측정 실패로 세지 않는다.**
- 어느 갈래든 **추측 수리 금지**. 이 회차는 계측과 정적 평가만 한다.

### 실패 예산

실패 가설 2회 또는 60분 안에 `FEASIBLE`/`NOT_FEASIBLE`/`BLOCKED`로 판정한다.
run이 전이 구간을 못 잡으면 **동일 파라미터로 1회만** 재시도하고, 두 번째도 실패하면 BLOCKED로
보고한다(창을 넓히거나 새 가설을 즉석에서 추가하지 않는다).
