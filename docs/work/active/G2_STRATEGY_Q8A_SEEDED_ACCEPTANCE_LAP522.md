- 발행: lap522 strategy (Claude Code `claude-opus-5-5` / high, INBOX 2026-09-23 strategy 모델 교체 지시), 2026-09-23 KST.
- 입력: INBOX 2026-09-23 18:43 사용자 **Q8 = (ㄱ) 목표 재정의**, `loop/ESCALATE_SOL` §79(lap521 STOP), DESIGN §2 G2.
- 성격: 방향·범위·검증 기준 문서다. 게임 코드·바이너리·브리지 변경 0, 게임 실행 0. 실행은 middle 카드 → work로 넘긴다.
  **이 문서는 G2 제품 합격도, 3단 마일스톤 승인도 아니다.** 사용자가 번복할 수 있다.

## 0. 입력 대조 — 라벨 충돌과 처리

- 사용자 응답은 내용을 풀어 썼다: "AI 자연 도달 대신 **시딩(자원/유닛 주입) 기반 cap 5000 근접 + 안정 동작 증거**".
- 문서상 "(ㄱ)" 라벨은 두 뜻으로 적혀 있었다. §67(iii)은 lap460 시딩 축 인정, §69 §5·§79는 창 연장(≳200k)이다.
- 사용자가 쓴 내용은 전자와 같다. **라벨이 아니라 내용을 따른다.** 창 연장은 선택되지 않았다.
- 명시 불변: AI 건설/생산 로직 무변경((ㄴ) 미선택), W34 미발행, Q9·Q7-B·"8인" 정의 미결.

## 1. 재정의가 바꾸는 것 / 바꾸지 않는 것

**바뀌는 것 (사용자 결정):**
- "8 owner가 각각 cap 5000에 접근/도달"은 **명시된 gate-legal 시딩**으로 만들어도 된다.
  수단은 op5/op6(원본 Place `0x42ECB0` → Gate `0x43EDA0` → Spawn `0x443190`)과 op7(자원만)이다.
- `NATURAL_ARRIVAL_ARITH_INFEASIBLE`(lap508)·N141·트랙② 결론은 **더 이상 G2를 막지 않는다.** 근거로 보존만 한다.

**바뀌지 않는 것 (DESIGN §2 G2 원문, 사용자가 축소하지 않음 — 모델도 축소하지 않는다):**
- 8명이 cap 근처에서 **전투·생산·사망·재생산**한다. 혼합 구성(저전비 다수/고전비/건물)을 쓴다.
- 무결성(장부·풀·ID), 메모리/시간 계측, 같은 후보의 24k와 144k, 저장/로드, 지원 멀티 동기화가 필요하다.
- 1단 기계 → 2단 독립 검수 → 3단 사용자 판단 순서다. op4(장부 직접 write) 금지 핀 3종도 유지한다.

**strategy 해석 (사용자 번복 가능):** "안정 동작"은 **상태가 움직이는 동안의 안정**을 뜻한다.
W26 144k는 cap 근접을 유지했지만 N141대로 "정지 상태 생존"이었다. 그래서 W26만으로는 이 기준을 채우지 못한다.
W26은 A1·A5의 144k 부분 증거로 계속 쓴다(Q7-B 제출 가능성은 사용자 몫).

## 2. 핵심 레버 — 원본 target-order 경로로 교전을 "명시 입력"한다

- 교전이 없던 이유는 fixture 기하가 아니다(N87, 셀 단위로 섞였는데도 24k 동안 소실 4기).
  AI가 idle 유닛에 명령을 내지 않는 것이 원인이다(G4 2026-09-16 probe: pathfinder 고장이 아니라 order 발부 공백).
- 원본 고수준 명령 함수 `FUN_00415480`(경로 `0x415480→0x4AEE10→0x4AED20→0x40FF90→0x412540→0x40C640`)가 실측됐다.
  pending order를 정상 경로로 승격시켜 **실제 이동과 target HP 500→0**을 만들었다
  (`docs/history/laps/20260916_g4_original_order_issuer_probe.md`, `ORIGINAL_ORDER_PATH_MOVEMENT_PASS`).
- **판정:** 시딩한 8 owner 군대끼리 이 원본 경로로 공격 명령을 걸어 교전을 만든다. 이것은 **테스트 입력(fixture)** 이다.
  - AI 코드·생산 정책·EXE를 바꾸지 않는다. 그래서 (ㄴ)이 아니다.
  - 원본 명령을 우회하지 않으므로 DESIGN "원본 명령 우회 성공 부족" 조항에도 걸리지 않는다.
  - 산출물에는 항상 "시딩 + 스크립트 교전 입력"이라고 적는다.
- **G4 probe의 한계를 그대로 물려받는다.** 그 호출은 worker thread에서 했고 동시성 안전은 입증되지 않았다.
  G2 하네스는 **main thread**(`supply_probe_poll`, window thread 검사가 이미 있음)에서만 호출한다.
  함수 첫 12바이트 `53 56 8B F1 57 8A 86 1C 03 00 00 84`를 fail-closed로 확인한다.
- **사용자 번복 조건:** 사용자가 스크립트 교전 입력을 (ㄱ) 범위 밖으로 보면 이 트랙은 멈춘다.
  그러면 G2 "동작" 증거는 W26(정지 생존)이 상한이다. 남는 길은 Q7-B 제출 또는 (ㄴ)뿐이다.

## 4. 단계 순서와 게이트

- **S0 가능성 (work 1회 또는 60분, 먼저 닿는 쪽):** 브리지에 진단 전용 op(예: op8 target-order)를 추가한다.
  시딩 fixture에서 owner a 유닛 → owner b 유닛 공격 1건으로 HP 감소나 사망을 보인다.
  - 같은 실행에서 8 owner 상호 적대 상태를 **읽기만** 해 기록한다. 이것이 N87 무교전의 대안 설명이다.
  - 결론은 `FEASIBLE` / `NOT_FEASIBLE` / `BLOCKED` 중 하나다. 실패 가설 2회면 멈추고 보고한다.
- **S1 24k 교전 순환 soak:** S0가 `FEASIBLE`이면 다음 work 회차에 곧바로 착수한다. A1~A8을 쓴다. 게임 1회, foreground 동기 완주.
- **S2 144k (발행 금지 재판정 결과):** **지금은 발행하지 않는다.**
  S1 원시에 대한 middle 독립 검수가 `ACCEPT`이고 라벨이 `DRIVEN_CYCLE_STABLE`이면, 같은 후보의 144k 카드 1장 발행을 **미리 허가한다**.
  그때는 strategy 재판정이 필요 없다. 그 밖의 라벨이면 144k는 닫힌 채로 strategy에 회부한다.
- **S3 동일 후보 통합:** F4(B) 32-bit 장부 후보(`1893ff50…`)를 포함할지는 Q9에 달렸다.
  Q9가 "실행 허용"이면 S1을 결합 후보로 한 번 더 돈다. 아니면 F4는 정적·단위 증거까지만이라고 제출문에 적는다.
- **S4 멀티 동기화:** DESIGN 조건으로 남아 있다. "8인이 사람인지 AI인지" 답이 올 때까지 일정에 넣지 않는다. 3단 제출문에 미충족으로 명시한다.
- **S5 3단 제출:** S1(+S2) 결과, W26, 미충족 항목(S3/S4)을 APPROVALS 제출 양식으로 올린다. 판정은 사용자만 한다.

## 5. 후보·fixture·경계

- 후보: W21/W26 계보 `a10024de…`(N=4001, supply5000)를 권고한다.
  - 144k 기준선이 이미 이 후보에 있다. 핀을 복사하지 말고 현재 source에서 다시 빌드해 SHA를 확인한다(N53).
  - middle이 다른 후보를 고르면 이유를 카드에 적는다.
- 원본 SHA `b56986e0…c9c08a8ac` 불변 확인, 새 복사본만 쓴다. 격리 prefix/display를 쓰고 다른 세션 Xvfb는 건드리지 않는다.
- 브리지 op 추가는 **진단 하네스 변경**이다. 제품 EXE 바이트 변경이 아니다. 하네스 테스트에 새 op의 fail-closed 검사를 넣는다.
- 금지:
  - AI/생산/건설 로직 패치.
  - op4. 타입 허용목록 확장. `(flags&14)` 가드 완화.
  - 명령 대상 선정을 G4 AI 개선으로 포장하는 것.
- PROMPT ③ 무증가 streak: 이 문서 회차가 2회째다(runtime implementation-unchanged-streak=1 → 2).
  - strategy는 **middle 카드 발행 1회차만** 문서 회차로 허가한다.
  - 그다음 회차는 반드시 S0 **실제 게임 실행**이어야 한다. S0 전에 추가 계획 회차를 쌓지 않는다.
