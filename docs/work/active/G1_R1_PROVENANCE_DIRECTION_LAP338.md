# lap338 Astra — 검수 원문 보존과 현재 검증 분리 결정

2026-09-12 / lap338 / Codex gpt-6-astra / Astra major direction.
이번 호출은 사용자 지정 상위 계획 세션이다. 게임·하네스·테스트 구현을 하지 않는다.
입력 메시지 lap=337과 달리 읽은 `loop/.lap_counter`는 338이므로 PROMPT에 따라 338을 사용했다.

## 1. 범위와 판단 근거

G1/M1 유지. 후보 R1 관측까지의 기존 방향과 lap334 봉투·lap337 R-a/R-b 범위를 유지한다.
이번 변경은 lap336/337 승격 질문 세 가지에 대한 보존 정책 하나다.
독립 확인: lap337 probe failures=[] 및 stdout SHA256
`c38a73f1220faf992155bc5a98fe814e9e8ded316b0935e5eb3f22f0738cdf46` 일치.
후보 artifact 0, 원본 artifact 1, R-a 세 이름 테스트 미존재, R-b `launch_started` 결합도 재확인했다.
이름 리터럴 검사는 실제 경로 사용 전체를 증명하지 않으며 middle이 회귀 잠금의 충분성을 검수한다.
lap332/334의 실패 분해는 lap337 기록을 근거로 인용한다. 이번에 두 실패 probe를 재실행했다고 주장하지 않는다.
lap331 검수 당시 소스 원문은 이번 세션에서 확보되지 않았다. 복구 가능성을 단정하지 않으며
현재 원문으로 과거 실행 원문 동일성을 증명할 수 없다는 한계를 유지한다.

## 2. Astra 결정

1. **재pin 불허.** lap332/334 probe와 기대 SHA, 과거 PASS/FAIL, lap331 artifact를 그대로 보존한다.
   두 probe 전체를 폐기하거나 현재 PASS로 바꾸지 않는다. 과거 SHA에 결합된 동일성 단언은
   역사적 검수 전용으로 분류한다. 현재 파일을 넣어 얻는 rc1은 그대로 FAIL 기록이다.
   이 분류는 현재 필수 게이트의 실패를 무시할 허가가 아니다. middle이 아래 분리 기준을 확인하기
   전에는 기존 검증 의무를 제거하지 않는다. W3도 재pin 불허이며 별도 미결로 남긴다.
2. **편집 전 원문 보존 필수.** 검수된 소스의 다음 편집 전에 work가 해당 소스와 결합된 테스트·probe의
   정확한 바이트를 새로운 `docs/history/laps/snapshots/lapN_pre_edit/`에 보존한다.
   기존 경로를 덮어쓰지 않는다. manifest에 원래 상대경로·SHA256·바이트 수·수집 시각·lap·역할·검수
   문서·적용 범위와 실제 의존 파일을 기록한다. 소스 텍스트만 대상이며 EXE/DLL/게임 데이터/save/자격 증명은 제외한다.
   지금 보존한 원문은 lap338 이후 비교용이다. 이를 lap330 실행 원문으로 표시하지 않는다.
   실행 직전에는 middle이 승인한 소스 묶음과 실제 실행 소스의 SHA를 다시 대조한다.
3. **결합 probe 영향표 필수.** middle은 편집 대상별로 과거 probe·가변 소스 SHA 단언·불변 artifact
   단언·현행 계약 단언을 식별한다. 재실행 결과와 실패 이유를 표로 남긴다. 역사적 probe를 편집하지
   않고 별도 현재 계약 검사를 정의한다. 과거 identity는 원문이 없으면 UNKNOWN, artifact 내부 정합성과
   현행 계약은 각각 별도 판정한다. UNKNOWN을 PASS로 합치거나 종합 exit0으로 가리지 않는다.
   새 검사에서 중복되는 계약은 기존 lap336/337 probe와 회귀 테스트를 재사용한다.

## 3. Middle handoff — 구현 전 보존 기준의 좁은 검수

새 middle(Sol/Opus5 high)이 이 결정과 lap337 §5의 합치 여부만 먼저 검수한다.
산출물은 영향표와 work용 파일 목록·스냅샷 manifest 요건·필수 명령·실패 분류가 있는 짧은 보완 봉투다.
입력 소스 기준은 runtime_env SHA `922a267c27f51fe47d7db69962dadbfdbbded9ff04c6350e8cb7a4c44f8a2575`,
테스트 SHA `c04a6265229f7e37cb9d4434f0e150c76e1e56d26f0e1c990cb938a06d769823`이다.
PASS 조건: 기존 pin 변경 0, 모든 실패 단언의 적용 범위 명시, 과거 identity UNKNOWN 보존,
현재 계약 검사 누락 0, 편집 전 원문 복원 가능성의 바이트/SHA 확인 절차 명시, 실행 예산 0.
FAIL/중단: 실패 원인이 SHA 드리프트 외로 확대되거나 필수 검증이 예상 밖으로 실패하면
현재 결과를 보존하고 ESCALATE_SOL로 반환한다. 과거 실행 소스를 역추정해 인증하지 않는다.
문서상 MODEL_ROUTING의 Opus5 선택과 상위 AGENTS의 Sol/Opus 허용 차이는 유지하며 이 결정으로
provider 설정을 변경하지 않는다. 실제 호출 모델/effort를 기록하고 대체 호출하지 않는다.

## 4. Work handoff — 승인된 작은 수리로 복귀

middle의 보완 봉투 뒤 work(Luna/Sonnet5 high)는 먼저 원문/manifest를 보존하고 SHA를 대조한다.
그다음 lap337 §5대로 R-b 인자 한 곳 + R-a/R-b 오프라인 회귀 잠금만 수행한다.
추가 프로덕션 변경·새 공통 추상화·과거 probe 수정은 0. make check와 safety 및 지정 현재 계약 검사를
수행하고 정확한 테스트 수·소스 전후 SHA·diff·실패 전량을 기록한다. 다음 새 middle만 기술 컨펌한다.
이 문서는 수리 완료/계획 검수 통과/후보 실행 허가가 아니다. 후보 1 run은 기존의 수리 후 독립 검수
조건을 모두 충족할 때만 발효한다. 수리 시 준비 40초 결합을 유지하되 설치 비용이나 시간 여유는
실측 전 UNKNOWN이다(lap337의 “예산 압박 없음” 추론을 실행 증거로 쓰지 않는다).

## 5. 우선순위와 중단 기준

추가 Astra 서술 반복보다 보존 절차를 확정한 뒤 R-a/R-b의 측정 가능한 코드·회귀 변경으로 복귀한다.
중간 검수에서 새로운 근거 충돌이 없으면 같은 상위 계획을 다시 작성할 필요가 없다.
M1 종료/다음 마일스톤 이동·Stage B·제품 승인은 0, 후보 실행 예산 0, G2~G4 확대 0.
ESCALATE_SOL 원문을 소비/삭제하지 않고 결정과 남은 middle 검수 의무를 부록으로 연결한다.
