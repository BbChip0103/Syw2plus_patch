# lap297 Astra — S1 연구 게이트 재계획

2026-09-12 / Codex gpt-6-astra / high / major direction/master-plan.
이 문서는 상위 범위 결정이다. middle 기술 수용·실행 허가·제품 승인이 아니다.
현재 큐는 STATUS에만 둔다. 게임 코드·검사 코드·PASS 규칙은 수정하지 않는다.

## 입력과 한 가지 가설

입력: DESIGN §1~4, APPROVALS 2026-09-12 01:03, lap283 상위 결정,
lap284 middle §0/3/4/5/8, lap296 middle §4.7 및 해당 probe/report.
가설: 연구 관측과 제품 판정을 분리하면 tick 오차를 알기 위해 먼저 tick 오차를
요구하는 순환을 끊고, 하네스 정비 반복을 실제 load 경로 준비로 되돌릴 수 있다.
성공 측정: middle이 아래 세 결정을 각각 ACCEPT/REJECT로 판정하고, 실행 봉투의
결측마다 정확한 근거·담당 역할·검증 조건을 붙일 수 있음. 프로세스 exit0은 수용이 아니다.
실패 측정: 제품 PASS 완화, 기존 미결 삭제, 좌표/오차 추측 또는 실행 예산 자동 발생.

## 상위 결정 세 가지 (M1 유지)

1. **tick report-only를 연구 계약에 채택한다.** lap284 §4 제안대로 향후 원본↔원본
   연구 쌍에서 각 load 사건·snapshot·before/after tick·delta·관측 시각·관측 출처를
   원시값으로 기록한다. 결측은 UNKNOWN, rewind 전후 tick 누적은 금지다. tick 허용오차를
   연구의 실행 전 입력에서 제외한다는 점만 lap283 표의 tick 항목을 대체한다.
   제품 S1의 (A)+(B), 동일 사건 대조 및 실제 상태 일치 조건은 유지한다. 관측 쌍 하나로
   제품 오차를 확정하지 않는다. 연구 결과를 본 새 middle의 제안과 상위 재결이 필요하다.
2. **load 연구는 별도 evidence 종류로 설계한다.** 기존 PS5→PS3 endpoint와
   producer/comparator/overall PASS를 확장하거나 우회해 연구 성공을 표시하지 않는다.
   별도 연구 기록은 fixture SHA, 실제 입력, 관측 PS 전이, 원시 상태, 실패 단계,
   timeout/flush/종료 결과를 담고 제품 evidence 소비 경로에 유입되지 않아야 한다.
   lap284의 PS9→PS35→PS3는 조사 가설이며 실제 관측 전 CONFIRMED로 쓰지 않는다.
   구현 함수·파일·스키마·거부 검사는 middle이 확정하고 work가 별도 세션에서 구현한다.
3. **fixture 후보는 save000/save006을 유지한다.** save011/012는 역사적 정적 대조
   자료로만 남긴다. save000 선호는 잠정이며 정확한 SHA와 활성 구성, load 선택 절차를
   근거로 middle이 하나를 확정한다. 파일 크기·정적 모델만으로 실제 로드 성공을 쓰지 않는다.

## 예산과 우선순위 경계

현재 게임/Wine/Xvfb/원본 재실행/Stage B 집행 예산은 모두 0이다. 사용자 bounded repair
허가는 유효하나 미충족 기술 게이트를 면제하지 않는다. 본 결정은 M1 마감이나 M2 전환이 아니다.
load UI 좌표·선택 절차의 근거가 없으면 추측 구현하지 않는다. middle은 기존 로컬 캡처의
SHA·환경·화면 근거로 확인 가능한지 판정한다. 자료가 없으면 **구체 연구 blocker**와 최소
단일 관측 봉투 제안을 상위로 반환한다. 관측 허가를 받은 것처럼 실행하지 않는다.
원본↔원본 각 1회 연구 쌍은 lap283의 조건부 수량일 뿐이며 아직 실행할 수 없다.

lap296 §4.7.6의 두 scrape 가드 인계는 철회하지 않는다. middle의 인계 패키지 안에 그대로
보존하며 work 실행 시 그 bounded repair를 먼저 끝내고 새 middle이 검수한다.
W2(a)(b)(c), reader 폭 사각, legacy 창 정비를 load 연구 준비의 추가 선행조건으로
확대하지 않는다. 실제 필수 게이트가 실패하면 원인·실패를 보존하고 승격한다.
이미 확인된 W2 mutant의 0바이트 실패는 예상된 잠복 결함으로 남긴다.
이 바퀴도 구현 진척 0이다. 반복 정비를 제품 진척으로 세지 않으며, 다음 중간 산출물은
새 문서 계보를 늘리는 대신 정확한 수정 대상/테스트 또는 부재 근거를 확정해야 한다.

## middle → work handoff 계약

middle 새 세션은 게임 실행·구현 없이 다음 표를 하나의 실행 가능한 패키지로 판정한다.

| 항목 | 필수 산출물 / 수용 기준 |
|---|---|
| 위 세 결정 | 각각 ACCEPT/REJECT와 이유. 거부하면 추정 수리 없이 상위 반환 |
| fixture·UI | 정확한 경로/SHA/활성 구성과 선택 입력의 출처. 부재는 UNKNOWN과 자료 검색 범위 |
| 연구 하네스 | 수정 대상 함수/별도 기록 위치/명령 설계 및 기존 제품 소비 경로와 분리되는 검사 |
| tick | 허용오차 없는 원시 필드/사건 순서/결측/rewind 처리; 제품 PASS에 미사용 |
| 실행 봉투 | 원본·fixture·하네스 SHA, 새 전체 복사본/prefix/display, run별·전체 시간 제한, 실제 명령, 수집/flush, 자기 PID만 종료, PS35 이후 PS3 미도달 기록 |
| 안전·회귀 | fixture 누락/해시 불일치 거부, 랜덤 새 게임 대체 거부, 기록 결측 보존, 기존 endpoint/PASS 불변, 보호 해시/원복 및 fresh Fast 확인 |

work(Luna/high 또는 Sonnet5/high)는 middle이 수용한 단일 범위만 새 세션에서 수행한다.
실무 결과는 그 다음 새 middle이 독립 검수한다. runtime 예산은 완성된 봉투와 근거를
상위에 제출해 별도 결정받는다. 이 세션에서는 하위 세션·유료 CLI를 실행하지 않는다.

## 중단 및 보존

load 입력·봉투의 구현 근거가 아직 불명확하므로 사용자 지시대로 ESCALATE_SOL로 인계한다.
최신 사용자 지시의 Sol 승격 명칭을 따른다. MODEL_ROUTING의 현재 middle=Opus5 전용과
차이가 있으므로 표식 생성은 provider 변경/실제 호출/폴백을 뜻하지 않는다.
G1 카드 종결 REJECT, R17/R6-B-R2/WM_CLOSE 및 G2~G4 미결을 유지한다.
검증 수치와 변경 SHA는 lap297 이력에 기록한다.
