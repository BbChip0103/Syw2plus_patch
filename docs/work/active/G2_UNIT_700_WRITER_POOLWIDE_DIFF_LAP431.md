## 1. lap431이 확정한 것 (재조사 금지)

- **측정은 재현된다.** 슬롯3565 창 `+0x6e0..+0x71c`의 전이는 `s353(t10399) → s354(t10400)`,
  인덱스 **6·7·8**(`+0x6f8`/`+0x6fc`/`+0x700`)이 `0 → {17, 16538, 22432}`. 양 옆 `+0x6f4`(idx5)·
  `+0x704`(idx9) 불변. `win[8]==K`·`win[7]==sib`가 **438표본 전부 일치**(교차검증 불일치 0),
  `src(+0x388)`는 **438표본 전부 0**(⇒ (J2) 외부 write가 이 run에서도 성립). `m`·`f688`은 `s355`
  (여전히 tick10400)에 변하고 `(10+347349) mod 65536 = 19679` 산술 일치. band anomaly 0,
  가드-스킵 84건 = `s354..s437` 정확 일치(K=22432 > 3758과 내부 정합).
- **창은 슬롯 전체를 한 번에 읽은 같은 버퍼에서 나온다.** probe는 `read(pid, POOL_BASE+slot*0x758,
  0x758)` **1회**로 `u`를 얻고 창·K·sib·src를 전부 그 `u`에서 언팩한다 ⇒ **표본 내부**에서는
  세 필드가 한 스냅샷이다. N40이 지적한 "필드 간 20.3ms" 문제는 **표본 내부에는 적용되지 않는다.**
- **대조 슬롯 3562의 창은 "전부 0"이 아니다(lap431 정정 C1).** 129표본 내내
  `[0]*11 + [0xFFFFFFFF] + [0]*4` 이며 **변화 0회**다. 정확하고 더 강한 서술은 "3562의 창이
  3565의 **전이 직전 창과 바이트 동일**하고 끝까지 불변"이다.
- **창 변화점은 2개이고, 앞의 1개는 오염이 아니다(lap431 정정 C2).** `s305/t10233`의
  `+0x70c 0→0xFFFFFFFF`는 슬롯3565가 **살아나는 바로 그 표본**이며(alive `s305..s437`, 133표본)
  대조 3562도 같은 `-1`을 갖는다 ⇒ **스폰 초기화**다. 카드 판정식의 "창이 처음 바뀌는 표본"을
  문자 그대로 읽으면 `s305`를 가리키므로, 앞으로 전이 sample을 고를 때 **스폰 표본을 먼저 배제**한다.
- **언롤 루프 배제는 이제 3중이다.** `0x4130e6`/`0x413103`/`0x413120`/`0x41313a` 네 site의
  명령 바이트(`89 ae f8/fc/00/04 06/06/07/07 00 00`)를 lap431이 **원본·후보 양쪽에서 직접 확인**
  했고 둘은 **바이트 동일**하다(`va - 0x400000 = 파일 오프셋` 규약도 이로써 재확인). 이 루프는
  모든 필드에 같은 `ebp`를 쓰는데 관측은 (i) 세 값이 서로 다르고 (ii) `+0x704`가 **불변**이다
  ⇒ 배제. lap428 N41보다 근거가 하나 더 늘었다.
- **P-L 0건은 7개 인코딩으로 확장됐다.** 3DWORD·2DWORD 2종·3WORD·2WORD·big-endian 2종 전부
  핀된 `original.bin`/`candidate.bin`에서 **0건**(탐색기 정상성은 대조 패턴 80건으로 확인).

## 2. 이 카드가 표적으로 삼는 것

**(K2) "블록 복사"는 확정이 아니라 SUPPORTED다(N44).** 이유는 N40과 **같은 계열의 결함**이다 —
W16 판정식이 고정한 "n>=3 연속 ⇒ 블록 복사"의 분해능은 **명령 1개가 아니라 tick 1개**
(`10399→10400`)다. 같은 tick 안에서 **별칭(aliased) 구조체의 인접 멤버 3개에 필드 단위로 각각
대입**해도 관측 서명이 정확히 같고, 그 경우 인덱스는 **연속**이므로 카드가 "구조체 필드 단위
대입"에 배정한 (K3) 산발 갈래로 가지 않고 (K2)로 들어온다 ⇒ **(K2)와 (K3)은 서로소가 아니었다.**

확정된 것(후퇴가 아니라 정밀화): 연속 12바이트 `[+0x6f8, +0x704)`가 **한 tick 안에** 서로 다른
비균일 값 3개로 쓰였고 양옆은 깨끗하다. 이는 균일 채우기(`rep stos`)와 위 언롤 루프를 배제한다.

문자 그대로의 블록 복사에 **불리한** 새 음성 증거 2건:
- P-L이 7개 인코딩에서 0건 ⇒ 값열이 정적 이미지 어디에도 없다.
- **N45:** 후보의 `rep movsd`(`f3 a5`) **567 site 중 앞 16바이트 안에 `mov ecx,3`이 있는 것은 0건**
  (`mov ecx,3` 즉치 자체는 26건). `ecx`가 동적 계산일 수 있으므로 **반증은 아니지만**, 12바이트
  복사의 정적 후보가 하나도 없다.
- 값 3개가 **의미적으로 이질적**이다 — `17`은 작은 id/개수처럼, `16538`/`22432`는 좌표쌍처럼
  읽힌다. 균질한 blob 복사보다 **필드 단위 주문/목표 write**에 더 부합한다(가설일 뿐, 미검증).

**따라서 STATUS가 제안한 "런타임 메모리 스캔으로 복사원 특정"을 그대로 다음 카드로 삼지 않는다.**
그 단계는 **블록 복사가 확정이라는 전제 위에서만** 의미가 있다. 필드 단위 write라면 12바이트
원본은 애초에 어디에도 연속으로 존재하지 않으므로 스캔은 0건을 내고 한 회차가 통째로 소모된다 —
PROMPT ③이 금지하는 "같은 추측 반복"이다.

**대신 값이 아니라 *주체의 인덱싱*을 잰다.** 어느 해석이 참이든 결론이 나오고, 값 스캔보다 싸다.

## 3. 수행 순서와 측정식

### P-M. 풀 전역 창 diff (이 회차의 유일한 실행 증거)

lap430 `movement_state_probe_pk.py`를 복사해 **읽기 범위만 넓힌다.** 새 가설을 추가하지 않는다.
`DENSE_LO=10380`, `DENSE_HI=10420`, `STOP_TICK=10500`, fixture(op7 resource-only, 8 owner,
N=4001, seed42), 새 prefix/빈 display **전부 그대로**.

1. **dense 구간에서만** 풀 전체를 1회 read로 떠서(`POOL_BASE`, `4001*0x758 = 7,521,880B`)
   슬롯마다 창 바이트 `[0x6e0, 0x720)` **64B만** 잘라 직전 표본과 비교한다.
2. 출력은 **diff 목록만** 남긴다: `{sample, tick, slot, idx, old, new}`. 전체 스냅샷을 디스크에
   쓰지 않는다(lap429 디스크 blocker 준수 — 이 창은 관측상 조용하므로 목록은 작아야 한다).
3. 기존 슬롯3565/ref 단일 기록(창·K·sib·src·m·f688·band)은 **그대로 유지**한다(회귀 앵커).
4. dense 밖에서는 기존 동작 그대로(풀 전역 read 하지 않음).

### rider. bulk blob 값열 탐색 (같은 회차, P-M과 함께)

전이 직전/직후 표본(`tick 10399`·`10400`)에서 bulk 라이브 blob `[0x892410, 0x975D8C)`
(약 932KB)를 **각 1회** 떠서 `§1`의 7개 인코딩으로 값열을 탐색한다. STATUS가 한 회차짜리로
제안했던 스캔을 **이 카드 안의 값싼 곁가지로** 흡수한다. 스냅샷 2개는 보관하지 말고 히트
목록(오프셋·인코딩)만 남긴다.

### 판정식 (실행 전 고정 — 갈래는 서로소여야 한다)

전이 tick(`10400`)에서 창이 바뀐 **슬롯 집합 S**로 가른다. 스폰 표본(`alive` false→true)에서
생긴 `+0x70c = -1` 변화는 **집합에서 제외**한다(§1 C2).

- **(L1) 루프형.** `|S| >= 2`이고 슬롯 인덱스 차분이 **일정하거나 작은 집합**이다 ⇒ 범인은 잘못된
  bound/base를 가진 **순회 루프**다. `stride`, `min(S)`, `max(S)`, 3565가 처음/끝/중간 중 어디인지,
  그리고 각 슬롯의 값열이 같은지 다른지를 기록한다. ⇒ 다음 카드는 **수리 카드**(루프 bound).
- **(L2) 단발형.** `S == {3565}` ⇒ 순회 루프 계열은 **소거**된다. 범인은 손상된 포인터/인덱스의
  일회성 write다. ⇒ 다음 카드는 포인터 출처를 표적으로 하며, rider 결과가 값 스캔이 성립하는지를
  가른다.
- **(L3) 창이 조용하지 않다.** dense 구간에서 이 창이 **많은 슬롯에서 상시** 바뀐다 ⇒ "3565가
  이상하다"는 W14~W16의 전제 자체가 약해진다. **수리로 넘어가기 전에 base rate를 먼저 보고한다.**
- **(L4) 전이 비재현.** 동일 파라미터로 **1회만** 재시도하고, 두 번째도 실패하면 `BLOCKED`로
  보고한다(창을 넓히거나 가설을 즉석 추가하지 않는다).

**정직성 조항:** (L1)/(L2)도 **tick 1개 분해능**이다. 결과를 "명령 단위 귀속"으로 쓰지 않는다.
그렇게 쓰려면 별도 수단(write watchpoint 등)이 필요하며 그것은 이 카드 밖이다.

### 실패 예산

실패 가설 2회 또는 60분 안에 `FEASIBLE`/`NOT_FEASIBLE`/`BLOCKED`로 판정한다.

### 9-A. (L1)과 (L3)을 서로소로 만든다 (판정식 수리, 실행 전 고정)

§3의 갈래는 **서로소가 아니다** — 둘 다 `|S| >= 2`를 허용하는데 문턱이 없다. 전이 tick에
stride 4로 300슬롯이 바뀌면 (L1)과 (L3) 양쪽에 해당한다. 또 (L1)의 조건이 "차분 일정" ∨
"작은 집합"의 OR이라 뒤쪽에서는 카드가 약속한 `stride`가 정의되지 않는다.

**두 축으로 순서를 정해 가른다. 실행 전에 이 정의를 고정하고, 실행 후에 바꾸지 않는다.**

- 축1 **base rate `B`** = dense 구간에서 **전이 tick을 제외한** 각 표본의 "창이 바뀐 슬롯 수"의
  중앙값(스폰 배제 후, 9-B 적용).
- 축2 **`|S|`** = 전이 tick(`10400`)에 창이 바뀐 슬롯 수(스폰 배제 후).

1. **(L3) 먼저 판정한다.** `B >= 1`이면 (L3) — 이 창은 애초에 조용하지 않다. `|S|`와 무관하게
   **수리로 넘어가지 말고 base rate를 먼저 보고한다**(§8 유지). 다른 갈래로 내려가지 않는다.
2. `B == 0`일 때만 아래로 내려간다.
   - **(L1a) 규칙적 루프형:** `|S| >= 2`이고 정렬한 `S`의 연속 차분이 **단일 값**이다
     ⇒ 그 값이 `stride`. `stride`·`min(S)`·`max(S)`·`S` 안에서 3565의 위치(처음/끝/중간)·
     각 슬롯의 값열 동일 여부를 기록한다. ⇒ 다음은 **수리 카드**(루프 bound).
   - **(L1b) 불규칙 소집합:** `2 <= |S| <= 8`인데 차분이 단일 값이 아니다 ⇒ `stride`는
     **없다**. 값열의 동일/상이와 `S` 전체를 그대로 기록하고 **stride를 지어내지 않는다.**
     ⇒ 다음 카드 판정은 middle이 한다.
   - **(L1c) 대집합:** `|S| > 8`이고 차분이 단일 값이 아니다 ⇒ (L3)과 같은 취급으로
     **보고 후 정지**한다.
   - **(L2) 단발형:** `|S| == 1`이고 그 원소가 3565다 ⇒ 순회 루프 계열 소거(§3 원문대로).
   - `|S| == 1`인데 원소가 **3565가 아니면** 전이 재현 실패로 보고한다(→ (L4) 절차).
3. **(L4)** 는 그대로: 전이 비재현이면 동일 파라미터로 **1회만** 재시도, 두 번째도 실패하면
   `BLOCKED`. 창을 넓히거나 가설을 즉석 추가하지 않는다.

§3의 정직성 조항(**tick 1개 분해능이므로 명령 단위 귀속으로 쓰지 않는다**)은 9-A에도 그대로 적용된다.

### 9-B. 스폰 배제를 **계산 가능하게** 만든다 (수집 항목 1개 추가)

§3은 C2에 따라 `alive` false→true 표본의 `+0x70c = -1` 변화를 `S`에서 빼라고 하지만, P-M은
슬롯당 **창 64B만** 자르므로 diff 항목에 `alive`가 없다 ⇒ **규칙을 적용할 수 없다.**
probe는 이미 매 표본 `read_existence(pid)`로 존재배열 전체를 읽고 있으므로 수리는 작다:

- diff 항목을 `{sample, tick, slot, idx, old, new, alive, alive_prev}`로 넓힌다
  (`alive`/`alive_prev`는 **이미 읽은** 존재배열에서 가져오고, 추가 `read`를 넣지 않는다).
- `alive_prev == False and alive == True`인 슬롯의 변화는 **스폰으로 분류해 `S`와 `B`에서 제외**
  하되, **목록에서 지우지는 않는다**(별도 `spawn_diffs`로 남긴다).

### 9-C. "band anomaly 0"을 이 카드의 국소성 근거로 **쓰지 않는다** (N46)

lap430/431이 보고한 `band anomaly 0`은 전이 구간을 **구조적으로 덮지 않는다.** lap432 실측:

- `BAND_SCAN_INTERVAL_S = 1.0`(벽시계) vs `DENSE_INTERVAL_S = 0.02` ⇒ dense 표본 **126개 중
  123개에 `band_scan`이 없다**(전체 438 중 124개 없음). 전이 이웃 `s347..s355`(tick 10395~10400)는
  **전부 없음**이고 재개는 `s356/t10402`다.
- `band_scan`은 `range(1, CAPACITY, 4)`로 **슬롯의 1/4만** 훑는다(3565는 포함, **대조 3562는 제외**).
- 읽는 것은 `MOVE_OFFSET=0x692`의 **2바이트 move 하나**이고 판정은 `|move|>100`이다 —
  **`[0x6e0,0x720)` 창은 한 번도 보지 않는다.**

⇒ "현상이 슬롯3565에 국한된다"를 지탱하는 것은 **대조 슬롯 3562 하나뿐**이다. 이는 P-M을
무효화하지 않고 **정당화**한다. 실무는 결과를 쓸 때 band 결과를 국소성 근거로 인용하지 말고,
**(L3)을 '먼 가능성'이 아니라 현재 전혀 배제되지 않은 갈래로 취급한다.**
