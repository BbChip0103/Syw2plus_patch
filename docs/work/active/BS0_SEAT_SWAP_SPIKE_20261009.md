## 판정: **FEASIBLE** (단일플레이, 런타임 메모리 쓰기 3개)

게임 중(ps3)에 아래 셋을 쓰면 사람이 좌석 k를 조종하고, 좌석 0은 컴퓨터가 이어서 조종하며, 좌석 k의 AI는 멈춘다.
패배 판정·크래시 없이 최대 186초(교체 뒤) 진행을 확인했다.

1. `[0xB63FC4]` (dword) = k — 로컬 좌석
2. `[0x956770 + 0*0x3ABC + 2]` (byte) = 1 — 좌석 0 `is_cpu`
3. `[0x956770 + k*0x3ABC + 2]` (byte) = 0 — 좌석 k `is_cpu`

공통 관측(b 런 전부):
- 교체 직후 HUD 자원·전비, 미니맵 틀(국가 장식), 시야(안개)가 좌석 k 기준으로 바뀐다. 좌석 0 기지는 좌석 k 시야 밖이면 안 보인다(캡처 `end_seat0`).
- 교체 전에 고른 좌석 0 유닛 선택은 남아 있지만 우클릭 명령은 적용되지 않았다(`stale_selection` 재지정 0, a·b 전부). 단 c(로컬 그대로)에서는 적용됨.
- 교체 뒤 좌석 0 시작 자리에서 드래그해도 좌석 0 유닛은 선택되지 않는다(`seat0_command` 선택 0).
- 좌석 0은 교체 전 사람 좌석이라 AI 초기화가 없었는데도 일꾼 운용·건설·생산을 바로 시작했다(별도 초기화 호출 불필요).
- (c): 로비 갱신 `0x4B7700`은 ps3에서 돌지 않는다(`[0xC0D0F4]` 5초 동안 미소비 → 0으로 복구). 게임 자체 경로로 local을 바꿀 수 없으므로 직접 쓰기 (a)/(b)가 필요하다.
  c에서는 사람과 AI가 같은 좌석 0을 동시에 조종해도 충돌·크래시는 없었다.

탐색 런(`explore1/`, 4인맵 3인)에서 (a)→(b)를 같은 게임에 차례로 적용해 약 4분 진행 뒤 좌석 2 AI의 공격으로 좌석 1(사람)이 밀려
ps 26→27→29 "패배했습니다"가 나왔다. 패배 타이머 `[0x975910]`이 설정돼 있었다(정상 패배 경로 `0x4448E0`). 당시 좌석 1의
판정 대상 유닛 수는 기록 전이라 **정상 패배인지 단정하지 않는다**(정식 프로브는 마지막 ps3 표본의 local `flags&0x4002` 유닛 수로 판별하며, 정식 5런은 모두 패배 없음).
G7 기록의 "local만 바꾸면 ps27"은 2611 정식 런(a, 75초)에서 재현되지 않았다.

## 찾은 주소

검증(2611 런타임): `0xB63FC4` 로컬 좌석 / `0x956770+s*0x3ABC+2` is_cpu(AI 켜기·끄기 스위치) / `0xB42D7C`·`0xB42D80` 카메라 중심 타일(쓰면 화면 이동) /
`0xB3DE58+i*0x338`(x)·`+4`(y) 좌석 i 시작 타일(본진 HQ 위치와 일치, 매 게임 난수) / 선택 개수 `0x899024`·entries `0x1604004`.

정적(2611 역어셈블): 로비 행 6바이트 → 플레이어 구조체 복사 `0x41BAD2..0x41BB0A`(행 +2 = is_cpu) / is_cpu 읽기 36곳 /
승패 `0x4C4040`→`0x4C4200`: 패배 = owner==local 이고 `flags(+0x1D8)&0x4002` 인 살아 있는 유닛 0(`0x4448E0`, 타이머 `0x975910`),
승리 = local과 다른 팀(`+5`) 그런 유닛 0(`0x444770`, 타이머 `0x97590C`), 2초 뒤 ps 24/26 / 맵 시작 목록 `0xB42D38`(개수 `0xB42D78`) → `0x42FB50` 셔플.

추정: 시계방향 = 타일 좌표(y 아래로 증가)에서 시작 자리 중심 기준 `atan2` 증가 순(아이소메트릭 변환이 방향을 보존한다고 가정, 미니맵 대조 미실시).
4인맵 시작 4곳 기준 순서는 (12,26)→(103,12)→(117,103)→(24,117)(화면 위→오른쪽→아래→왼쪽).

## 남은 위험 / 미확인

- 승패는 local 좌석 기준이다. 회전 직후 넘겨받은 기지가 이미 `flags&0x4002` 유닛 0이면 2초 뒤 바로 패배한다(규칙 설계 필요: 전멸 좌석은 회전에서 제외 등).
- 승리 조건 "상대 유닛 전멸"은 원래 판정(다른 팀의 `0x4002` 유닛 0)과 같다. 팀 byte(+5)는 좌석에 남으므로 회전해도 팀은 좌석 기준.
- 부대지정(F1~F11)·선택·건설 예약·화면 위치는 회전 때 정리 필요(이번 런은 stale 선택이 명령을 받지 않음만 확인).
- 컴퓨터 자원 보너스(AI 좌석 쌀이 수천씩 뛰는 현상)가 is_cpu를 따라가는지 정량 미확인.
- 저장/불러오기: 세이브의 플레이어 블록(`0x892410` 고정 블록)에 is_cpu가 들어가므로 회전 상태는 저장되지만 local은 G7 경로를 따른다(미시험).
- 멀티플레이: local은 기계마다 다르고 is_cpu 변경이 동기화돼야 함 — 범위 밖.

## 다음 단계 제안 (DLL 타이머 훅으로 N분마다 시계방향 회전)

1. 훅 지점: 게임 tick(`[0x8924B8]`, 약 20 tick/초)을 보는 `_inmm.dll` 브리지 타이머 또는 EXE tick 경로(`0x41C8C0` 부근) cave. 단일플레이(`[0x4ED848]==1`)·ps3에서만.
2. 회전 계산: 게임 시작 때 `0xB3DE58+i*0x338`으로 활성 좌석의 시작 타일을 읽어 시계방향 순서를 고정(`clockwise_order`/`rotation_map` 순수 함수 그대로 이식).
3. N분마다: 사람 좌석 h → 다음 좌석 n. `is_cpu[h]=1`, `is_cpu[n]=0`, `[0xB63FC4]=n`, 선택 개수 0, 카메라 = n 시작 타일(또는 n의 HQ).
   컴퓨터끼리의 "회전"은 조종 주체가 모두 AI라 바꿀 것이 없다(사람 1명 = local 1개만 이동).
4. 회전 대상에서 이미 판정 대상 유닛 0인 좌석 제외, 회전 직후 승패 타이머(`0x97590C`/`0x975910`) 상태 확인.
5. 검증: 이 프로브에 `--rotate-every` 반복 모드를 더해 3~4회 회전·각 60초, 그 뒤 저장/불러오기 1회.
