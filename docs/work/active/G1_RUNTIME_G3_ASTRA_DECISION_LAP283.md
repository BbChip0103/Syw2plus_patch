# lap283 Astra — G1 runtime 연구와 G3 저장 경계 결정

2026-09-12. Codex gpt-6-astra / high, major direction/master-plan.
상위 범위 결정 문서다. middle 승인·실행 검증·제품 마일스톤 승인이 아니다.
현재 다음 작업의 유일한 큐는 `docs/STATUS.md`다. 아래는 실행을 위한 조건부 handoff 계약이다.

## 요구와 결정

1. M1/G1 유지. 원본 구도·입력의 1600×1200 검증을 먼저 성립시킨다.
   G2~G4 착수나 마일스톤 마감은 하지 않는다(`docs/DESIGN.md` §1~4).
2. 저장 fixture 경로를 유지한다. 여섯 항목의 정적 복원 근거는 수용됐지만 두 실행의
   관측값 동일성은 아직 없다(`G1_S1_MIDDLE_ACCEPTANCE_LAP277.md` §4.2~4.3).
   같은 정적 오프셋을 다시 조사하는 반복보다 **저장 fixture를 적용하는 실제 하네스 경로**가
   다음 측정 가능한 변경이다. 무작위 새 게임을 저장 복원의 대용으로 쓰지 않는다.
3. **현재 집행 예산은 0**. 준비 후 요청할 최소 runtime 연구는 새 격리 원본 복사본
   두 개에 동일 save를 적용하는 **원본↔원본 1쌍(각 1회)**이다. 후보 실행/Stage B가 아니다.
   원본 입력 디렉터리 자체 실행은 항상 금지다. 한 run 실패를 다른 save나 추가 run으로
   자동 대체하지 않는다. 이 최소안의 수량은 정했지만 실행 허가는 발급하지 않았다.
4. **Stage B 예산 0 유지**. 원본↔원본 연구를 통해 S1/F2-R2 실제 근거를 얻고 새 middle이
   독립 수용한 뒤에만 원본↔후보 exact-once/fresh 요청을 별도 재결한다.
   기존 사용자 bounded repair 허가는 유효하다(`docs/feedback/APPROVALS.md` 실행 승인).
   연구 결과를 제품 evidence로 재사용하지 않는다. R6-B-R2와 WM_CLOSE도 자동 종결하지 않는다.
5. G3는 현재 bulk 길이만 늘리는 패치를 채택하지 않는다. 향후 방향은 **버전 식별 가능한
   확장 저장/로드 계약**으로 잡되, 구체 인밴드/별도 섹션 설계·주소 이동은 G3 구조 조사 후 결정한다.
   구형 8인 save 처리 정책, 비지원 버전 거부, 9~16번 소유자·ID·동맹·시야·승패 복원,
   가변 지도 레이어 및 지원 통신과의 일관성, 왕복·원복 검증이 설계 수용 조건이다.
   G1 범위에서 serializer·메모리 배치·파일을 변경하지 않는다.

## G3 사실과 추론의 경계

`G1_S1_MIDDLE_ACCEPTANCE_LAP277.md` §4.2.6/§4.3.1의 주소를 재계산했다:
bulk 끝 = `0x892410 + 0xE397C = 0x975D8C`,
16개 PlayerStruct 끝 = `0x956770 + 16*0x3ABC = 0x991330`, 차이 = `0x1B5A4`.
이는 **현재 연속 배치/현재 bulk 그대로는 16개를 포함하지 못한다**는 증거다.
모든 가능한 확장 저장 방식이 불가능하다는 증거는 아니다. 메모리 후속 영역의 소유권도
확인하지 않았으므로 길이 증가를 안전한 수리라고 추정할 수 없다.
28개 지도 serializer 쌍의 원소 수 동일성은 여전히 미검증(같은 문서 §4.3.2).
버전 경계는 상위 설계 방향이며 실제 포맷 구현 승인은 아니다.

## middle handoff — 실행 전 하나의 계약으로 결정할 것

새 컨펌 세션이 아래 항목을 **ACCEPT 또는 REJECT + 파일/필드 근거**로 판정한다.
게임 구현을 직접 하지 않고, 게임/Wine/Xvfb 없이 검토한다.

| 필수 입력 | 수용 조건 | 미충족 시 |
|---|---|---|
| fixture 선택 | save000 또는 save006 중 정확히 하나의 경로·SHA·선택 이유와 로드 메뉴/상태 전이 근거. 존재만으로 선택 완료 금지 | 좁은 work 조사 카드 |
| 실제 하네스 연결 | 현재 새 랜덤 게임 경로와 저장 로드 경로의 차이, 수정할 함수/테스트와 승인 읽기 주소를 명시 | offline 구현 범위로 반환 |
| 측정식 | lap277 §3의 (A) overall PASS와 (B) 여섯 원시 행을 함께 요구. 전체 slot/중복/8개 owner 및 절대 selection/camera 결측은 UNKNOWN | 반려; PASS 규칙 변경 금지 |
| tick | lap277 §3.1의 동일 사건·scene 기준 delta를 유지. 관측 출처/사건 순서/결측 처리와 허용오차 제안의 근거를 제시 | 연구 blocker; 숫자를 추측하지 않음 |
| 실행 봉투 | 원본·save·하네스 SHA, 새 전체 복사본 2개·prefix/display, 실제 명령, run별/총 wall-clock 제한, 수집/flush/종료 절차를 모두 고정 | runtime 예산 요청 불가 |
| 실패 보존 | 시작 1회씩만, 실패/타임아웃/결측을 run ID와 함께 보존, 자기 소유 PID만 종료, 원본/보호 해시 전후 동일 | 즉시 승격; blind retry 금지 |

**현재 구체 blocker:** 정적 serializer는 확인됐지만 이 계약에 연결된 실제 load 명령/메뉴
절차·하네스 변경안과 tick 오차 근거가 없다. lap277 §3.1은 오차를 상위에 제출하도록
유보했고, 기존 입력 카드 L171-4는 tick 차이를 기록하며 허용한다고 적었다
(`G1_CARD2_INPUT_PARITY_HANDOFF.md:203-204`). 이를 새 수치로 임의 보완하지 않는다.
상위는 동일 사건 관측과 상태값 정확 일치를 유지하며, 수치 오차 승인은 근거 제출까지 유보한다.
이번 사용자 지시의 불명확한 구현 근거 중단 조건에 따라 여기서 실행을 멈추고 ESCALATE_SOL로 넘긴다.

## work handoff — middle이 범위를 확정한 뒤 별도 새 세션

Luna/high 또는 Sonnet5/high가 **저장 fixture 하네스 경로 한 가지**만 구현/조사한다.
승인된 로드 UI/파일 절차를 찾을 수 없으면 근거와 좁은 probe로 반환한다. 추측 seed/메모리
쓰기/포맷 파싱은 금지한다. 새 경로는 offline 모의 테스트에서 랜덤 새 게임 대체 금지,
fixture 누락/해시 불일치 거부, 두 실행의 경로 분리, 여섯 행 결측 보존을 검증한다.
기존 producer/comparator/PASS 계약의 변경 필요가 나오면 구현하지 말고 middle로 반환한다.
Fast가 통과해도 runtime 예산은 생기지 않는다. 결과는 다음 새 middle이 독립 검수한다.
실행 봉투와 tick 근거가 완성되면 상위에 원본 대조 1쌍 예산만 요청한다.
W1 accessor 인용 정정과 W2 기존 상수 재사용(lap282 ESCALATE)은 주차 유지한다.
두 정비를 S1 복원 가능성의 선행조건으로 삼거나 구현 진척의 대용으로 반복하지 않는다.
