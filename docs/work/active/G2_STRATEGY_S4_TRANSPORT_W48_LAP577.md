### 2.1 N141 재분류

W47에서 장부가 멈춘 owner는 모두 T0 시딩 직후 `used`가 cap 근처(4,950)에 있었다. 사망이 없으면 cap에 걸린 AI는 더 생산할 수 없다. 따라서 장부 동결은 "cap 근접 fixture + 교전 제외(Q10 `(다)`)"의 결과로 설명된다. 이것을 따로 풀려면 교전(사용자가 닫음)이나 AI 변경((ㄴ), 미승인)이 필요하다. 그래서 N141은 새 실행 축으로 두지 않고 제출문에 "교전 제외의 파생 한계"로 적는다. 동결 원인이 cap이라는 것은 정황 설명이며 실행으로 증명한 것은 아니다.

3. 결합 후보는 풀 4,001과 저장 포맷(F4)을 바꿨다. `g2_capacity_boundaries.md`의 "저장/네트워크 개체 슬롯" UNKNOWN이 아직 한 번도 실행으로 시험되지 않았다.

**판정 성격:** 최초 가능성 조사다(PROMPT ③). work 1회 또는 60분 중 먼저 오는 시점, 혹은 실패 가설 2회에서 `FEASIBLE`/`NOT_FEASIBLE`/`BLOCKED(env)` 중 하나로 끝낸다.

## 4. W48 work 계약 (계획 회차 없이 다음 work가 착수)

### 4.1 고정 입력
- 원본 SHA `b56986e018b43293be8d9945521d145bba8dbe4e49fe70c6b6488b8c9c08a8ac`, 결합 후보 `dfdc91adb88a732d96dff96f78648f03406003bffce1b22a7e5836317f963883`(W47과 같은 메모리 재현·역적용=`a10024de…2d68` 확인). 커뮤니티 배포본(2601·2606) 실행 금지(Q9 해석 유지).
- 인스턴스마다 새 전체 게임 복사본·fresh prefix·사용 중이 아닌 새 Xvfb display. 두 인스턴스는 서로 다른 prefix(=서로 다른 wineserver)를 쓴다. 기존 wineserver·Xvfb·다른 프로세스에 붙거나 정리하지 않는다.
- 제품 source·브리지·AI·게임 로직 변경 0. 새 의존성(네이티브 DirectX 재배포 DLL 등) 설치 금지 — 필요하면 그것 자체가 `BLOCKED(env)` 결론이다.

### 4.2 네트워크 안전
- 이 호스트는 비특권 user/net namespace가 막혀 있다(`unshare -rn`: `uid_map Operation not permitted`, lap577 확인). 그래서 격리 netns를 전제로 하지 않는다.
- 연결은 **127.0.0.1 유니캐스트 주소 입력만** 쓴다. LAN 브로드캐스트 검색에 의존하는 경로는 쓰지 않는다. 시작 전 `ss -lun`/`ss -ltn`으로 47624·2300~2400 점유를 기록하고, 점유돼 있으면 실행하지 않고 `BLOCKED(env: port_busy)`로 기록한다. 종료 후 자기 PID만 정리하고 포트 해제를 기록한다.

### 4.3 단계와 예산 (합계 wall 60분, 게임 인스턴스 쌍 최대 2회)
1. **정적(게임 0회, ≤15분):** 원본 EXE import/문자열/호출 경로에서 멀티 메뉴 진입, DirectPlay 서비스 공급자 선택(TCP/IP·IPX·직렬 등), 세션 생성·참가 호출(`Open`/`EnumSessions` 등 vtable 오프셋)을 읽기 전용으로 찾는다. 결과를 `analysis/memory_maps/`에 근거와 함께 한 파일로 남긴다.
2. **대조군 C0 = 원본 EXE 두 인스턴스(1회):** host가 TCP/IP 세션을 만들고 client가 `127.0.0.1`로 찾아 참가한다. 둘 다 게임 화면에 들어간 뒤 ≥2,000 tick 진행을 목표로 한다.
3. **후보 C1 = 결합 후보 두 인스턴스(C0 PASS일 때만, 1회):** C0와 같은 절차. 시딩·저장/로드·144k는 이 카드 범위 밖이다.
- C0가 실패하면 원인 가설을 하나만 고쳐 C0를 한 번 더 할 수 있다(가설 2회 한도). 그 뒤에도 실패면 멈춘다.

### 4.4 실행 전 고정 측정식
| ID | PASS | FAIL / 판정 |
|---|---|---|
| T1 세션 성립 | client가 host 세션을 목록에서 찾고 참가, 두 인스턴스 모두 게임 화면(PS3 또는 멀티 진행 상태 값) 진입 | 목록 비어 있음·참가 오류·크래시 |

**판정 라벨:**
- `FEASIBLE`: C0 T1·T2 PASS이고 C1 T1·T2 PASS.
- `CANDIDATE_REGRESSION`: C0 PASS, C1 FAIL → 재실행 없이 middle 독립 검수 후 strategy 승격(후보 결함 후보).
- `BLOCKED(env)`: C0가 가설 2회 안에 T1 실패(Wine DirectPlay·포트·메뉴 입력 등 환경 원인). 제품 불가능 판정이 아니다.
- `NOT_FEASIBLE`: 정적 근거로 원본 멀티 경로 자체가 이 EXE에 없거나 쓸 수 없음이 확인된 경우만.

### 4.5 종료
- work는 raw·하네스 SHA·후보 SHA·포트 기록·캡처·Fast 결과를 보존하고 자기 라벨만 적는다. 다음 middle이 summary 없이 raw로 재검수한다.
- `BLOCKED(env)`면 대안을 적는다: (i) 네이티브 DirectPlay 런타임 도입(새 의존성 → 사용자 승인 필요), (ii) 다른 호스트/VM, (iii) 멀티 검증을 이번 G2 제출에서 "환경 미검증"으로 명시. 모델이 스스로 고르지 않고 제출문에 올린다.
