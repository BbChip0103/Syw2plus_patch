# W16 — `unit+0x700` 오염 **구간 범위** 측정 (발행: lap428 middle, 수행: 다음 work 회차)

- 발행자 / 역할: lap428 Claude Code `claude-opus-5` / high / **middle(검수·중간계획)**.
  근거 `docs/history/laps/20260921_lap428_middle_g2_w15_pj_independent_review.md`.
- 수행 역할: **work (Sonnet5/high)**. 실행 probe **1회**(읽기 창 확장만) + 값열 정적 대조.
- 선행 상태: **W15는 CLOSED.** lap427 P-J 측정은 lap428이 원시 476표본으로 재계산해 **불일치 0**으로
  ACCEPT했다. 다만 해석 2건을 정정했다(N40 REJECT / N41 근거 교체) — 아래 §1이 그 확정 사항이다.
- 목표 연결: G2 P2(원본 생산·AI 경로 안정성). fault `0x00414133` 인과 사슬 최상류 확정.

## 1. lap428이 확정한 것 (재조사 금지)

- **측정은 재현된다.** 슬롯3565 `K`는 단일 변화점 `s382/t10399(0) → s383/t10400(22432)`,
  `sib(+0x6fc)`는 **정확히 같은 경계**에서 `0→16538`, `src(+0x388)`는 생존 172표본 전부 `0`.
  `m`·`f688`은 한 표본 뒤(`s384→s385`)에 변해 인과 `K→m→f688`이 재확인됐다. 대조 슬롯3562는
  생존 168표본 전부 불변. band anomaly 0. 가드-스킵 정합 불일치 0(93건 = `s383..s475`).
- **(J2) 외부 write 확정 — 알려진 `+0x700` write 4곳은 전부 배제됐다. 근거는 두 갈래다:**
  - `0x40d733`/`0x40d79f`/`0x40f040`: `+0x388`을 복사하는데 `+0x388`이 전 구간 `0`이므로 배제.
  - `0x413120`(+`0x413103`): 아래 언롤 루프가 **모든 필드에 같은 `ebp`를 쓴다**. `ebp`는
    `call 0x412f70` 사이에서 callee-saved라 두 store 사이에 바뀌지 않는다 ⇒ 한 번 지나가면
    `[+0x6fc] == [+0x700]`이어야 하는데 관측은 `16538 ≠ 22432`다 ⇒ 배제.
- **`+0x6f8`/`+0x6fc`/`+0x700`/`+0x704`는 한 배열의 연속 원소다**(원본 image base `0x400000` 기준
  바이트 확인, 후보와 **바이트 동일**):

```
0x4130e6  mov  [esi+0x6f8], ebp
0x4130ec  mov  eax, [esi+0x6fc] ; cmp eax,ebp ; je 0x413109 ; ... call 0x412f70
0x413103  mov  [esi+0x6fc], ebp
0x413109  mov  eax, [esi+0x700] ; cmp eax,ebp ; je 0x413126 ; ... call 0x412f70
0x413120  mov  [esi+0x700], ebp
0x413126  mov  eax, [esi+0x704] ; ... ; 0x41313a  mov [esi+0x704], ebp
```

- **W15 카드 §3의 판별자는 무효다(N40).** "블록 write는 이웃을 더럽히고 단일 store는 그러지
  않는다"는 거짓이다 — 위 언롤 루프가 **정당 경로인데도 이웃을 함께 바꾼다**. 따라서
  "이웃 동시 변화"만으로 블록 write를 주장하지 않는다. **(J3)은 확정이 아니라 SUPPORTED다.**
- **값 패턴은 균일 채우기가 아니라 복사를 가리킨다(N42).** `0x0000409A`, `0x000057A0` —
  인접 DWORD 둘 다 상위 WORD가 0이고 값이 서로 **다르다**. `rep stos`(균일)와 불합치,
  블록 **복사**(`memcpy`/`rep movsd`/구조체 대입)와 부합. 핀된 원본·후보에 연속 DWORD 쌍
  `9a 40 00 00 a0 57 00 00`은 **0건** ⇒ 값은 런타임 생성이며 정적 상수표 복사가 아니다.
- **1200-bound 전방 순회는 슬롯3565에 닿지 못한다.** `unit3565` base
  `= 0x0108C000 + 3565*0x758 = 0x16F0478`, `+0x6fc = 0x16F0B74`, `+0x700 = 0x16F0B78`.
  1200 한정 전방 순회의 최대 도달은 `unit1199` 끝 `0x12B2C80`으로 **0x43DF50(4,448,080B,
  2,366슬롯) 아래**다. 즉 "슬롯 0..1199만 도는 잔존 site"는 **덜 훑는 결함**이지 이 OOB write가
  아니다. 이 사실이 §2의 표적을 바꾼다.

## 2. 이 카드가 표적으로 삼는 것

`ESCALATE_SOL` §14 항목2는 두 선택지를 물었다 — (i) 잔존 1200-bound site 정적 전수 평가,
(ii) `sib=16538` 값의 발생원 특정. **lap428 middle 판정: 둘을 합쳐 하나의 측정으로 닫는다.**

이유: 오염이 블록 복사라면 **더러워진 연속 DWORD의 개수와 그 값열**이 곧 복사원의 지문이고,
그 지문 하나가 (ii)를 직접 풀며 (i)의 후보 집합도 사거리 계산으로 잘라낸다. 반대로 더러워진
DWORD가 딱 2개면 블록 복사가 아니라 표적 쌍 write이므로 (i)의 정적 전수가 비로소 정당해진다.
**지금 (i)를 먼저 하면 §1 마지막 항목 때문에 사거리가 안 맞는 site를 훑는 데 한 회차를 쓴다.**

## 3. 수행 순서와 측정식

### P-K. 오염 구간 범위 측정 (이 회차의 유일한 실행 증거)

lap427 `movement_state_probe_pj.py`를 복사해 **읽기 창만 넓힌다.** 새 가설을 추가하지 않는다.
`DENSE_LO=10380`, `DENSE_HI=10420`, `STOP_TICK=10500` **그대로**. fixture도 **그대로**
(op7 resource-only, 8 owner, N=4001, seed42, 새 prefix/빈 display).

슬롯3565와 ref 슬롯 양쪽에 매 표본 추가 기록:

1. `win[i] = DWORD [unit + 0x6e0 + 4*i]`, `i = 0..15` ⇒ `+0x6e0`~`+0x71c` **연속 16 DWORD**.
   기존 `src`/`sib`/`K`/`m`/`f688` 기록은 **그대로 유지**한다(`sib`/`K`는 창과 중복되지만
   교차검증용으로 남긴다 — 두 경로가 어긋나면 그 자체가 결함 신호다).
2. 가드: 이 창은 **읽기 전용**이고 unit 슬롯 내부(`0x758` stride 안)이므로 범위 가드가 필요 없다.
   `+0x700`의 `P` 보정표 읽기에는 기존 가드 `0 ≤ K < 3759`를 **그대로 유지**한다.

### 판정식 (실행 전 고정)

전이 sample(직전 대비 창이 처음 바뀌는 표본)에서 **바뀐 DWORD의 개수 `n`과 그 인덱스 구간**으로 가른다.

- **(K1) 표적 쌍.** `n == 2`이고 바뀐 것이 정확히 `+0x6fc`·`+0x700` ⇒ 블록 복사 아님.
  다음 표적은 W15가 못 본 형태 — 변위가 다른 인덱스형 write `[reg + reg*scale + disp]` —
  의 정적 전수다. `+0x6fc`/`+0x700` **쌍을 함께** 쓰는 site로 좁힌다.
- **(K2) 블록 복사.** `n >= 3`이고 바뀐 인덱스가 **연속 구간** ⇒ 블록 복사 확정(이제 근거가
  이웃 1개가 아니라 구간 길이다). 구간의 **시작·끝 오프셋과 값열**을 기록한다. 이 값열이
  다음 회차의 복사원 탐색 키다.
- **(K3) 산발.** `n >= 3`인데 인덱스가 **불연속** ⇒ 복사도 쌍 write도 아니다. 구조체 필드
  단위 대입이 여러 번 일어난 것이므로 `+0x6f8`~`+0x704` 언롤 루프의 **변형/다른 인스턴스**를
  `ebp` 불일치와 함께 재검토한다(§1의 배제는 "한 번 지나감" 전제였다 — 서로 다른 `ebp`로 **두 번**
  지나갔을 가능성은 이 갈래에서만 되살아난다).
- **(K4) 전이 비재현.** 창이 이번 run에서 안 바뀐다 ⇒ 동일 파라미터로 **1회만** 재시도하고,
  두 번째도 실패하면 `BLOCKED`로 보고한다(창을 넓히거나 가설을 즉석 추가하지 않는다).
- 어느 갈래든 **추측 수리 금지.** 이 회차는 계측과 값열 대조만 한다.

### P-L. 값열 정적 대조 (P-K가 (K2)일 때만, 같은 회차 안에서)

P-K가 뱉은 값열(연속 DWORD 배열)을 핀된 `original.bin`/`candidate.bin`
(`temp/Syw2plus_patch/g2_capacity/20260921_lap424_middle_review/`, **image base `0x400000`**)에서
바이트 탐색한다. lap428이 쌍 `(16538, 22432)`로 이미 시도해 **0건**이므로, 정적 0건이면
"복사원은 런타임 상태(bulk 라이브 blob 등)"로 결론내고 **거기서 멈춘다** — 런타임 메모리 스캔은
이 카드 범위 밖이며 다음 카드의 대상이다.

### 실패 예산

실패 가설 2회 또는 60분 안에 `FEASIBLE`/`NOT_FEASIBLE`/`BLOCKED`로 판정한다.
