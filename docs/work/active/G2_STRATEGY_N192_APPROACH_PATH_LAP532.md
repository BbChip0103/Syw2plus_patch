## 1. 판정 (1) — N192 경로: **(a) 접근 진단 probe 채택**, (b)는 결과 분기로 미룸, (c) 기각

  (b) 정적 추적은 네 갈래 중 어느 것인지 모른 채 `0x4AEE10→…→0x40C640`와 이동·공격 루틴 전체를 읽어야 한다. 비용이 크고 실행 증거도 늘지 않는다.
  그래서 probe 결과가 가리키는 한 구간만 읽도록 뒤로 미룬다(§3 분기표).
- **J2 (c) 인접 배치 기각.** 이유는 둘이다.
  - 인접 배치는 "움직이는 상태의 안정"(lap522 §1)을 "제자리 근접전"으로 바꾼다. 사용자 번복 위험이 있다.
  - **W37 짝 (2,3)이 이미 반증이다.** 인접분 7기가 죽자 남은 목표가 다시 거리 4가 되어 교전이 멈췄다. 인접 배치는 지속성을 만들지 못하고 늦출 뿐이다.
- **J3 양성 대조를 같은 실행에 넣는다.** 시딩 파동 뒤 시작 유닛 type110끼리 op8을 한 번 건다(§2 H7).
  이 대조가 움직이면 "재배치 후보에서도 op8 이동은 된다"가 입증된다. 그러면 시딩 군대의 정지는 밀집 기하 탓으로 좁혀진다.
  대조까지 안 움직이면 후보·경로 결함 의심으로 넘어간다.

**판정식 (실행 전 고정 — 사후 재채점 금지, middle은 강화만 가능)**
- 대상 집합 S = 파동 1~3에서 수락된 op8 중 **선택 시점 거리 ≥2**인 소스.
- 소스 단위: `promoted` = 추적 읽기 중 `+0x290`==4가 한 번이라도 있음. `moved` = op8 직전 위치에서 Chebyshev 변위 ≥1. `hit` = 그 목표 HP가 추적 창 안에서 감소.
- 대조: `CONTROL_MOVED` = 대조 소스 중 하나라도 600 tick 안에 변위 ≥2. `CONTROL_STILL` = 수락됐지만 둘 다 변위 ≤1. `CONTROL_NA` = 위 H7 조건.

| 라벨 | 조건 (우선순위 위에서 아래) |
|---|---|
| `BLOCKED` | gate·timebox·하네스 결함·main thread 미도달·게임 fault |
| `PROBE_VOID` | 무장 실패(W36 §5 `ARM_FAIL` 조건) 또는 |S| = 0 |
| `ENGAGED` | S 중 `hit` 소스가 있는 짝이 4짝 중 ≥2 |
| `MOVED_NO_HIT` | S의 ≥50%가 `moved` |
| `PROMOTED_NO_MOVE` | S의 ≥50%가 `promoted` |
| `NOT_PROMOTED` | 그 밖 |

- 라벨과 대조 결과(`CONTROL_*`)를 함께 적는다. 보고 의무: 소스별 `promoted/moved/hit`, `+0x290` 값 순서, 최소 도달 거리, 막힘 여부 계산 입력(H8).
- 이 probe는 A1~A8'를 판정하지 않는다. 라벨은 합격 라벨이 아니다.

**3.1 전열 배치 (사전 허가, 필요할 때만)** — 짝 (o, o^1)의 type2 60기를 본 블록과 떼어 **전열 anchor**에 시딩한다.
- 두 전열 사이에 **빈 칸 6~10칸 폭의 개방 띠**를 둔다. 본 블록(type5/7/46)은 기존 anchor에 그대로 둔다. X 보충(op5 type2)도 전열 anchor를 쓴다.
- T0 위치표(H8)로 띠 안에 유닛이 0임을 확인한다. 확인이 안 되면 `ARM_FAIL`이다.
- 소스는 여전히 **최소 6칸을 걸어야** 목표에 닿는다. 그래서 "움직이는 상태"의 뜻은 바뀌지 않는다. 인접 배치(c)와 다르다.
- 수량·타입·op·가드·허용목록·A1·A8'는 그대로다. 정확한 좌표는 middle이 지도 폭 100·높이 100과 H8을 보고 정한다.

## 4. 판정 (2)(3) — A6·A3 정의 정리 (W39부터 적용, lap522 §3 원문은 보존)

**(2) A6 — 약화하지 않는다. 둘로 나누고 전제를 명시한다.**
- 거절 이유: lap522 A6 원문은 "**교전 중** op2 저장"이다. W37은 교전이 로드 약 8,400틱 전에 끝나서 전제 자체가 성립하지 않았다.
  "로드 전 창에 사망이 있을 때만 요구"로 바꾸면 교전 없는 저장/로드도 A6를 통과한다. 그것은 약화다.
- **A6a(무결성):** op2·op3 `ok`, op2 직후 == op3 직후(8 owner `(used,reserved,count)` + `live`). FAIL이면 `CYCLE_UNSTABLE`.
- **A6b(교전 지속):** 전제 = op2 직전 3파동 안에 op8 기인 사망 ≥1. 그리고 op3 뒤 사망 합 증가. 전제 미충족도 FAIL이다. FAIL이면 `CYCLE_PARTIAL`(하위 사유 표기).
- 이것으로 N194 라벨 틈도 닫는다. 필드 일치·로드 성공·교전 없음은 `CYCLE_PARTIAL`이다. 두 라벨 모두 합격이 아니고 144k는 열리지 않는다.

**(3) A3 — 재정의한다(strategy 권한, 사용자 번복 가능).**
- 이유: "owner o의 죽은 슬롯에 새 type7"은 할당기의 빈 슬롯 선택 정책을 잰다. 풀 4,001칸에 빈칸이 많으면 사망이 적을 때 구조적으로 0이 된다(N193).
  G2가 요구하는 것은 "재생산이 된다"와 "죽은 슬롯이 다시 쓰여도 무결성이 유지된다"이다. 특정 owner의 특정 슬롯이 아니다.
- **A3'(재생산, owner마다):** 양성 대조 PASS ∧ owner o의 창 E 첫 사망 뒤 **op1 귀속 type7 출생 ≥1**(새 uid).
  - 양성 대조: op1 receipt의 `after.reserved − before.reserved`==10이거나, 50 tick 안 표본에서 `reserved` +10. 그리고 1,000 tick 안 `producer_change`.
  - op1 귀속 규칙(AI 자체 생산과 구분)은 middle이 W39에 원시 필드로 고정한다. 구분이 안 되면 AI 출생을 따로 세고 A3'는 FAIL이다.
- **A3r(슬롯 재사용, 풀 단위):** 창 E에서 사망으로 비워진 슬롯 중 ≥1개가 다른 uid로 다시 채워짐(owner 무관). 채워진 뒤 A5 위반 0.
- **op1 발주 조건:** `reserved`==0 → `used + reserved + 10 ≤ 5000`로 바꾼다. AI 자체 예약이 있어도 여유가 있으면 발주한다. 측정만 바뀐다.
- `DRIVEN_CYCLE_STABLE` = A1·A2·A3'·A3r·A5·A6a·A6b·A8' 전부 PASS. A2(owner마다 D_o ≥ 20, 3등분 ≥2구간)는 그대로다.
- 144k 사전 허가(lap522 J4)는 그대로 `DRIVEN_CYCLE_STABLE`에만 적용된다.
