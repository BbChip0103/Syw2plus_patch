# lap325 Astra — R1 연구 범위 조건부 허용 및 실행 보류

2026-09-12 / Codex gpt-6-astra / high / major direction/master-plan.
M1/G1 내부의 상위 범위 결정이다. 게임 코드 수정·실행 0, 마일스톤 종료/이동 0.
현재 다음 작업은 STATUS만 따른다. 이 문서는 사람 승인 원문을 변경하지 않는다.

## 결정과 권한

lap324 R1을 **연구 방향으로 조건부 허용**한다. 기존 exact-site 봉투는 반려 유지한다.
APPROVALS 2026-09-12 01:03의 G1 bounded repair/fresh validation과 이번 Astra 지정 역할,
STATUS의 상위 범위 결정 요청에 근거해 아래 세 가지 로컬 연구 제한의 변경 범위를 확정한다.
이는 별도의 사용자 마일스톤 승인이나 즉시 실행 허가가 아니다.

| 항목 | 허용 상한 | 발효 조건 |
|---|---|---|
| runtime 0 | 원본의 새 격리 전체 사본 1 fresh run, 준비부터 종료까지 총 ≤90초 | middle 봉투 수용 + work 구현 + 필수 검사 통과 + 새 middle의 실행 전 독립 검수 |
| 하네스 수정 금지 | 연구 전용 읽기 경로·별도 evidence 파일·PS 대기 선언과 해당 실패 검사 | middle이 파일/함수/스키마를 지정한 뒤 work만 구현; 기존 제품 PASS 경로 확장 금지 |
| 입력 0 | PS9 확인 후 클라이언트 기준 (296,505) 클릭 1회 | 좌표계와 변환 근거, 창/PID 소유 확인, 도달 판정식 사전 명시; 재클릭 0 |

지금 실행 가능 예산은 여전히 **0**, work 카드는 **0**이다. 위 조건들이 충족되면 상한 내
실행을 위해 같은 범위의 Astra 허가를 다시 요청할 필요는 없다. 조건이 충돌하거나 입증되지
않으면 실행하지 않고 middle이 구체 blocker를 보존한다. 별도 세션 자동 호출은 하지 않는다.
Stage B·원본/후보 쌍·PNG 비교·W3 재pin·baseline/golden 변경·INT3/원본 실행 이미지 변경 금지는
이번 연구에서 유지한다. 종료용 소유 PID 제어는 필요하지만 추가 UI 클릭을 허용하지 않는다.

## 선행 검수와 한계

lap324 probe를 수정 없이 1회 재실행했다. failures=[]이고 stdout SHA는
`c00eed094885334ecc2fb072defb543ac43e4cd2e32105919518859fbb1e21cf`로 보존 보고서와 동일하다.
이는 원본 PE/하네스 정적 증거의 재현성 확인이며 새 독립 알고리즘 검수나 실제 게임 증거가 아니다.
직접 writer 1/1은 절대 operand 스캔의 범위이고 간접/계산 writer는 UNKNOWN이다.
"입력 없이 도달 근거 없음"은 모든 실행 경로의 불가능성 증명이 아니다.
1클릭은 성공이 입증된 경로가 아니라 이번 실험에 허용할 입력 상한이다.

## middle에 인계할 판정 항목

lap324 §5의 '구성 확인 시점'은 실행 가능한 판정식이 아직 없다. 다음 두 항목이
불명확하므로 이번 세션은 구현으로 밀어붙이지 않고 ESCALATE_SOL로 인계한다.

1. **도달 관측:** PS35 등 어떤 상태/필드를 어떤 원본 주소·바이트 근거로 읽어 다이얼로그
   진입을 판정할지 명시한다. A/B origin 값 자체로 도달 성공을 정의하는 순환 판정은 금지한다.
   클릭 좌표의 기존 출처와 실제 창 좌표계 변환을 연결한다. 근거가 없으면 UNKNOWN/BLOCKED.
2. **표본 일관성:** x/y가 서로 다른 두 store라는 점을 반영한다. 인접 4바이트 읽기의
   길이·오류·순서와 pre/post 시계열, 반복 관측 규칙을 선언한다. 하나의 read도 게임 쓰기와
   원자적이라는 보장은 없으며 안정 반복값도 exact-site나 간접 writer 배제를 증명하지 않는다.
   안정성 횟수/간격은 실행 전 가정으로 정하고 원시 샘플을 보존한다. 불일치/중간값은 UNKNOWN.

middle은 위 항목과 함께 다음을 포함한 봉투를 한 문서로 수용 또는 반려한다:
- 새 run/prefix/빈 display·원본 SHA/사본 SHA·소유 PID·시작 명령과 종료 방식.
- 실제 수정할 파일/함수, 연구 evidence 파일과 제품 소비 경로의 분리, PS 집합 대기 가드(N6).
- 준비40/클릭20/관측15/종료15초는 실측 아닌 상한 배분 가정. 종료 예산을 침범하지 않는
  단일 deadline과 실패 시 보존 경로. 사전 격리 복사 준비 시간의 포함 범위를 숨기지 않는다.
- 미도달·미변화·timeout·수집 실패 네 모드 및 짧은 read/불일치 표본의 합성 검사.
  원시 PS/tick·단조시간·run ID·SHA·PID·입력 수·오류·flush 경로·종료 결과가 필요하다.
- N4 선평가 패턴을 재사용하면 먼저 수리하도록 work 범위를 지정. W3 자가 재pin은 불허.

## 연구 판정 계약

실행 안전/수집 유효성, 값 분류, 제품 판정을 분리한다. 실패/미도달/불안정/수집 오류 또는
pre==post이면 **UNKNOWN 우선**이며 숫자가 우연히 A/B여도 성공으로 바꾸지 않는다.
독립 도달 근거와 일관된 유효 post가 있을 때만 (240,145)는 A와 일치, (160,85)는 B와 일치로
기록한다. 그 외 안정된 유효값이면 A/B 후보를 모두 반려한다. 미완성 표본은 후보 반증이 아니다.
결론은 '이 run의 이 진입 경로에서 관측한 origin'뿐이다. 중심식 계산 순간, 화면 전역값,
모든 로드 경로의 결정성, hitbox/슬롯/로드 성공은 증명하지 않는다. G1 제품 증거 0 유지.

## 실행 분리와 중단

상위 범위 결정 → 새 middle 봉투 검토 → work(Luna/Sonnet5 high) 최소 연구 구현/검사 →
새 middle 실행 전 독립 검수 → work 1회 측정 → 새 middle 결과 검수로 역할을 분리한다.
이번 사용자 지시는 Sol 승격을 명시하므로 ESCALATE_SOL을 쓴다. MODEL_ROUTING의 현재 Opus5 선택과
루프 라우팅이 다르면 실행기가 명시적으로 해소할 일이며 모델 자동 대체/호출은 하지 않는다.
필수 검사 예상 밖 실패, 구현 근거 충돌, 마일스톤 경계에서는 보존 후 승격하고 종료한다.
측정 실패 시 자동 연장/재시도는 없다. 동일 정적 CFG 재유도나 문서량을 구현 진전으로 세지 않는다.
R1의 위 불명확성 해소만 요청하며 G2~G4·fixture 반증 같은 두 번째 카드는 열지 않는다.
