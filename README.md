`../Syw2plus_re_loop`와 같은 **한 바퀴=새 세션, 기억은 파일** 구조를 사용한다.
전체 엔진 재구현이 아니라 원본 기반 버전/패치가 산출물이다.

### Windows 실행 거부 후속 — 헤더 구조 수정

사용자가 r10 자리고정판의 Windows 실행 거부를 확인했다. 추가섹션 때문에 헤더0x1200이 첫 코드RVA0x1000과 겹치는 결함이 있었다. r11은 기존 owned `.g8code+0x20`의 검증된 빈 공간에15byte G9 stub을 옮겨 일반판과 같은94sections/header0x1000을 유지한다. 일반판도 헤더/table·섹션 겹침/정렬·파일/image범위·실행EP를 확인했고 검사 오류가 없었다. 이는 제한된 구조 검사이지 모든 결함이 없다는 보장은 아니다.

r11의 G9/조합 회귀4개와 새·역사r10 byte-exact 원복, 독립 PE/27byte 변경범위 확인 및 private Wine 실제 시작/120초 PS3 진행·owned cleanup을 수용했다. 보조 결과의 `LIVE_FAILED`(목표1200 초과 개체 미달)·상속 generic metadata는 그대로 보존하며 전체 도구 PASS로 바꾸지 않는다. **native Windows 실행과 r11 자리좌표 행동은 재확인 전 미검증**이다. 후처리 도구의 TypeError·손상 controller JSON, 고정 지도 추적 뒤 GDB 종료 오류는 그대로 보존한다. **전체 도구 PASS가 아니라 실제 기능별 증거의 수용**이며, 과거 실패를 성공으로 바꾸지 않는다. 합성 대기실/개체·장수·자원 fixture는 자연 플레이와 구분한다. G6 원시 자료는 공유 temp `20261010_g6_sp_driver_v1/artifacts/`에 있다.

G9는 **자리 순서 → 해당 지도의 시작좌표 목록 순서**다. seed가 달라도 같은 XY를 강제하지 않는다. 실Windows·장기 안정성·실제 100기 선택 스트레스·빈 자리 G9는 미검증이며, 멀티는 이번 요청 범위 밖이다. 원본·기존 전달물은 덮어쓰지 않았다.

기계 검사 원시 로그: `logs/gates/20261010_esl2613_followup/20261010_142052_fast/`의 `2181 passed, 9 skipped`와 별도 G2/G9 조합·저장 회귀 `95 passed`. 같은 후보·같은 범위의 증거는 재사용하며 문서 변경만으로 전체 검사를 반복하지 않는다. 검사 도구 통과는 실제 게임 합격이 아니다.

실행은 원본 전체 게임 사본 + 공식 2612 데이터 묶음 + 후보 2613 EXE를 별도 prefix/display에서 사용한다. 공식 EXE도 요구하는 누락 자원 `fnt/poisonfx.spr`, `fnt/poisonfield.spr` 두 파일을 공통 fixture로 보충한다. 기존 타이틀 실패를 막던 비소켓 errno 반환 수정은 네트워크 허용 확대 없이 독립 확인했고, 양 ABI의 정확한 `$LIB/guard.so` 경로로 재사용한다.

## 모델 역할

현재 선택은 Codex다(2026-10-09 사용자 전환). 역할별 provider를 바꿀 수 있으며 최신 선택은 [역할 계약](docs/MODEL_ROUTING.md)을 따른다.

- **큰 방향/상위 계획:** `astra/high` (큰 분기·교착에서만)
- **중간 계획/독립 컨펌:** `sol/high`
- **실무:** `luna/high`

`luna`/`sol`/`astra`는 모델 캐시의 계열별 최신으로 해석한다. 실무가 자기 결과를 최종 승인하지 않으며,
설정 실패 시 다른 모델로 자동 폴백하지 않는다.

## 루프의 기억과 판정

| 파일/폴더 | 역할 |
|---|---|
| `docs/DESIGN.md` | 사용자 확정 제품 계약 |
| `docs/STATUS.md` | 현재 상태/다음 한 가지/블로커/검증/최근 바퀴 |
| `docs/feedback/INBOX.md` | 최신 사용자 지시, 최우선 |
| `docs/feedback/APPROVALS.md` | 독립 검수/반려/마일스톤 사용자 판단 |
| `docs/baseline/{compare,traces,golden}/` | 기준/비교/승인 자료 색인과 해시 |
| `docs/reference/` | 고정 원본 프로필 |
| `docs/history/` | 이전 Git/미커밋 스냅샷/실험/요구 변경/lap 이력 |
| `loop/PROMPT.md` | 매 바퀴①~⑥ 지시서 |
| `loop/{env.sh,loop.sh,loopctl.sh}` | 설정/신규 세션/실행 제어 |
| `checks/` | 원본/고정근거/컨텍스트 안전 검사 |
| `patches/`, `tools/`, `tests/` | 패치/격리 진단/회귀 시험 |

1단 기계 검사 →2단 다음 새 세션 독립 검수 →3단 사용자 마일스톤 판단.
승인된 기준은 이후 기계 검사가 감시한다. 과거성공/skip/모델exit0은 승인 대신이 아니다.

## 개발과 제어

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
git config core.hooksPath .githooks
make doctor
make check
loop/loopctl.sh status
loop/loopctl.sh models      # 모델 설정 조회만; 실행하지 않음
```

현재 머신에는 기존 패키지를 재사용하는venv를 세팅했다. 실제 모델 세션/서비스는 켜지 않았다.
초기 안전 pin은 세팅에서 수행한다. 새 복제 환경에서는 원본/profile을 검토한 뒤
`checks/safety.sh pin`으로 한 번 고정한다. 자동 재pin은 금지다.
실제 실행 설정은 [loop/README.md](loop/README.md). 기본 비활성/최대1바퀴/자동커밋 없음이다.
서비스 이름은 **syw2plus-patch-loop.service**로 기존 루프와 충돌하지 않는다.

`loop/FULL_TEST` 요청은 세션 밖에서`tests/test_build.sh`→`make check`를 실행한다.
이 결과는Fast이지 원본 앱/8인/16인/24k/144k를 실제로 돌린 결과가 아니다.

## 기존 패치와 로컬 입력

- [전비 패치/원복](patches/population/README.md), [과거QHD 참고](patches/resolution/README.md).
- 진단 inmm/X11 도구만 가져왔고 Plan C 엔진 실행 의존은 제거했다.
- 로컬`Syw2plus/`는 검증용 원본EXE만 있으며 전체 게임 설치가 아니다. 게임 데이터는 배포하지 않는다.
- 실제 실행 환경은 `local/runtime/`에 격리하며 prepare/check/smoke·doctor와 증거 검사 CLI를 제공한다. [안내](docs/setup/README.md).
- 게임 없는CI에서는 원본 필요한 테스트가skip. 원격CI를 실행한 것으로 주장하지 않는다.
- EXE/DLL/save/local/logs/세션 상태는Git 제외. 원격은 `github.com/BbChip0103/Syw2plus_patch`; 루프 자체는 자동 커밋/푸시하지 않는다.
- 출처에 없는 라이선스를 임의 부여하지 않았다.
